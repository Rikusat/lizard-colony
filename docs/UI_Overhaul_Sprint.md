# UI_Overhaul_Sprint — Neo-Terrarium

- 版: 1.0（2026-07-11）
- 役割: ゲームディレクター兼UX/UIディレクターによる、Claude Code 向けUI刷新スプリント指示書
- **本書は仕様であり、コードは含まない。** 実装はPhase順に「分割 → 基盤 → 部品 → 画面 → ピーク → 仕上げ」で進める。
- **必読**: 本スプリントの全UI実装は `UISkills.md`（デザインシステム）に従う。**UIに触れる各コミットの冒頭で該当トークン/コンポーネント仕様を参照すること。** UISkillsに無いスタイルを場当たりで足さない。足す前にUISkillsへ追記する。

## このスプリントの狙い

現状の2Dゲーム画面は、シンプルで懐かしい（テラリウムを覗く魂）。これを損なわず、**近年のUI技術で"額縁"を磨き、若年層に刺さる大胆さとレトロ世代の心地よさを両立**させる。設計言語は **Neo-Terrarium**（`UISkills.md` §0）。

> **魂はレトロ、額縁はモダン。平常は静か、ピークは大胆。**

- **ゲームシステム・ゲームループ・バランスは一切変更しない。** 本スプリントは**見た目・操作感・演出のみ**。
- **既存機能を1つも壊さない。** 各Phaseで機能回帰テストを行う（V4.1で openHQ/openAllies を一括置換で消した実例あり。§安全制約を厳守）。
- ドットの生き物・大地のフィールドは魂として維持。近代化は周囲の枠に限定。
- **対象はPCブラウザのみ。** スマホ/タッチ最適化は本スプリントの対象外（マウスのホバー操作を積極活用してよい）。
- **絵文字は全面禁止。** UI・ラベル・演出・アイコンを含め絵文字を一切使わず、すべて自作SVG/スプライトのアイコンで表現する（`UISkills.md` §9）。

## 安全制約（今回の事故を再発させない・全Phase共通）

1. **一括置換の前に必ずgrepで件数確認する。** 複数箇所の一括置換（sed／広範囲str_replace）を行う前に、置換対象が**意図した範囲だけにマッチするか**を grep で件数確認し、想定より多ければ分割する。関数定義（`function xxx`／`openXxx` 等のエントリポイント）を巻き込む置換は禁止。
2. **各コミット後にビルド/構文チェック＋主要画面のスクリーンショット**（メイン/巣/HQ/惑星マップ/新規起動）で回帰を確認してから次へ。
3. **コミットは200〜400行目安**・単体でレビュー可能な粒度で閉じる。
4. 破壊的変更の前にバックアップ。UI崩れは即ロールバックできるようにする。
5. 数値・色・時間はハードコードせず、`UISkills.md`のトークン（CSS変数等）へ集約する。

## ロードマップ（Phase 0〜9）

### Phase 0 — ui.js 分割（純リファクタ・見た目は変えない）

- **目的**: 巨大UIファイルを責務単位へ分割し、以後の刷新を安全にする。一括置換事故の物理的予防。
- **変更内容**: `UISkills.md` §8の構成へ分割（components / screens / hero / motion）。**挙動は一切変えない。**
- **対象**: `ui.js` ほかUI関連。
- **UI**: 変化なし（見た目・機能は完全に現状維持）。
- **テスト**: 全画面が分割前と同一に動作（メイン/巣/HQ/惑星マップ/設備/繁殖/図鑑/新規起動の回帰）。openHQ/openAllies等のエントリポイントが全て生存。
- **完了条件**: 責務分割が完了し、見た目・機能が分割前と完全一致。

### Phase 1 — デザイントークン基盤

- **目的**: `UISkills.md`のトークン（色・字・余白・角丸・段差・モーション）を実体化し、全UIの土台にする。
- **変更内容**: トークン定義（CSS変数等）／フォント導入（Zen Kaku Gothic New / M PLUS Rounded 1c / DotGothic16・§2）／等幅数字／`clamp()`流体化／`prefers-reduced-motion`の土台。
- **UI**: 全体の色味・字面が新トークンへ寄る（レイアウトは現状維持）。
- **テスト**: 全画面がトークン参照で描画される／ハードコード色が残っていない／reduced-motionで演出が簡素化される。
- **完了条件**: 全UIがトークン経由になり、以後は値の一元変更が効く。

### Phase 2 — コアコンポーネント刷新

- **目的**: 繰り返し使う部品（`UISkills.md`§5）をジュース付きで統一。
- **変更内容**: 資源ピル（カウントアップ）／アクションボタン（長押しリング・無効状態・CTA色）／カード／モーダル（中央スケールイン）／トースト／タブバー／通知バッジ。
- **UI**: ボタン・パネルの質感と反応が現代化。押すと弾む・数字が回る。
- **テスト**: 各コンポーネントの全状態（通常/ホバー/押下/無効/長押し）が仕様通り／既存の全ボタンが新部品へ差し替わり機能維持。
- **完了条件**: 主要UI部品が統一され、クリックの手触りが向上。

### Phase 3 — メイン画面（ヘッダー＋3カラム）

- **目的**: 常時見る画面を"飼育ケースを覗く"没入へ。
- **変更内容**: ヘッダーの資源ピル整列／フィールドを**テラリウムのガラス面**として縁取り（内側の光・わずかな映り込み・ヴィネット。生き物とフィールド自体は不変）／左アクション・右ステータスの階層整理／流体レイアウト。
- **UI**: 中央フィールドが"覗いている感"を獲得。周囲パネルが層状に。
- **テスト**: 各画面幅で崩れない／生き物・フィールドの描画が変わっていない／情報階層が明快。
- **完了条件**: メイン画面がNeo-Terrariumの平常面として完成（静かで心地よい）。

### Phase 4 — 主要サブ画面（巣・HQ・惑星マップ・設備・繁殖・図鑑）

- **目的**: 各画面を新コンポーネントとトークンで再構成し、体験を揃える。
- **変更内容**: 巣（蜘蛛の巣ネットワークの視認性・糸/ノードの発光整理）／HQ（研究・宇宙港・資源の情報設計）／惑星マップ（ノード＋侵食リング＋フロンティアの明快化）／設備2タブ／繁殖二段階＋クイック繁殖／図鑑（惑星別＋Lore）。
- **UI**: 全画面のトーンが統一され、回遊が快適に。
- **テスト**: 各画面の既存機能が完全維持／新コンポーネントで再構成されている。
- **完了条件**: 全サブ画面が統一言語で再構成され、機能回帰なし。

### Phase 5 — 大胆な瞬間（ヒーロー演出）

- **目的**: 若年層向けの"沸き"を`UISkills.md`§6の各ピークへ集中投下。
- **変更内容**: ボス襲来/撃破・巣ノード解放（含先行解放）・隕石を割る・惑星ワープ・ロケット発射・成長/伝説誕生・レベルアップの映画的演出。全てスキップ可＋reduced-motion対応。
- **UI**: ピーク体験が劇的化。SNS映えする瞬間を作る。
- **テスト**: 各ヒーローが発火/スキップ/reduced-motionで正しく動く／演出がゲーム進行を止めない／平常面に演出が漏れていない。
- **完了条件**: ピークが大胆になり、平常との落差が効いている。

### Phase 6 — モーション＆マイクロインタラクション横断

- **目的**: 全体の手触りを`UISkills.md`§4で統一。
- **変更内容**: ばねイージング統一／数値カウントアップ全適用／リスト/カードのstagger入場／報酬バースト／クリック弾み。共通ヘルパ（`ui/motion`）へ集約。
- **UI**: 触れる場所すべてに一貫した反応。
- **テスト**: 全遷移が統一イージング／reduced-motionで無効化／パフォーマンス低下がない。
- **完了条件**: モーションが一貫し、"生きている"手触りが全画面に。

### Phase 7 — デスクトップ操作性＆アクセシビリティ

- **目的**: マウス/キーボード操作の質と可読性・多様性対応の完成（PCブラウザ前提）。
- **変更内容**: ホバー状態の積極活用（プレビュー/ツールチップ）／キーボードフォーカスリング／クリック標的の拡張／コントラストAA／色のみ依存の排除／広い画面幅でのレイアウト最適化。
- **UI**: PCで快適・誰にでも読める。
- **テスト**: 主要動線がマウスで快適／ホバー/フォーカスが明確／コントラスト・可読性を満たす。
- **完了条件**: デスクトップ操作性とアクセシビリティ規則（`UISkills.md` §7）を全て満たす。

### Phase 8 — 惑星アクセント・テーマ

- **目的**: 惑星ごとの個性を差し色で軽く演出（`UISkills.md`§1.5）。
- **変更内容**: 惑星アクセント色をヘッダー縁・マップリング・専用UIへ適用。**ベース土壌は共通のまま**。惑星移動時に差し色がスッと切り替わる。
- **UI**: 惑星を跨ぐと世界の色が変わる小さな高揚。
- **テスト**: 8惑星でアクセントが正しく切り替わる／可読性・コントラストが各色で保たれる。
- **完了条件**: 惑星の個性が色で伝わり、統一感を壊さない。

### Phase 9 — 仕上げ・QA

- **目的**: 全体の破綻検証と磨き込み。
- **テスト**: 全画面×主要ウィンドウ幅×新規/既存セーブで崩れなし／V2〜V4.1の全機能（長押し・クイック繁殖・ボスティア・味方・巣収納・巣ネットワーク・侵食率・惑星マップ・鉱石/ロケット）が無傷／演出がreduced-motion/スキップで安全／スクリーンショット差分レビュー。
- **完了条件**: 見た目が刷新され、魂（レトロ）が残り、機能が1つも壊れていない。

## 禁止事項（Claude Codeへ）

- **ゲームシステム・ループ・バランスを変えない。** UI/演出のみ。
- **生き物・フィールドの魂を汚さない。** ドット生物・大地の描画は原則不変。
- **平常画面を賑やかにしすぎない。** 大胆さはヒーロー（§Phase 5）へ寄せる。
- **絵文字を一切使わない。** アイコンは自作SVG/スプライトで用意する（`UISkills.md` §9）。
- **UISkillsに無いスタイルを場当たりで足さない。** 足すならUISkillsへ先に追記。
- **一括置換の安全制約（§安全制約1）を毎回守る。** 関数エントリポイントを巻き込まない。
- **Phase 0完了前に見た目を変えない。** 分割が土台。
- 各Phaseの節目でスクリーンショットと回帰チェックをHANDOFFに残す。

## 未決定事項（Ric確認待ち）

1. **レトロ差し色フォントの範囲**: ドットフォント（DotGothic16）をSTAGE名・称号・"BOSS"等の判子ラベルに限定する方針。もっと広く使いたい/使いたくない場合は指示を。
