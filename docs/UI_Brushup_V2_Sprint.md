## Phase 1 — 給餌ダイヤル（飼育槽ハンドル）

**最重要のUX刷新。** 最も多く触る給餌を、ボタン列から独立させ、飼育槽そのものに備え付けの機構へ移す。

> **設計思想**: 一括餌やりを「他ボタンに挟まれた1行」から解放し、**飼育槽の右下に据え付けた給餌クランク**にする。誤タップの原因（隣接ボタンとの近接）を構造ごと消す。餌が育成へ効くロジックは不変で、既存の一括餌やり処理を裏で再利用する（新ルールは足さない）。

### 1.1 配置

- **飼育槽の右下**に据え付ける（左のボタン列からは物理的に離す）。フィールドのクリック対象（トカゲ・巣・氷穴・水場）と重ならない隅に置き、pointer-eventsを持たせる。
- 飼育槽の"備え付け機器"として、テラリウムの世界観に馴染む造形（真鍮/琥珀のクランク＋コオロギの意匠）。UISkillsのトークンで着色。**絵文字は使わず自作SVG**（§UISkills 9）。

### 1.2 操作モデル

| モード | 挙動 |
|---|---|
| **手動（既定）** | クランクをクリック（または軽くドラッグして回す）と、餌が一掴み分まかれる＝**現行の一括餌やりに相当**。回した量（トルク＝回転量）が多いほど1回の給餌量が増える。クランクが回る手応えあるアニメ＋コオロギが飼育槽へ散る＋トカゲが反応。 |
| **トルク／レート設定** | クランクの脇に小さなレート設定（低〜高）。オート時の給餌頻度を決める。"回り具合"＝レート。 |
| **オート（トグル）** | ONで、クランクが設定レートで自動回転し、空腹個体へ連続給餲。コオロギ在庫が尽きたら停止（下記コオロギ自動補給がONなら継続）。 |
| **コオロギ自動補給（コオロギマーク・トグル）** | ONで、オート稼働時に**不足分のコオロギをGoldから自動購入**して給餌する。**Goldがある限り永続稼働**。Goldが尽きたら一時停止し、回復で自動再開。 |

- **手動とオートは排他ではない**: オートOFFでも手動クランクはいつでも可能。オートONなら放置で回り続ける。
- **餌の効果**: 給餌の効果（満腹回復・成長カウント）は既存ロジックをそのまま呼ぶ。ダイヤルは"入力手段"の差し替えであり、"結果"は不変。

### 1.3 フィードバック（平常は静か・UISkills遵守）

- 手動給餌: クランク回転＋コオロギ散布パーティクル＋対象トカゲの反応＋短いSE（既存流用可）。
- オート稼働中: クランクが**ゆっくり回り続ける穏やかな表示**＋"稼働中"の淡い発光。**ヒーロー演出やトーストを毎回出さない**（放置で氾濫させない）。空腹→給餌の様子が飼育槽内で自然に見える程度に留める。
- 状態表示: 現在の空腹個体数、オート/補給のON/OFF、コオロギ在庫（またはGold駆動中の表示）をクランク近傍に小さく。

### 1.4 左列からの撤去と整理

- **左「ショップ/行動」列から「一括餌やり」を撤去**（給餌ダイヤルへ移設）。これで購入・繁殖が隣接し、誤タップ源が消える。
- コオロギ購入（×1,000／×10.0K）は在庫の手動確保用として**ショップに残す**が、コオロギ自動補給ONなら購入は任意になる。

### 1.5 アクセシビリティ

- **ドラッグ必須にしない**: クリックだけでも給餌でき、トグルは通常のボタン/スイッチとして操作可能に。キーボードフォーカス対応。
- reduced-motion時: クランクの回転アニメを止め、機能は維持（給餌は即時反映）。
- クリック標的は十分な大きさ（誤操作しないが、隣接要素と干渉しない配置）。

### 1.6 テスト／完了条件

- **テスト**: 手動クランクで給餌（トルクで量が変わる）／オートONで連続給餌／コオロギ自動補給ONでGold消費・在庫ゼロでも永続稼働／Gold枯渇で停止・回復で再開／左列から一括餌やりが消え購入・繁殖が誤タップしにくくなった／reduced-motion・キーボードで操作可／飼育槽内の他クリック対象（トカゲ・巣・氷穴）と干渉しない。
- **完了条件**: 給餌が飼育槽右下のダイヤルに一本化され、手動・オート・Gold永続の3運用が成立。誤タップ構造が解消。既存の給餌効果ロジックは不変。

## Phase 2 — ボタン言語の作り込み＋左列再設計

**「焼き増し」からの脱却。** Phase 2（前スプリント）は既存フォーマットに色とジュースを足しただけで、ボタンの造形自体は元のままだった。ここで**ボタンを1から作り込む。**

### 2.1 ボタン造形の刷新

- 現状のフラットな角丸矩形を脱し、**据え物としての物理感**（微妙なエンボス/彫り込み、押下で沈む立体、素材感のあるふち）を与える。テラリウムの"操作卓"に置かれた道具のような手触り。
- **種別で造形を明確に差別化**する（今は色しか違わない）:
  - 主行動（繁殖など）＝生命の緑・主張の強い造形
  - ショップ（購入）＝琥珀・取引の造形
  - 設備/巣/味方など画面遷移＝落ち着いた造形
  - トグル（オート等）＝スイッチとして明確に区別
- **選択肢を出す**: いきなり全置換せず、代表ボタン（繁殖 or 購入）で**造形案を2〜3種**作り、スクショを並べて提示。Ricが選んでから全体へ横展開する（ガラス強度の時と同じ進め方）。

### 2.2 左列の再設計

- 一括餌やりが抜けた（Phase 1）左列を、詰め直して整理する。
- 残る項目: 購入 / 繁殖 / 設備 / 味方 / 巣・探索。**行動**と**画面遷移**でグループを分け、余白で呼吸させる。
- **味方ボタンの転換**: 現在の位置から、より意味の通る場所へ。味方は"特別な仲間"であり画面遷移系なので、設備・巣と同じ遷移グループへ。（ステージ固有化・解放撤廃は§7の判断待ちで、本Phaseでは**位置と造形のみ**扱う。）

### 2.3 テスト／完了条件

- **テスト**: 造形案の選定後、全ボタンが新言語で統一／種別が造形で見分けられる／既存機能・遷移が全維持／トグル（Phase 1のオート等）がスイッチとして明確／コントラストAA維持。
- **完了条件**: ボタンが"焼き増し"を脱し、種別が造形で伝わる。左列が整理され誤操作しにくい。

## Phase 3 — ボス脅威感の完全刷新

**このゲームで唯一"怖くていい"要素。** 現状のボスは小さなHPバー付きスプライトで脅威感が薄い。**完全刷新して、現れた瞬間の脅威を最大化する。**

> **魂の線引き（重要）**: 保護対象の"魂"は**トカゲ・大地・飼育槽の描画**。**ボスは魂ではなく脅威**なので、脅威感のためにボスの描画（レンダラ）に手を入れてよい。ただし**トカゲ・フィールドの描画には一切触れない。**

### 3.1 登場（Telegraph）— 現れる瞬間に全力

- 襲来開始で**飼育槽が緊張状態へ**: 危機のヴィネットが脈打ち、Neo-Terrariumの琥珀基調が一時的に危機の赤へ寄る（UIの縁・アクセント）。ごく軽い画面震動。
- ボスは**フィールド端から大きな影/シルエットとして迫り**、トカゲが可視に散る・身構える（既存個体挙動の範囲で）。
- 前スプリントのボス・ヒーローカットイン（Phase 5）と接続しつつ、**フィールド内の登場そのもの**を重くする。

### 3.2 ボスの造形・スケール・挙動

- ボスを**大きく・威圧的に**描く（かわいい register を破る）。静的スライドではなく、**とぐろ・威嚇・呼吸などの挙動**を持たせる。目や質感で脅威を出す。
- **ティア表現**: 高ティア（T2+）はオーラ/発光、T5級は禍々しさを増す。**Enrage（残HP20%）**で赤く明滅・攻撃間隔短縮を視覚化（V2 §① の設計を描画で実現）。

### 3.3 ボス戦のUI

- 現在の小さな浮遊HPバーを廃し、**上部中央に映画的なボスHPバー**を据える: ボス名（判子フォント DotGothic16）＋ティアバッジ（T5）＋HP数値＋ボスの小ポートレート/アイコン。
- 被弾フィードバックの重量化: ヒットでボスがフラッシュ、ダメージ数値に重み（大きく・パンチのある演出）、タップ加勢の手応え。
- 撃破: フィールド内の死に様を劇的に（のけぞり→崩壊→報酬噴出）。Elite/大ボス/T3+の撃破ヒーロー（Phase 5）はそのまま活かす。

### 3.4 濃淡の配慮（放置を殺さない）

- **中盤は毎回ボス**（R30+）。だから**登場演出は"重いが短い"**（脅威は出すが数秒・スキップ可）。毎戦フル暗転で長時間眺めを妨げない。危機のUI変色・ヴィネットは戦闘中のみで、終了後に完全に平常へ戻す（残り香ゼロ）。
- reduced-motion: 震動・明滅・カメラ効果を止め、静的な危機表示に置換。

### 3.5 テスト／完了条件

- **テスト**: 登場で脅威が伝わる（変色・迫り・トカゲの反応）／ボスが大きく挙動を持つ／ボスHPバーがボス名・ティア・数値で映える／被弾・撃破の手応え／戦闘終了後にUIが完全に平常へ戻る（残り香ゼロ）／reduced-motion対応／**トカゲ・フィールド描画は不変**／毎戦でも長時間眺めを妨げない。
- **完了条件**: ボスが「現れた瞬間に怖い」存在になり、かつ放置の心地よさを損なわない。

## 安全制約（全Phase共通・前スプリントの規律を継承）

1. **一括置換の前に必ずgrepで件数確認。** 関数エントリポイント（openXxx等）を巻き込む置換は禁止。想定より多ければ分割。
2. **1機能=小コミット（200〜400行目安）**、単体でレビュー可能に。1画面/1機能ごとに前後スクショ。
3. **各コミット後にビルド/構文チェック＋主要画面スクショ**（メイン/巣/HQ/惑星マップ/新規起動＋当該画面）で回帰確認してから次へ。
4. 破壊的変更の前にバックアップ。崩れは即ロールバック。
5. 数値・色・時間はハードコードせず、`UISkills.md`のトークンへ集約。
6. **コンテキストが肥大したら /clear**（HANDOFF/CLAUDE.mdに記録があるため情報は失われない）。特にPhase境界で有効。

## 禁止事項

- **トカゲ・大地・飼育槽の描画（魂）には触れない。** ボスの描画は脅威のため可（Phase 3）。
- **給餌の"効果"ロジックを変えない。** ダイヤルは入力手段の差し替えで、既存の給餌処理を再利用する。
- **平常画面を賑やかにしすぎない。** オート給餌・ボス戦の演出を平常へ持ち込まない（残り香ゼロ）。
- **UISkillsに無いスタイルを場当たりで足さない。** 足すなら先にUISkillsへ追記。
- **Phase 0（巣バグ）完了前に他Phaseへ進まない。**
- 各Phaseの節目でスクショと完了条件チェックをHANDOFFに残す。
