# roulette.md — 遺伝子ルーレット設計憲章

- 版: 1.0
- 位置づけ: 給餌に連動する新しい繁殖演出システム「遺伝子ルーレット」の恒久設計憲章。工数・検証が大きいため独立文書として管理する。実装は `Roulette_Sprint`（別途）で行う。
- 前提: V5でコオロギ廃止・Gold消費給餌へ移行し、左メニュー下部に本システムを設置する。

---

## 0. コンセプト

給餌するたびに、遺伝子の球が放出され、ルーレットを通って一定確率で卵が生まれる。**餌やり＝遺伝子の抽選**という体験。純血設計（GameExpansion_V5 Phase 4）と噛み合い、「その惑星の生態系の中で、繁殖により新しい個体・稀に新種が生まれる」楽しさを、視覚的なルーレットで表現する。

- クランクで手作業の餌やりが不要になった今、プレイヤーの注意は「何が生まれるか」に向く。ルーレットはその期待を可視化する装置。
- 大量給餌（オート高）で球が増え、球同士がぶつかって意図せぬ動きが生まれ、レア（レインボー）の確率が上がる——**偶然性と物理の面白さ**を核にする。

## 1. 構造（レール→フリーフォール→釘→虹）※v3改訂（物理決定型パチンコ）

> **設計転換（Ric・v3・最重要）**: v2の「emit時に結果確定→演出で公開（スクラッチカード式）」を**撤回**。**結果を先に決めてはならない。** 球を射出したあと、**落下の物理そのものが結果を決める**。プレイヤーは落下を見守り、大当たりを狙う——それが本物のパチンコ体験であり、本システムの核心。

### 1.1 球（見た目）
- 球は**しっかりとした球体**として描く（初期検証で出ていた大きめの球体の見た目）。小さすぎる粒（ミジンコのような点）にしない。落下や跳ね返りが目で追える大きさ・質感。

### 1.2 発射
- **自動OFF** → **クランク1クリックにつき1発**だけ発射（単発発射が必ず機能すること。※現状これが動作していない＝要修正）。
- **自動ON** → 等間隔で自動的に連続発射。
- 発射は給餌に接続（給餌1回＝球1発）。

### 1.3 落下の流れ（レール→フリーフォール→釘）
1. **レール区間**: 射出された球は、まずレールに沿ってある程度落下する（軌道が導く区間）。
2. **フリーフォール区間**: レールを離れた後は**必ず自由落下**させる。ここからは軌道に縛られない、本物の物理落下。
3. **釘との衝突**: 落下中に**釘に当たって不規則に跳ね**、進路が変わりながら落ちていく。パチンコの釘と同じ役割＝**偶然性を生む装置**。
4. **着地**: 最後に**虹（大当たり）に入るか、入らないか**が決まる。

### 1.4 結果の決まり方（事前確定の禁止）
- **結果は落下の物理が決める。** 発射時点では当たり/外れは決まっていない。釘に当たった軌跡の結果として、虹に入るか入らないかが決まる。
- **大当たり（虹）＝未所持の新種**（種族同一）。
- **大当たりでなくても、当たりは確実にもらえる**——虹に入らなかった球も、**通常の当たり（卵）は確実に**得られる。空振り（何も得られない）はない。

## 2. 確率（物理から創発させ、物理パラメータで調整）※v3改訂

- **確率を数式で先に決めて演出で見せるのではない。** 釘の配置・間隔・反発、虹の穴の幅・位置、落下の初期条件などの**物理パラメータを調整して、結果的に大当たり率が目標値（0.5%＝200発に1回を基準）付近になるようにする**。
- **検証方法**: 多数回シミュレーション（モンテカルロ）を回し、**物理から創発する実測の大当たり率**を測る。目標帯（0.5%付近）に収まるまで、釘の配置や穴の幅といった**物理パラメータを反復調整**する（roulette.md §6 反復推論プロトコル）。
- **決定論**（fable2）: 落下・衝突の乱数（初速のばらつき等）は単一シード窓口経由。同一シード＋同一発射列＝同一結果で再現・検証可能にする。決定論だからこそ、モンテカルロで大当たり率を信頼して測れる。
- **fable1「見た目と真実のズレ」の解消**: v3では**見えている落下がそのまま真実**（結果を先に決めていないので、演出と結果の乖離が原理的に起きない）。球が虹に入ったら当たり、入らなければ通常。プレイヤーが見たものが、起きたこと。

## 3. 卵と景品システム



- レーン2到達で**卵が産まれる**（既存の繁殖・卵スロットと接続）。
- レインボー穴＝**未所持の新種の卵**（種族同一）。既存の「固有種2種」設計（V5 Phase 4）や図鑑と整合させる。
- 景品（生まれる種）の抽選ロジックは、そのステージの固有種・所持状況に基づく（未所持を優先的にレインボー景品に）。

## 4. 実装上の注意（工数・検証が大きい）

- **物理シミュレーション**（球の放出・移動・衝突・落下）は負荷と検証が要る。球数上限・パフォーマンス（大量球でのフレーム落ち）を必ず実測。
- **確率の検証**：通常卵率・レインボー率が意図通りか、大量球でレインボー率が上がることを数値で実証。
- **偶然性の公平性**：確率が破綻しない（レインボーが出過ぎ/出なさ過ぎない）よう、CFGで全確率を調整可能に。
- **既存システムとの接続**：卵スロット・繁殖・図鑑・純血設計（固有種2種）と矛盾しないこと。
- reduced-motion時：物理演出を簡略化（結果は保証）。魂（トカゲ・大地・飼育槽）不変。
- `roulette_skills.md`（実装作法・物理/確率のチューニング指針）を必要に応じて作成。

## 5. この憲章の使い方

- ルーレットに関わる実装は着手前に本ファイルを読む。仕様追加は先に本ファイルへ追記してから実装。
- 工数が大きいため、段階実装（GameExpansion_V5 Phase K の K.1）で1段階ずつ作り込む。

## 6. 高クオリティ構築のための反復推論プロトコル（長時間自律実行用）

> このシステムは本作の新たな目玉であり、"動けばよい"ではなく**高いクオリティ**を目指す。長時間の自律実行では、下記の「ゴールを決めて反復改善する」ループで作り込むこと。1回作って終わりにしない。

### 6.1 クオリティのゴール（達成基準＝これを満たすまで反復する）
1. **物理が気持ちいい**: 球の放出・落下・衝突・跳ね返りが、見ていて心地よく自然。カクつかない。大量球でも破綻しない。
2. **カオスが意味を持つ**: 大量給餌（オート高）で球が増えて衝突が増え、"混沌としてきた→レインボーに入りやすい"が視覚的にも確率的にも体感できる。少量と大量で明確に体験が違う。
3. **レインボーが"事件"になる**: レインボー穴に入って未所持の新種が生まれる瞬間が、思わず声が出るジュース感（演出・音・間）を持つ。日常の卵とレアの卵の差が劇的。
4. **公平で壊れない**: 通常卵率・レインボー率が意図した範囲に収まり、出過ぎ/出なさ過ぎない。確率が数値検証で保証される。
5. **既存と調和**: 卵スロット・繁殖・図鑑・純血設計（固有種2種）と矛盾せず、Neo-Terrarium/UISkillsの世界観に収まる。
6. **性能**: 想定球数上限でフレーム落ちなし（60fps維持）。reduced-motionで簡略化しても結果は保証。

### 6.2 反復ループ（各段階で回す）
各実装段階（K.1の1〜5）ごとに、以下を繰り返す:
1. **実装** → 2. **自己検証**（スクショ＋数値：球の軌跡・衝突回数・卵率・レインボー率・fpsを実測）→ 3. **ゴール（6.1）と照合**（どの基準にどれだけ届いていないかを言語化）→ 4. **改善案を複数出して比較**（1案で満足せず、パラメータ/物理式/演出の代替を2案以上検討）→ 5. **最良案を適用して再検証** → 基準を満たすまで繰り返す。
- **1回で満足せず、"もっと良くできないか"を各段階で最低数回問い直す。** 特に物理の手触り（6.1-1,2）とレインボーのジュース（6.1-3）は反復価値が高い。
- 反復の過程（試した案・数値・なぜその案にしたか）をHANDOFFに記録し、Ric帰還後に判断の経緯を追えるようにする。

### 6.3 CFG化（Ric帰還後の最終調整を前提）
- 通常卵率・レインボー率・球速・重力・反発係数・衝突係数・球数上限・放出数・レインボー穴の判定幅・演出の強度——**すべてCFGに集約**。自律実行では"良い初期値"まで反復で追い込み、最終の手触りはRicが実機で確定する。CCが到達した推奨値と、その根拠（数値）をHANDOFFに残す。

### 6.4 設置スペース（V5の空間再設計と連動）
- ルーレットは、コオロギUI撤廃で空いた左メニュー下部＋右パネル縮小分の幅を使う。ただし**飼育水槽の拡大が最優先**（GameExpansion_V5）。水槽を広げた上で、残りの幅でルーレットが機能的に成立するレイアウトにする。狭ければ縦構成・折返し等で機能を保つ。

## 7. アーキテクチャ（v3・物理決定型パチンコ）※実装の正本

> **v2からの転換**: v2は「emit時に結果確定＋パラメトリック軌道(進行度p)＋表現層のeasingで減速＝焦らし」だった。v3では**結果を先に決めない**——落下の物理そのものが結果を決める（§1.4）。よって重力・衝突・反発の**物理シミュレーションをルール層に復活**させる。v2の p+easing は撤去。

### 7.1 レイヤー分離（fable2・決定論）
- **ルール層 `js/roulette.js`＝物理シミュレーション（決定論・単一シード窓口・DOM非依存）**。
  - 球の実体を保持: `{id, x, y, vx, vy, r, gene, phase, landed}`（座標と速度＝真実。進行度pは持たない）。
  - 固定タイムステップ積分（`CFG.roulFixedDt`・アキュムレータ方式）で**フレーム非依存＝決定論**。同一シード＋同一発射列＝同一軌跡＝同一結果。だからモンテカルロが信頼できる。
  - 重力・釘衝突・壁反射・反発を積分。**当たり/外れは着地時のx座標が虹穴の範囲に入るかで決まる**（事前抽選なし）。
  - 乱数は初速のばらつき・衝突の微小ジッタ**のみ**、単一窓口 `_rng`(mulberry32) 経由。`onEgg({gene, rainbow})`／events を発火。
- **表現層 `js/ui/screens/roulette.js`＝描画のみ**。ルール層の実 `(x,y)` をそのまま描く。釘・レール・虹穴も描く。**結果は計算しない**（見えている落下がそのまま真実＝§2 fable1のズレが原理的に起きない）。

### 7.2 落下フェーズ（§1.3の物理化）
1. **発射(emit)**: 球を発射口（上部）に生成。初速 `vx=_rand(-roulInitVxJit, +roulInitVxJit)`、`vy=roulInitVy`。**rainbowは決めない**。
2. **レール区間(phase=rail)**: `y < roulRailEndY` の間はレール曲線へx を寄せつつ重力で加速（軌道が導く導入部）。
3. **フリーフォール＋釘(phase=fall)**: レール終端で解放。以降 `vy += roulGravity*dt`。**釘**（`roulNailRows×roulNailCols`・千鳥配置・半径`roulNailR`）との距離が `r+nailR` 未満で反射（法線方向に反発係数`roulRestitution`＋微小ジッタ）。左右壁も反射(`roulWallRestitution`)。
4. **着地(land)**: `y >= roulLandY` で停止。x が `[roulHoleX ± roulHoleW/2]` 内なら **rainbow**、外なら **通常**。どちらも `onEgg` を発火＝**空振りなし**（§1.4）。

### 7.3 確率（物理から創発・§2）
- 数式で先に決めない。**虹穴の幅`roulHoleW`・位置`roulHoleX`、釘の間隔・千鳥量、反発`roulRestitution`、初速ばらつき`roulInitVxJit`** を調整し、モンテカルロ実測の虹率が **0.5%（1/200）付近**に収まるまで反復（§6）。
- 決定論ゆえ、`setSeed`＋固定dt＋同一発射列で**node単体でN万回シミュレート**して虹率を測れる。

### 7.4 パフォーマンス・reduced-motion
- `roulMaxBalls` で同時球数を制限。固定dtアキュムレータで積分回数を管理し60fps維持を実測。
- reduced-motion: 物理は回すが装飾（尾・バースト等）を抑制。結果は保証。魂不変。

### 7.5 既存接続（不変）
- `onEgg({gene, rainbow})` の契約は**v2と同一**＝`Game.spawnRouletteEgg` は無改修。発射は `Game.feedAll` の給餌1回＝`Roulette.emit(gene)` 1発（配線不変）。
- CFG: v2の軌道パラメータ（roulTravelSec/roulFallEase/roulRiseP/roulArcP/roulCommitP/roulLaunch*/roulApex*/roulFallX/roulSlotX/roulLaneJitter）を撤去し、v3物理パラメータ（roulGravity/roulRestitution/roulWallRestitution/roulBallR(大)/roulNailRows/Cols/roulNailR/roulNailStagger/roulRailEndY/roulLandY/roulHoleX/roulHoleW/roulInitVy/roulInitVxJit/roulFixedDt）へ置換。全てCFG（§6.3）。
