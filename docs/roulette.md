# roulette.md — 遺伝子ルーレット設計憲章

- 版: 1.0
- 位置づけ: 給餌に連動する新しい繁殖演出システム「遺伝子ルーレット」の恒久設計憲章。工数・検証が大きいため独立文書として管理する。実装は `Roulette_Sprint`（別途）で行う。
- 前提: V5でコオロギ廃止・Gold消費給餌へ移行し、左メニュー下部に本システムを設置する。

---

## 0. コンセプト

給餌するたびに、遺伝子の球が放出され、ルーレットを通って一定確率で卵が生まれる。**餌やり＝遺伝子の抽選**という体験。純血設計（GameExpansion_V5 Phase 4）と噛み合い、「その惑星の生態系の中で、繁殖により新しい個体・稀に新種が生まれる」楽しさを、視覚的なルーレットで表現する。

- クランクで手作業の餌やりが不要になった今、プレイヤーの注意は「何が生まれるか」に向く。ルーレットはその期待を可視化する装置。
- 大量給餌（オート高）で球が増え、球同士がぶつかって意図せぬ動きが生まれ、レア（レインボー）の確率が上がる——**偶然性と物理の面白さ**を核にする。

## 1. 構造（レール→フリーフォール→釘→虹）※v3改訂（物理決定型パチンコ）

> **設計転換（Ric・v3・最重要）**: v2の「emit時に結果確定→演出で公開（スクラッチカード式）」を**撤回**。**結果を先に決めてはならない。** 球を射出したあと、**落下の物理そのものが結果を決める**。プレイヤーは落下を見守り、大当たりを狙う——それが本物のパチンコ体験であり、本システムの核心。

### 1.1 球（見た目）
- 球は**しっかりとした球体**として描く（初期検証で出ていた大きめの球体の見た目）。小さすぎる粒（ミジンコのような点）にしない。落下や跳ね返りが目で追える大きさ・質感。

### 1.2 発射【v4改訂：ボス討伐後の報酬として実行】

> **設計転換（Ric・v4・重要）**: ルーレットを**左メニューからの常設表示・給餌連動の常時発射**から、**ボス討伐後の報酬**へ変更する。
>
> **理由**: 実プレイ検証（Ric＋デバッガー）で、常設のルーレットに注意が奪われ、本作のコンセプト「**トカゲを飼育し、眺める**」が損なわれることが判明した。動き続ける球は、静かに生き物を眺める体験と両立しない。左メニューから撤去し、飼育槽を全画面化する。
>
> **移設先の意義**: ボスは既に「画面を開いて待ち、討伐まで見届けた者だけが報酬を得る」体験（V5 Phase 3.11.3）。**その報酬がルーレット**となり、2つの設計が噛み合う。見届けた先に、球を撃つ儀式がある。

- **ボス討伐後にルーレットが起動**し、**一定数の球を撃てる**（球数はCFG。ボスのTier/Lvに応じた増加も検討）。
- 給餌連動の常時発射・レート別発射間隔（roulEmitIntervalByRate）は**この文脈では使わない**（撤去または報酬モード用に転用）。
- 球の射出＝抽選の機会であり、卵の獲得を約束するものではない（獲得可否は §1.4 の着地で決まる）。

### 1.2.1 【必須】報酬文脈に合わせた確率の再設計
> **旧確率（卵1/16.8・虹1/200）は「常時大量に球が飛ぶ」前提で調整されたもの。** ボス報酬（1回あたり数十球）にそのまま適用すると、**卵はほとんど得られず、虹（未所持の新種）はボス200回相当で事実上到達不能**になる。**必ず報酬文脈に合わせて再設計すること。**

- 決めるべき3つ（実装前に複数案を提示してRic承認）:
  1. **ボス1回あたりの球数**（固定か、ボスTier/Lvで増えるか）
  2. **卵の獲得率**（報酬なので旧値より大幅に引き上げる）
  3. **虹（未所持の新種）の確率**（新種発見がボス報酬の目玉になるなら、旧1/200では渋すぎる）
- 参考の方向性（Ric推奨・要検討）: 球数はTierに応じて増加（例 T1=10球 → T6=40球）、卵率は1/3〜1/4程度、虹は1/20〜1/50程度。「ボスを倒すたびに数個の卵、たまに新種」という報酬感を狙う。
- 確率は従来どおり**物理から創発**させる（景品穴・虹穴の幅、釘配置で調整）。モンテカルロで3率を実測し、目標帯に収まるまで反復（§6・roulette_rules §4）。


### 1.2.2 ボスの格による景品ポケットの differentiation【v4.1】

- **ルーレットは、通常ボス・大ボスのどちらの討伐でも開始される**（大ボス限定ではない）。
- **ただし盤面の景品ポケットの種類が、ボスの格によって変わる**:
  - **通常ボス → レアポケット**
  - **大ボス → 虹レアポケット**（＝未所持の新種）
- 狙い: 通常ボスにも戦う理由を残しつつ、**新種の発見は大ボスの特権**とする。ボスの格が報酬の質に直結する。
- 球数は従来どおりボスTierに応じる（roulRewardBalls）。

#### 実装前に確定すべき事項
1. **「レアポケット」の中身**: 虹＝未所持の新種に対し、通常ボスのレアポケットは何を出すか（レア卵＝既存固有種の高品質個体／ジェム／Gold 等）。※Ric推奨は「レア卵」（将来の特性システムと接続の余地があり、"卵を得る"体験の延長になるため）。
2. **「大ボス」の定義**: コード上の区別（ELITEフラグ等）を実測で確認し、どのボスが大ボス扱いかを明確にする。
3. **【重要・純血設計との整合】虹が出す「未所持の新種」の定義**: 純血化により `breedablePool` は現在の惑星の固有種2種のみ。固有種#1はスタートのペア、#2は過去ステージ復帰の報酬で得られるため、**その惑星で「未所持の種」は原理的にほぼ存在しない**可能性がある。虹に入っても出すものがない状態になり得るため、虹の景品定義を純血設計に合わせて決め直すこと（例：レア変異個体／高星個体／将来の特性付き個体／全種所持済みなら別の価値へ変換）。※現行実装でも既に発生し得る問題として調査すること。

#### 確定事項（2026-07-19・Ric承認 / C1.5・C2a 実装済）
1. **レアポケット（通常ボス）＝レア卵**: 固有種の卵で**レアモーフ(albino/mela/golden)確率UP**(`CFG.roulRareMorphChance`=0.5)＋**初期Lvボーナス**(アダルトで `1+CFG.roulRareEggBonusLv` として誕生)。将来の特性システム（trait_system.md）に接続。
2. **大ボス＝elite**: `r.elite`(R30+・5戦ごと・カットイン持ち)。通常ボス＝`r.boss && !r.elite`。**R30未満はeliteが無く全て通常ボス**（＝新種発見はR30以降の特権）。
3. **虹＝未所持の図鑑エントリ**（固有種2種×非レジェンダリ4モーフ＝**8枠**。レアモーフも「新発見」として成立し、新規時点で7枠が未所持）。**全8枠コンプ後はレジェンダリー個体**（apex・既存 `heroLegendBirth` 演出）へフォールバックし、虹を空振りにしない。実測: 全所持惑星で虹→旧実装は"平凡な通常卵"へ劣化していた（本改修で解消）。
4. **盤geometryは共通**（中央 2.6% / 卵帯 28% / ハズレ 69%）。**中央ポケットの色と景品だけ**ボス格で差替（虹＝七色 / レア＝琥珀）。MCは1回で両盤に適用（roulette_rules §4を満たす）。報酬文脈の確率は `roulPrizeOuterf=0.215`・`roulRainbowHalfWf=0.06`（MCで卵1/3.5・虹1/40=1/39を実測確定）。球数は `CFG.roulRewardBalls`（Tier別 8→40）。

### 1.2.3 報酬モーダル内のクランク【v4.2】

> **設計（Ric）**: 報酬ルーレットのモーダル内、盤面の**右下にクランクを再登場**させる。餌を与えていた機構が、そのまま遺伝子の球を撃ち出す。

- **モーダルは十分に大きく**表示する（盤・球の落下・釘の跳ねが見やすいこと）。
- **盤面の右下にクランクを配置**する。これは `crank.md` の既存クランク機構を**再利用**する（新規の別機構を作らない）。
- **操作モデル（ボス前のオート状態を継承）**:
  - **ボス前に自動回転モードだった場合** → モーダル内でも**自動で射出**（操作不要）。
  - **自動回転OFFだった場合** → **クリックで1発／長押しで連続射出**。
- **意義**: クランクは「生物に崇められる食料神」（crank.md）＝餌を与え生命を育む装置。それが遺伝子の球を撃つことで、**同じ機構が育成と繁殖の両方を司る**。プレイヤーの普段の遊び方（放置派／じっくり派）が報酬の場でもそのまま続く。

#### 将来（惑星ごとの意匠）
- 今後、ルーレットの構造（レール・釘・受け皿・台）を**惑星ごとに合わせていく**（`roulette_rules.md`）。**モーダル内のクランクも、その惑星のクランクスキン（crank.md 10種）を使う**ことを前提に設計すること。
- `roulette_rules.md` §0 の原則（**骨格・確率は全惑星で不変／意匠のみ惑星ごと**）が、盤とクランクの両方に適用される。意匠変更時は §4 の必須プロセス（モンテカルロで3率を再測）に従う。
- クランクの不変条件（回る主体・緑=オート・#spin-proof の回転継続）は、モーダル内でも維持すること。

### 1.3 落下の流れ（レール→フリーフォール→釘）
1. **レール区間**: 射出された球は、まずレールに沿ってある程度落下する（軌道が導く区間）。
2. **フリーフォール区間**: レールを離れた後は**必ず自由落下**させる。ここからは軌道に縛られない、本物の物理落下。
3. **釘との衝突**: 落下中に**釘に当たって不規則に跳ね**、進路が変わりながら落ちていく。パチンコの釘と同じ役割＝**偶然性を生む装置**。
4. **着地**: どこに落ちたかで結果が決まる（§1.4）。

### 1.4 結果の決まり方（事前確定の禁止・ハズレあり）【最重要】

> **【重要事項】卵は「必ずもらえる」ものではない。景品穴に入った時だけ獲得できる。** 旧版の「空振りなし・落ちれば必ず卵」は**誤り**であり撤回する。パチンコと同じく、**入賞しなければハズレ**。ハズレがあるからこそ入賞が嬉しい。

- **結果は落下の物理が決める。** 発射時点では当たり/ハズレは決まっていない。釘に当たって跳ねた軌跡の結果として、どこに着地するかが決まる。
- **着地による結果は3種類**:
  1. **景品穴に入る → 卵を獲得**（通常の当たり）。
  2. **虹穴に入る → 大当たり**。確定で未所持の新種（種族は同一）。**稀**に入る穴として設ける。
  3. **どちらの穴にも入らない → ハズレ**（何も得られない）。
- 景品穴・虹穴は複数/単数いずれでもよいが、**虹穴は景品穴より遥かに入りにくい**位置・幅にする。


## 2. 確率（物理から創発させ、物理パラメータで調整）※v3改訂

- **確率を数式で先に決めて演出で見せるのではない。** 釘の配置・間隔・反発、**景品穴と虹穴の幅・位置**、落下の初期条件などの**物理パラメータを調整して、結果的に目標の入賞率になるようにする**。
- **調整すべき2つの率**（どちらも物理から創発させる）:
  1. **卵の獲得率（景品穴に入る率）** — 射出した球のうち、どれくらいが卵になるか。ハズレとのバランスで、遊びのテンポを決める（実機で手触りを見て確定）。
  2. **大当たり率（虹穴に入る率）** — **0.5%＝200発に1回**を基準。景品穴より遥かに入りにくい位置・幅にする。
- **検証方法**: 多数回シミュレーション（モンテカルロ）を回し、**物理から創発する実測の入賞率・大当たり率**を測る。目標帯に収まるまで、釘の配置や穴の幅といった**物理パラメータを反復調整**する（roulette.md §6 反復推論プロトコル）。
- **決定論**（fable2）: 落下・衝突の乱数（初速のばらつき等）は単一シード窓口経由。同一シード＋同一発射列＝同一結果で再現・検証可能にする。決定論だからこそ、モンテカルロで各率を信頼して測れる。
- **fable1「見た目と真実のズレ」の解消**: v3では**見えている落下がそのまま真実**（結果を先に決めていないので、演出と結果の乖離が原理的に起きない）。球が穴に入ったら獲得、入らなければハズレ。プレイヤーが見たものが、起きたこと。


## 3. 卵と景品システム



- レーン2到達で**卵が産まれる**（既存の繁殖・卵スロットと接続）。
- レインボー穴＝**未所持の新種の卵**（種族同一）。既存の「固有種2種」設計（V5 Phase 4）や図鑑と整合させる。
- 景品（生まれる種）の抽選ロジックは、そのステージの固有種・所持状況に基づく（未所持を優先的にレインボー景品に）。

## 4. 実装上の注意（工数・検証が大きい）

- **物理シミュレーション**（球の放出・移動・衝突・落下）は負荷と検証が要る。球数上限・パフォーマンス（大量球でのフレーム落ち）を必ず実測。
- **確率の検証**：通常卵率・レインボー率が意図通りか、大量球でレインボー率が上がることを数値で実証。
- **偶然性の公平性**：確率が破綻しない（レインボーが出過ぎ/出なさ過ぎない）よう、CFGで全確率を調整可能に。
- **既存システムとの接続**：卵スロット・繁殖・図鑑・純血設計（固有種2種）と矛盾しないこと。
- reduced-motion時：物理演出を簡略化（結果は保証）。魂（トカゲ・大地・飼育槽）不変。
- `roulette_skills.md`（実装作法・物理/確率のチューニング指針）を必要に応じて作成。

## 6. 高クオリティ構築のための反復推論プロトコル（長時間自律実行用）

> このシステムは本作の新たな目玉であり、"動けばよい"ではなく**高いクオリティ**を目指す。長時間の自律実行では、下記の「ゴールを決めて反復改善する」ループで作り込むこと。1回作って終わりにしない。

### 6.1 クオリティのゴール（達成基準＝これを満たすまで反復する）
1. **物理が気持ちいい**: 球の放出・落下・衝突・跳ね返りが、見ていて心地よく自然。カクつかない。大量球でも破綻しない。
2. **カオスが意味を持つ**: 大量給餌（オート高）で球が増えて衝突が増え、"混沌としてきた→レインボーに入りやすい"が視覚的にも確率的にも体感できる。少量と大量で明確に体験が違う。
3. **レインボーが"事件"になる**: レインボー穴に入って未所持の新種が生まれる瞬間が、思わず声が出るジュース感（演出・音・間）を持つ。日常の卵とレアの卵の差が劇的。
4. **公平で壊れない**: 通常卵率・レインボー率が意図した範囲に収まり、出過ぎ/出なさ過ぎない。確率が数値検証で保証される。
5. **既存と調和**: 卵スロット・繁殖・図鑑・純血設計（固有種2種）と矛盾せず、Neo-Terrarium/UISkillsの世界観に収まる。
6. **性能**: 想定球数上限でフレーム落ちなし（60fps維持）。reduced-motionで簡略化しても結果は保証。

### 6.2 反復ループ（各段階で回す）
各実装段階（K.1の1〜5）ごとに、以下を繰り返す:
1. **実装** → 2. **自己検証**（スクショ＋数値：球の軌跡・衝突回数・卵率・レインボー率・fpsを実測）→ 3. **ゴール（6.1）と照合**（どの基準にどれだけ届いていないかを言語化）→ 4. **改善案を複数出して比較**（1案で満足せず、パラメータ/物理式/演出の代替を2案以上検討）→ 5. **最良案を適用して再検証** → 基準を満たすまで繰り返す。
- **1回で満足せず、"もっと良くできないか"を各段階で最低数回問い直す。** 特に物理の手触り（6.1-1,2）とレインボーのジュース（6.1-3）は反復価値が高い。
- 反復の過程（試した案・数値・なぜその案にしたか）をHANDOFFに記録し、Ric帰還後に判断の経緯を追えるようにする。

### 6.3 CFG化（Ric帰還後の最終調整を前提）
- 通常卵率・レインボー率・球速・重力・反発係数・衝突係数・球数上限・放出数・レインボー穴の判定幅・演出の強度——**すべてCFGに集約**。自律実行では"良い初期値"まで反復で追い込み、最終の手触りはRicが実機で確定する。CCが到達した推奨値と、その根拠（数値）をHANDOFFに残す。

### 6.4 設置スペース（V5の空間再設計と連動）
- ルーレットは、コオロギUI撤廃で空いた左メニュー下部＋右パネル縮小分の幅を使う。ただし**飼育水槽の拡大が最優先**（GameExpansion_V5）。水槽を広げた上で、残りの幅でルーレットが機能的に成立するレイアウトにする。狭ければ縦構成・折返し等で機能を保つ。
