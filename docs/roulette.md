# roulette.md — 遺伝子ルーレット設計憲章

- 版: 1.0
- 位置づけ: 給餌に連動する新しい繁殖演出システム「遺伝子ルーレット」の恒久設計憲章。工数・検証が大きいため独立文書として管理する。実装は `Roulette_Sprint`（別途）で行う。
- 前提: V5でコオロギ廃止・Gold消費給餌へ移行し、左メニュー下部に本システムを設置する。

---

## 0. コンセプト

給餌するたびに、遺伝子の球が放出され、ルーレットを通って一定確率で卵が生まれる。**餌やり＝遺伝子の抽選**という体験。純血設計（GameExpansion_V5 Phase 4）と噛み合い、「その惑星の生態系の中で、繁殖により新しい個体・稀に新種が生まれる」楽しさを、視覚的なルーレットで表現する。

- クランクで手作業の餌やりが不要になった今、プレイヤーの注意は「何が生まれるか」に向く。ルーレットはその期待を可視化する装置。
- 大量給餌（オート高）で球が増え、球同士がぶつかって意図せぬ動きが生まれ、レア（レインボー）の確率が上がる——**偶然性と物理の面白さ**を核にする。

## 1. 構造（軌道レーン＋落下抽選）※v2改訂（パチンコ方式）

> **設計転換（Ric・v2）**: 旧版の「大量発射→球の衝突でカオス→レインボー率上昇」を**撤回**。代わりに**パチンコ方式**——等間隔で1発ずつ発射し、各球が軌道を通って落下、最奥部で独立に抽選する——に変更。確率を明確に設計・制御できることを優先する。

### 軌道レーン（放出→上昇）
- 球は画面**左下から発射**され、**左下→左上へ向かう軌道レーン**を通って上がっていく。
- 前回の「球が左下に溜まる」問題を解消：球は溜まらず、軌道レーンに沿って**段階的に運ばれる**。

### 発射リズム（パチンコ的・等間隔1発ずつ）
- **大量同時発射はしない。** 従来のパチンコのように**等間隔で1発ずつ**発射する。
- **発射トリガー**:
  - **自動ON** → 等間隔で**自動的に連続発射**（一定間隔で1発ずつ・間隔はCFG）。
  - **自動OFF** → **クランクを1回クリックするごとに1発だけ発射**（手動・1クリック=1球）。
- ※旧「給餌するたび放出」から、この発射モデルへ変更。

### 落下と最奥部抽選
- 軌道を上がった球は落下に転じ、**落下終盤にかけてゆっくりになる**（減速）。この減速で「入るか入らないか」の緊張を演出する（ジュースの核・§6.1-3）。
- 球は**最奥部**に達し、そこで**レインボーに入るか入らないかの確率抽選**を行う。
  - **レインボー**（当たり）→ 確定で「今持っていない別の種」の卵（種族は同一＝新遺伝子の発見）。
  - **通常**（外れ）→ 既存の種の卵（レーン到達＝繁殖成立は保つなら通常でも卵、または設計時に確定）。

## 2. 確率（パチンコ方式・明確な設計値）※v2改訂

- **各球は独立に抽選される**（球同士の衝突でレア率が変わる旧方式は撤回）。1発ずつ淡々と試行を積む、パチンコ/スロット的な体験。
- **基準確率：200発に1レインボー（＝0.5%）**。CFGで調整可（Ric帰還後に実機で最終調整）。
- 落下終盤の減速演出は「見た目の焦らし」であり、抽選自体は最奥部で確率的に決まる。演出（減速）と確率（抽選）は分離するが、体感として「ゆっくり近づいて、入るか入らないか」の緊張が確率の瞬間と重なるよう設計する。
- **決定論**（fable2）：抽選・軌道の乱数は単一シード窓口経由。同一シード＋同一発射列＝同一結果で再現・検証可能。0.5%が実測で出ることをモンテカルロで検証（多数回発射してレインボー率が1/200付近に収束）。

## 3. 卵と景品システム


- レーン2到達で**卵が産まれる**（既存の繁殖・卵スロットと接続）。
- レインボー穴＝**未所持の新種の卵**（種族同一）。既存の「固有種2種」設計（V5 Phase 4）や図鑑と整合させる。
- 景品（生まれる種）の抽選ロジックは、そのステージの固有種・所持状況に基づく（未所持を優先的にレインボー景品に）。

## 4. 実装上の注意（工数・検証が大きい）

- **物理シミュレーション**（球の放出・移動・衝突・落下）は負荷と検証が要る。球数上限・パフォーマンス（大量球でのフレーム落ち）を必ず実測。
- **確率の検証**：通常卵率・レインボー率が意図通りか、大量球でレインボー率が上がることを数値で実証。
- **偶然性の公平性**：確率が破綻しない（レインボーが出過ぎ/出なさ過ぎない）よう、CFGで全確率を調整可能に。
- **既存システムとの接続**：卵スロット・繁殖・図鑑・純血設計（固有種2種）と矛盾しないこと。
- reduced-motion時：物理演出を簡略化（結果は保証）。魂（トカゲ・大地・飼育槽）不変。
- `roulette_skills.md`（実装作法・物理/確率のチューニング指針）を必要に応じて作成。

## 5. この憲章の使い方

- ルーレットに関わる実装は着手前に本ファイルを読む。仕様追加は先に本ファイルへ追記してから実装。
- 工数が大きいため、段階実装（GameExpansion_V5 Phase K の K.1）で1段階ずつ作り込む。

## 6. 高クオリティ構築のための反復推論プロトコル（長時間自律実行用）

> このシステムは本作の新たな目玉であり、"動けばよい"ではなく**高いクオリティ**を目指す。長時間の自律実行では、下記の「ゴールを決めて反復改善する」ループで作り込むこと。1回作って終わりにしない。

### 6.1 クオリティのゴール（達成基準＝これを満たすまで反復する）
1. **物理が気持ちいい**: 球の放出・落下・衝突・跳ね返りが、見ていて心地よく自然。カクつかない。大量球でも破綻しない。
2. **カオスが意味を持つ**: 大量給餌（オート高）で球が増えて衝突が増え、"混沌としてきた→レインボーに入りやすい"が視覚的にも確率的にも体感できる。少量と大量で明確に体験が違う。
3. **レインボーが"事件"になる**: レインボー穴に入って未所持の新種が生まれる瞬間が、思わず声が出るジュース感（演出・音・間）を持つ。日常の卵とレアの卵の差が劇的。
4. **公平で壊れない**: 通常卵率・レインボー率が意図した範囲に収まり、出過ぎ/出なさ過ぎない。確率が数値検証で保証される。
5. **既存と調和**: 卵スロット・繁殖・図鑑・純血設計（固有種2種）と矛盾せず、Neo-Terrarium/UISkillsの世界観に収まる。
6. **性能**: 想定球数上限でフレーム落ちなし（60fps維持）。reduced-motionで簡略化しても結果は保証。

### 6.2 反復ループ（各段階で回す）
各実装段階（K.1の1〜5）ごとに、以下を繰り返す:
1. **実装** → 2. **自己検証**（スクショ＋数値：球の軌跡・衝突回数・卵率・レインボー率・fpsを実測）→ 3. **ゴール（6.1）と照合**（どの基準にどれだけ届いていないかを言語化）→ 4. **改善案を複数出して比較**（1案で満足せず、パラメータ/物理式/演出の代替を2案以上検討）→ 5. **最良案を適用して再検証** → 基準を満たすまで繰り返す。
- **1回で満足せず、"もっと良くできないか"を各段階で最低数回問い直す。** 特に物理の手触り（6.1-1,2）とレインボーのジュース（6.1-3）は反復価値が高い。
- 反復の過程（試した案・数値・なぜその案にしたか）をHANDOFFに記録し、Ric帰還後に判断の経緯を追えるようにする。

### 6.3 CFG化（Ric帰還後の最終調整を前提）
- 通常卵率・レインボー率・球速・重力・反発係数・衝突係数・球数上限・放出数・レインボー穴の判定幅・演出の強度——**すべてCFGに集約**。自律実行では"良い初期値"まで反復で追い込み、最終の手触りはRicが実機で確定する。CCが到達した推奨値と、その根拠（数値）をHANDOFFに残す。

### 6.4 設置スペース（V5の空間再設計と連動）
- ルーレットは、コオロギUI撤廃で空いた左メニュー下部＋右パネル縮小分の幅を使う。ただし**飼育水槽の拡大が最優先**（GameExpansion_V5）。水槽を広げた上で、残りの幅でルーレットが機能的に成立するレイアウトにする。狭ければ縦構成・折返し等で機能を保つ。

## 7. アーキテクチャ確定（v2・2026-07-18・パチンコ方式・着手前レイヤー確定 / fable0）

> **v2確定**: 旧§7（カオス/衝突方式）は撤回。v2は**パラメトリック軌道＋独立抽選**。着手前に本節でレイヤーを確定し、実装は本設計に従う（反復§6はこの構造内のチューニングのみ）。

### 7.1 レイヤー構成（軌道＝表現／抽選＝ルール の分離）
- **ルール層**（`js/roulette.js`・`Roulette`。決定論・単一シード窓口・node検証可・DOM非依存）:
  - **発射**: 「給餌1回＝球1発」。1回の給餌イベント（クランク1タップ or オート1ティック＝`feedAll`1回）で**1球だけ**emit（旧「個体ごとに1球」＝大量同時発射は撤回）。geneはコロニーの代表個体。
  - **抽選（各球独立）**: emit時に**その球の結果を確定**＝`b.rainbow = _rng() < CFG.roulRainbowChance`（基準0.5%）。衝突・密度で確率が変わる旧方式は撤回。抽選は**単一シード窓口経由**＝同一シード＋同一発射列＝同一結果。
  - **到達＝卵生成**: 球が軌道の最奥部（progress p=1）に達したら`onEgg({gene, rainbow})`（注入コールバック）で卵生成。`BallLanded`/`BallEnteredRainbow`イベント発行。
  - **軌道の進行（progress）**: 球は速度・重力を持たず、**経過時間`age`からeasingで進行`p`を算出**（`p = _progress(age)`）。減速（焦らし）はこのeasingに内包＝到達タイミングも決定論。ルールは`p`と`rainbow`のみ保持（座標は持たない）。
- **表現層**（`js/ui/screens/roulette.js`・`#roulette-canvas`。描画のみ）:
  - **軌道の座標写像**: ルールの`b.p`（0→1）を軌道パス（左下発射→左上へ上昇→頂部でアーク→最奥部へ落下）へ写像して描くだけ。**結果は計算しない**。
  - **焦らしの見せ場**: 落下終盤（p後半）はeasingで遅くなる。最後の区間で球が**当たり穴（レインボー）or 通常スロット**へドリフト（`b.rainbow`を読んで最終approachのみ分岐＝それまでは中央中立で「入るか?」の緊張）。
  - **ジュース**: `BallEnteredRainbow`購読で七色バースト。魂のメインCanvasは非接触。

### 7.2 決定論の窓口（fable2準拠・旧基盤を流用）
- **単一シードPRNG**（mulberry32）を流用。抽選・軌道の微小ばらつきは全てこの窓口経由。`Math.random`をシム内で呼ばない（`reset`のデフォルトシード選択のみ）。
- **フレーム非依存**: `advance(dt)`で各球の`age += dt`、`p = _progress(age)`。同一シード＋同一発射列＝同一結果（node検証）。固定タイムステップは物理積分が無いv2では不要（`p`はageの純関数）。
- **セーブ非依存**: 飛行中の球はtransient（非保存）。生まれた卵のみ既存`state.eggs`に入る（スキーマ変更なし）。**fable2: 卵に未使用の来歴フラグを載せない**（前回除去済み。§4.3特別孵化を作る時に消費される原データとして再追加）。

### 7.3 確率＝独立抽選（式で作る・創発ではない）
- v2は**各球0.5%の独立試行**（旧「物理の創発」は撤回）。`_rng() < CFG.roulRainbowChance`。
- 落下の減速（演出）と抽選（0.5%）は**分離**するが、体感として「ゆっくり近づく→当たり穴に入る/外れる」が確率の瞬間と重なるよう、**結果はemit時に確定・視覚は最終approachで公開**（スクラッチカード式＝見た目と真実は常に一致＝fable1のズレなし）。

### 7.4 確率の保証（§6.1-4）
- **モンテカルロ**: 多数回発射し経験的レインボー率が`roulRainbowChance`（0.5%＝1/200）付近に収束することを実測。決定論なのでレート信頼可。
- CFG: `roulRainbowChance`（0.005）／`roulTravelSec`（総旅程秒）／easing係数（減速カーブ）／軌道形状（発射点・頂部・最奥部・当たり穴x幅）／連続発射の球数上限・fps。全CFG化・到達値はHANDOFF。

### 7.5 旧コードの扱い（YAGNI）
- 撤去: 重力積分・球衝突（`_collideBalls`）・壁反射・床回収・カオス創発ロジック（v2で不要）。
- 流用: 単一シードPRNG窓口・emit/advance/events/onEggの骨格・卵接続（spawnRouletteEgg）・レインボー演出。

### 7.6 §6.1-2 の扱い（v2整合）
- §6.1-2「カオスが意味を持つ（衝突が増えてレインボー率上昇）」は**v2で撤回**（独立抽選のため密度でレインボー率は変わらない）。v2の対応ゴール＝**「焦らしのジュース」**（落下減速で入るか外れるかの緊張・§6.1-3と一体）。§6.1-2はv2では「発射リズムが心地よい・軌道が自然・大量連続でも破綻しない」に読み替える。
