## 2. 規律の柱

1. **初回は無音スタート**(既定 `soundOn:false`)。設定でON・状態はセーブ(dial系の器)。ONへの導線は一度だけ静かに知らせる(押し売りしない)。
   技術的裏付け: ブラウザのautoplay policyによりユーザー操作前のAudioContextは動かない=「初回から鳴らす」は技術的にも不成立。
2. **音は情報の唯一の担い手にならない**。全ての音イベントは既存の視覚表示(§9「見ればいつでも分かる」)と対で、音を切っても体験が成立する。
3. **発音は単一窓口 `Sound.play(id)`**。AudioContext直叩きの散在禁止。演出層はイベント購読で鳴らす(ルール層に音コードを置かない)。
4. **同時再生の間引き**: 同一SEの最小間隔・同時発音上限(ボイスプール)・連打時は音量減衰。優先度表(石の生成>ボス撃破>孵化>繁殖>給餌)。
5. **CFG外部化**: soundOn / master・系統別音量(BGM/SE/環境) / 各音の波形・周波数・尺・間引き閾値。数値は全て★Ric実機調整。
6. **決定論とテスト**: 発音ログで「給餌1回=feed音1回」「連打10回=≦N回」を装置QA検査。波形はOfflineAudioContextレンダリングのRMS/ピーク/尺を数値ゲート。乱数は決定論バケット。
7. **1操作1音**。UI開閉・ホバーに音を付けない。頻発アクションほど短く小さく、核となる瞬間(石の生成・ボス撃破)に音予算を集中。
8. **新規音は本書の対象表(§4)へ追記してから実装**(UISkillsと同じ作法)。

## 3-2. 音づくりの基礎知識(実測で確立・2026-08-11 S1・Ric指示で明記)

新しい音を作る前に必ず読むこと。**S1で「撃破が給餌より小さい」という設計ミスを数値ゲートが捕まえた**ときに確立した知識で、耳で気づく前に数字で捕まえるための前提になる。

1. **フィルタを掛けた音に `peak = vol × master × 系統音量` は成り立たない。**
   ローパス等のフィルタは通過帯域外のエネルギーを削るため、**`vol` の額面どおりには鳴らない**。実例: `defeat`(白色ノイズ+ローパス800Hz・vol0.50)の実測 peak は 0.126 で、額面 0.25 の半分だった。
   → フィルタ付きの音の検査は「=」ではなく**上限**(`peak ≤ vol×master×系統`)で縛る。音量を決めるときは **CFGの数値ではなく実測値**を見る。
2. **音の重さの物差しは RMS ではなく peak。**
   RMS はバッファ全体の平均なので、**余韻の長い音ほど静寂で薄まる**。尺の違う音どうしの重さ比較には使えない。peak は瞬間の当たりの強さで尺に依存しない。
   実例: 是正後の `defeat` は peak では最大(0.259)だが、余韻200msのぶん RMS では `hatch` を下回る。**§2-7「核となる瞬間に予算を集中」が守れているかは peak の序列で確認する。**
3. **基準音3種(給餌 `feed` / 孵化 `hatch` / 撃破 `defeat`)は 2026-08-11 にRic承認で確定した。以後の音は全てこの3種からの相対で設計する。**
   実測の基準値(master0.5・SE1.0時): peak = 給餌 **0.080** < 孵化 **0.150** < 撃破 **0.259** / 尺 = 110ms < 370ms < 390ms。

### 原則(確定): 場所ごと・惑星ごとの音の差は、**既存の真実から導出する**

✅ **確定(2026-08-27)**: 当初「S2で確立・Ric承認」→出所誤りの判明で【承認待ち】へ降格(2026-08-13)→**REL指示書§1が本原則を規律として明記し、REL-1判定=合格(2026-08-27)をもって憲章条項として確定**。

音のために新しい対応表を作らない。**その場所の性格を既に決めている実データ**(惑星なら `STAGES[].sky` の空色)から音のパラメータを導く。

- **なぜ**: ①同じ真実から視覚と聴覚が導かれるため、**惑星の性格が音と絵で必ず一致する**(暗く沈んだ空の惑星は、音も低くこもる) ②**二重定義が生まれない**(色を変えたら音も自動で追随する。片方だけ直し忘れる事故が原理的に起きない) ③10惑星ぶんの表を手で書かずに済む。
- **調整はCFGの範囲値で行う**(下限/上限/基準値)。個別惑星の値を直接いじらないため、**10惑星の関係(明暗・暖寒・高低)が崩れない**。「⑨だけ低くしたい」ではなく「暗い惑星をもっと低くしたい」と考える。
- S2の写像: 色相→パッドの音程 / 明度→風のこもり具合とオクターブ / 彩度→パッドの存在感。
- 例外を作るとき(ある場所だけ導出では表現できない)は、**本書に理由を書いてから**個別値を置く。

**S3で「惑星差」から「場所差」へ広げる(2026-08-13提案・2026-08-27 REL-1判定で承認)**。導出元は場所ごとに既に存在していた:

| 場所 | 導出元(既存の真実) | 値 | 出てくる性格 |
|---|---|---|---|
| 飼育槽 | `STAGES[].sky` | 惑星ごと | 惑星の空色そのまま(温かい生命) |
| 本部 | `CFG.holoPal.void` | `#04060a` | 色相220°=冷たい / 明度3%=低く沈む(冷たい計器) |
| 巣 | `NEST_VIS.palette.bg0` | `#2a1c0c` | 色相32°=暖かい / 明度11%=最も低い(籠もった安息) |

- **3場所とも同じ写像 `ambientFromTint()` を通す**。場所ごとの導出器を作らない。色を変えれば音も追随する。
- ★**差の無い場所に差を作らない**。本部とHOLO、巣ネットワークはどちらも**全惑星共通**なので、惑星による音の差を持たない。導出は「差」を作るための道具であり、差が存在しない軸に導出を持ち込むと、無い差を捏造して二重定義になる。
- ★**色から導けるのは「音程・こもり・存在感」まで。質感(構造)は導けない。** 温かい生命=風+パッド / 冷たい計器=ハム+tick / 籠もった安息=ディレイ+心拍 という**グラフの形の差**はコードが持つ。ここが§3-2の但し書きであり、色に無理をさせない境界。
- **場面の音も既存の真実から導出する。同じ真実を持つ音(影と本部ハム等)は同じ根を共有してよい——世界が一つであることの音訳。**(2026-08-27 Ric裁定・REL-2判定。実例: S4の影 mvShadow=87Hz と本部ハム=同じ `holoPal.void` の根)

### 場所の切替は差し替えでなく再構築(2026-08-27 Ric承認・REL-1)

**「場所の切替は差し替えでなく再構築——構造の違う音は沈黙の間に作り直す。切替は合体通知で中間音を挟まない。」**

- 同じ場所の中の切替(惑星の切替=同じグラフ構造)はパラメータ差し替えでよい。しかし**場所が変わるとグラフの構造ごと違う**(風+パッド / ハム+tick / ディレイ+心拍)ため差し替えでは足りず、沈み込み(`soundAmbFadeSec`・惑星移動と共有=聴こえ方は同一)の**無音の間に作り直す**。
- 画面遷移は「巣を閉じる→本部を開く」のように**中間状態を通る**。場所はDOMから導出するため、通知を次のタスクまで**合体**(`UI.placeChanged()`)してから1回だけ読めば、必ず最終的な場所だけが音になる=中間の飼育槽が一瞬立ち上がらない。

### ムービーの音の予算(REL-2・2026-08-27 Ric承認)

**「最重の音は常にプレイヤーの行為に紐づく(石=成果・撃破=勝利)。観る場面の音はそれを超えない。」**

- ムービー(オープニング/Lore)の音は**SE優先度表に載せない「場面の音」**。アクセントの最大peakは**撃破(0.259)を超えない**・石(0.507)に近づけない。持続層を置く場合は環境音の物差し(持続RMS・定常性・低域比率)に従う(S4実装は持続層なし=無音が基準・暗転=無音の溜め)。
- タイムライン従属: 同期の真実はムービー側のノード表(`CFG.holoOpenNodes`/`holoLoreNodes`)ただ一つ。**音側に時間表を作らない**(恒久テストが走査)。スキップは短い減衰で即無音(ハードカット=クリックの事故感を出さない)。reduced-motion は静止表示=音も一切鳴らさない。

### 常時鳴る音は「持続層」と「点の層」に分かれる(S3で確立・2026-08-27 REL-1判定で承認)

場所の音には、背景に敷かれ続けるもの(風・ハム・パッド=**持続層**)と、周期的に打たれるもの(本部のtick・巣の心拍=**点の層**)がある。**この2つは物差しが違い、混ぜて測ると疲れを隠す。**

- **定常性は持続層だけで測る**(点の層の音量を0にしてから測る)。tickがあるだけで定常性は当然悪化するので、混ぜたまま閾値を緩めると「ハムそのものが揺れて疲れる」を見逃す。
- **点の層はSEと同じく peak で測る**。ただし環境音である以上、SE最軽(給餌 0.080)を超えてはならない。
- 点の層の**周期も既存の真実から導く**。本部のtickは `CFG.holoGridSec`(0.4秒=HOLO起動シーケンスのグリッド)の倍数に乗る。
- 実測の基準値(master0.5・環境1.0): 本部 持続RMS **0.0078** / 定常性 **1.01** / 低域比率 **0.963** / peak 0.0177。巣 持続RMS **0.0089** / 定常性 **1.99** / 低域比率 **0.991** / peak 0.0257。**三者の籠もり序列 = 巣 0.991 > 本部 0.963 > 飼育槽 0.83〜0.91**。

### 立ち上がりは「疲れ」ではない(S3で確立・2026-08-27 REL-1判定で承認・計測器の改訂)

巣のフィードバックディレイは無音から反響が積み上がるまで時間が要り、その**一度きりの立ち上がり**が「耳につく揺れ」と同じ数字になった。1.2秒のフェードインの中に隠れており疲れの原因ではないので、`CFG.soundAmbSteadySkipSec`(1.0秒)で定常性の対象から外す。

- ★**窓の長さ(100ms)は変えていない**。速い揺れの検知能力を落とさないため。改訂後に**カナリアで再実証済み**(速く深い息づかい→3.94で検知)。
- ★飼育槽(S2実装ぶん・REL-0で追認)の数値は**この改訂で動かない**ことを実測で確認: 定常性 2.61/2.72 → **2.51/2.59**(閾値3.2に対して十分内側・持続RMS/peak/低域比率は完全に不変)。

### 効果音と環境音は、物差しが違う(S2で確立・2026-08-12)

同じ「音」でも、**一瞬の主張(SE)と常時鳴る背景(環境音)は測り方が正反対**になる。取り違えると、正しく作った音が落ちたり、疲れる音が通ったりする。

| | 効果音(SE) | 環境音(アンビエント) |
|---|---|---|
| 役割 | 一瞬の主張・出来事の合図 | 背景に沈む・場の空気 |
| 主な物差し | **peak**(尺に依存しない当たりの強さ) | **持続RMS**(実際の存在感) |
| 序列の確認 | peakの序列(核>中間>頻発) | SE最軽より**小さい**こと |
| 疲れの確認 | 不要(一瞬で終わる) | **定常性**=短窓RMSの max/min。立ち上がり・減衰・耳につく揺れが無いこと |
| 音色の確認 | 実測周波数(ゼロ交差) | **低域比率**(こもり具合) |
| peakの扱い | 主役 | **判定に使わない**(一瞬の尖りは背景の性質を表さない) |
| RMSの扱い | 使わない(余韻の長い音ほど薄まる) | 主役(常時鳴るので平均が実態) |

- **定常性の窓は短くする(100ms)**。★S2で 1秒窓にしていたとき、**わざと速く深く揺らしたカナリアが引っかからなかった**(窓内で平均されて見えない)。窓を短くして初めて、疲れの原因になる数Hzの変動が見える。**「観測できない計測は問題なしを偽造する」**の実例。
- 実測の基準値(master0.5・環境1.0時): 環境音 peak **0.022〜0.032**(SE最軽の給餌0.080より小さい)/ 持続RMS **0.0066〜0.0097** / 定常性 **2.6〜2.7**(速く深く揺らすと3.9まで悪化)/ 低域比率 **0.83〜0.91**。
- **常時鳴る音の設計原則**: 息づかい(ゆらぎ)は**周期10秒以上・浅く**。静止したノイズは扇風機のように疲れ、速い/深い揺らぎは「主張」になる。パッドは風より控えめに置き、**旋律を持たせない**(旋律はBGMであり、§3の「BGMらしいBGMを置かない」に反する)。

### 走査の原則: 「語の出現」ではなく「使用」を検査する

音の規律を守らせる恒久テストは、ソースを走査して違反を探す。ここで**素の語句一致は誤検知する**。S0でコメント(「Math.random 不使用」)を、S1で検分ページの表示文言("OfflineAudioContext 非対応")を、それぞれ違反と誤判定した。**2度の誤検知を経て、音の走査全体の原則として格上げする**:

- コメントは走査対象から除く(`codeOf()` で除去。文字列・正規表現リテラルは保持)。
- 「使う形」だけを違反とする(`new AudioContext` / `.createOscillator()` などの**生成・呼び出し形**)。**説明は使用ではない。**
- 誤検知したとき、**語を書き換えて通すのは偽の合格**。走査側を直す。
- 「無いことの検査」は必ず**カナリアで検知能力を先に実証**してから信用する(違反サンプルを捕まえられるか/正しい書き方を通すか)。

## 5. 不可逆性の判定と将来の制約(改定で固定されるもの)

## 6. 拡張条項((c)併用への道)
