# SoundSkills — 音の憲章(V6-P5)

> **状態: 承認済み(2026-08-11 Ric裁定・4点すべて承認)**。①技術方式=(b)WebAudio合成基盤+拡張条項 ②独立憲章(UISkillsと同格・fable1の下位) ③規律8項(初回無音の既定を含む) ④不可逆制約4点の受諾(§5)。
> **最重要の柱(Ric明記指示): 「音にしかない情報を作らない」**(§2-2) — 全ての音は§9の視覚表示と対であり、音を切っても体験が成立することの保証。

## 0. 位置づけ(階層)

  fable1 の「イベント購読・パラメータ外部化・手触り・同時多発の間引き」を音に適用した固有仕様が本書。競合時は本書(固有仕様)が正。

## 1. 技術方式: WebAudio合成を基盤(将来のファイル併用へ拡張可能な抽象化)

| 評価軸 | (a) 音声ファイル同梱 | (b) WebAudio合成 | (c) 併用 |
|---|---|---|---|
| 憲章整合(外部通信なし/ビルドなし) | ○ 同一オリジン配信なら整合(P2画像解禁の前例) | ◎ 追加ファイルゼロ・コードのみ | ○ |
| 表現の幅 | ◎ 楽曲・録音物・生楽器 | ○ 電子音/計器音/ドローン/ノイズ系SE/ベル・パッド。**生楽器の実在感・歌・録音物の質感は不可** | ◎ |
| 容量・読み込み | × BGM1曲2〜5MB×場面数。モバイル初期ロード増・遅延ロード必須 | ◎ 数KB(コード)・読み込み影響ゼロ | △ |

| 決定論・テスト | △ 再生トリガのみ検査可。波形検証は事実上不能 | ◎ OfflineAudioContextでレンダリング→RMS/ピーク周波数/尺を数値ゲート化。発音イベントはスパイ可能 | △ |

- **採用案: (b)を基盤**。ただし発音の単一窓口(§3)をソース非依存に設計し、**将来ファイル音源が必要になったら(c)へ拡張できる形**にする(拡張条項=§6)。
- 根拠: ①本作の音はHOLO機械音・環境音・電子SEが中心=合成の得意域と一致 ②ライセンスリスクゼロ ③数値ゲート(B2以来の作法)を音にも適用できる唯一の方式 ④容量ゼロ ⑤P2画像は「参照原画の再現」が目的でアセットが正解だったが、**音には正解素材が存在しない**=作りながらRic実機判定する既存プロセスに乗る。
- 合成の境界: 歌もの・生演奏の質感が要る演出が発生した時点で(c)拡張を裁定にかける。

## 2. 規律の柱

1. **初回は無音スタート**(既定 `soundOn:false`)。設定でON・状態はセーブ(dial系の器)。ONへの導線は一度だけ静かに知らせる(押し売りしない)。
   技術的裏付け: ブラウザのautoplay policyによりユーザー操作前のAudioContextは動かない=「初回から鳴らす」は技術的にも不成立。
2. **音は情報の唯一の担い手にならない**。全ての音イベントは既存の視覚表示(§9「見ればいつでも分かる」)と対で、音を切っても体験が成立する。
3. **発音は単一窓口 `Sound.play(id)`**。AudioContext直叩きの散在禁止。演出層はイベント購読で鳴らす(ルール層に音コードを置かない)。
4. **同時再生の間引き**: 同一SEの最小間隔・同時発音上限(ボイスプール)・連打時は音量減衰。優先度表(石の生成>ボス撃破>孵化>繁殖>給餌)。
5. **CFG外部化**: soundOn / master・系統別音量(BGM/SE/環境) / 各音の波形・周波数・尺・間引き閾値。数値は全て★Ric実機調整。
6. **決定論とテスト**: 発音ログで「給餌1回=feed音1回」「連打10回=≦N回」を装置QA検査。波形はOfflineAudioContextレンダリングのRMS/ピーク/尺を数値ゲート。乱数は決定論バケット。
7. **1操作1音**。UI開閉・ホバーに音を付けない。頻発アクションほど短く小さく、核となる瞬間(石の生成・ボス撃破)に音予算を集中。
8. **新規音は本書の対象表(§4)へ追記してから実装**(UISkillsと同じ作法)。

## 3-2. 音づくりの基礎知識(実測で確立・2026-08-11 S1・Ric指示で明記)

新しい音を作る前に必ず読むこと。**S1で「撃破が給餌より小さい」という設計ミスを数値ゲートが捕まえた**ときに確立した知識で、耳で気づく前に数字で捕まえるための前提になる。

1. **フィルタを掛けた音に `peak = vol × master × 系統音量` は成り立たない。**
   ローパス等のフィルタは通過帯域外のエネルギーを削るため、**`vol` の額面どおりには鳴らない**。実例: `defeat`(白色ノイズ+ローパス800Hz・vol0.50)の実測 peak は 0.126 で、額面 0.25 の半分だった。
   → フィルタ付きの音の検査は「=」ではなく**上限**(`peak ≤ vol×master×系統`)で縛る。音量を決めるときは **CFGの数値ではなく実測値**を見る。
2. **音の重さの物差しは RMS ではなく peak。**
   RMS はバッファ全体の平均なので、**余韻の長い音ほど静寂で薄まる**。尺の違う音どうしの重さ比較には使えない。peak は瞬間の当たりの強さで尺に依存しない。
   実例: 是正後の `defeat` は peak では最大(0.259)だが、余韻200msのぶん RMS では `hatch` を下回る。**§2-7「核となる瞬間に予算を集中」が守れているかは peak の序列で確認する。**
3. **基準音3種(給餌 `feed` / 孵化 `hatch` / 撃破 `defeat`)は 2026-08-11 にRic承認で確定した。以後の音は全てこの3種からの相対で設計する。**
   実測の基準値(master0.5・SE1.0時): peak = 給餌 **0.080** < 孵化 **0.150** < 撃破 **0.259** / 尺 = 110ms < 370ms < 390ms。

### 効果音と環境音は、物差しが違う(S2で確立・2026-08-12)

同じ「音」でも、**一瞬の主張(SE)と常時鳴る背景(環境音)は測り方が正反対**になる。取り違えると、正しく作った音が落ちたり、疲れる音が通ったりする。

| | 効果音(SE) | 環境音(アンビエント) |
|---|---|---|
| 役割 | 一瞬の主張・出来事の合図 | 背景に沈む・場の空気 |
| 主な物差し | **peak**(尺に依存しない当たりの強さ) | **持続RMS**(実際の存在感) |
| 序列の確認 | peakの序列(核>中間>頻発) | SE最軽より**小さい**こと |
| 疲れの確認 | 不要(一瞬で終わる) | **定常性**=短窓RMSの max/min。立ち上がり・減衰・耳につく揺れが無いこと |
| 音色の確認 | 実測周波数(ゼロ交差) | **低域比率**(こもり具合) |
| peakの扱い | 主役 | **判定に使わない**(一瞬の尖りは背景の性質を表さない) |
| RMSの扱い | 使わない(余韻の長い音ほど薄まる) | 主役(常時鳴るので平均が実態) |

- **定常性の窓は短くする(100ms)**。★S2で 1秒窓にしていたとき、**わざと速く深く揺らしたカナリアが引っかからなかった**(窓内で平均されて見えない)。窓を短くして初めて、疲れの原因になる数Hzの変動が見える。**「観測できない計測は問題なしを偽造する」**の実例。
- 実測の基準値(master0.5・環境1.0時): 環境音 peak **0.022〜0.032**(SE最軽の給餌0.080より小さい)/ 持続RMS **0.0066〜0.0097** / 定常性 **2.6〜2.7**(速く深く揺らすと3.9まで悪化)/ 低域比率 **0.83〜0.91**。
- **常時鳴る音の設計原則**: 息づかい(ゆらぎ)は**周期10秒以上・浅く**。静止したノイズは扇風機のように疲れ、速い/深い揺らぎは「主張」になる。パッドは風より控えめに置き、**旋律を持たせない**(旋律はBGMであり、§3の「BGMらしいBGMを置かない」に反する)。

### 走査の原則: 「語の出現」ではなく「使用」を検査する

音の規律を守らせる恒久テストは、ソースを走査して違反を探す。ここで**素の語句一致は誤検知する**。S0でコメント(「Math.random 不使用」)を、S1で検分ページの表示文言("OfflineAudioContext 非対応")を、それぞれ違反と誤判定した。**2度の誤検知を経て、音の走査全体の原則として格上げする**:

- コメントは走査対象から除く(`codeOf()` で除去。文字列・正規表現リテラルは保持)。
- 「使う形」だけを違反とする(`new AudioContext` / `.createOscillator()` などの**生成・呼び出し形**)。**説明は使用ではない。**
- 誤検知したとき、**語を書き換えて通すのは偽の合格**。走査側を直す。
- 「無いことの検査」は必ず**カナリアで検知能力を先に実証**してから信用する(違反サンプルを捕まえられるか/正しい書き方を通すか)。

## 4. 効果音の対象表(初期・追加はここへ追記してから)

## 5. 不可逆性の判定と将来の制約(改定で固定されるもの)

- 音の**導入自体**は準可逆(soundOn既定false=実質可逆)。
- 本改定で将来固定される制約: ①音必須のゲームプレイを作れない(§2-2) ②発音はSound窓口+CFG経由のみ(§2-3,5) ③音声ファイル追加は§6の拡張条項による再裁定が必要 ④初回無音の既定を覆すには裁定が必要。

## 6. 拡張条項((c)併用への道)

ファイル音源が必要と判断された場合: Sound窓口のソース層(合成/ファイル)差し替えで対応し、ライセンス台帳(`docs/sound_licenses.md`)の新設・容量予算・遅延ロード設計をセットで裁定にかける。本条項があることで、その時の改定は「台帳と予算の追加」だけで済む。

- **S0 完了**(2026-08-11): 単一窓口 `Sound.play(id)`・CFG外部化・OfflineAudioContextの数値ゲート。
- **S1 完了・Ric承認**(2026-08-11): 基準音3種の確定(§3-2)+検分ページ `?tune=1#sound`+ゲームへの配線。
- **S2 たたき台**(2026-08-12・Ric実機判定待ち): 飼育槽の環境音。風ノイズ(決定論)+惑星tint連動の微パッド、BGMは置かない。**惑星差は `STAGES[].sky` から導出**(色は既に惑星ごとの真実=音のために別表を作らない。色相→音程 / 明度→こもり具合とオクターブ / 彩度→パッドの存在感)。調整は個別惑星ではなくCFGの**範囲値**で行い、10惑星の関係を崩さない。惑星切替は**いったん無音へ下げてから差し替えて戻す**(周波数を鳴らしたまま動かすとポルタメント、瞬時差し替えはクリック。走査ビームの視覚トランジションとも合う)。
