# stage_skills.md — 惑星背景制作憲章

- 版: 1.0（2026-07-20・Phase 5 本格実装スプリントで新設）
- 位置づけ: **惑星背景を制作する全作業が従う単一の作法。** `UISkills.md`／`crank.md` を継承し、背景固有の指針をここへ集約する。以後の背景制作はまず本ファイルを読み、無い作法は追記してから使う。
- 対象: `js/render.js` の `paintBackground`／`paintDeco`／`draw()` の背景層。

---

## 0. 設計思想 — ポップ × 意味深さ（最重要・全惑星共通）

**「ポップさ」と「暗に示す意味深さ」をバランス良く織り交ぜる。**

- **ポップ**: 一目で親しみやすく、可愛らしく、彩りがある。シルエット・色・形で「わかりやすく良い眺め」。
- **意味深さ**: 細部に、説明されない意味が潜んでいる。crank.md の作法「**気配だけ見せて説明しない**」——玄室の金、モノリスのグリフ、賢者の石の「これは何だ？」という問い。
- **問いを与え、答えは書かない。** 世界の奥行きは明示でなく暗示で。envText も断定しない（一行の気配のみ）。
- **背景とクランクは1つの文明。** crank.md §3.4 の割り当て（世界観×機構×素材×物理挙動）が各惑星背景の設計源。その文明が**何を作り、何を失ったか**が背景から伝わること。

> 判断基準: 「一目で良い眺めと感じ、しかし細部で"これは何だろう"と二度見するか」。二度見させたら成功。ただし説明はしない。

## 1. 層構成（`paintBackground` の描画順）

空(グラデ) → 光源(太陽/炉光/粉塵) → 遠景稜線2層(`ridge`) → 地面グラデ → 色ムラ → 環境光 → 土ノイズ → 小石 → 大岩 → **ステージ固有 deco(`paintDeco` の `st.id` 分岐)**。

- **遠景** = 文明の輪郭（シルエットで語る・稜線/スカイライン/墳丘）。
- **中景** = 文明の遺物（**意味の核**。モノリス/原子炉群/御神体/王墓）。ここに謎を凝縮。
- **近景** = 大地の質感（小石・岩・草・雪・水）。ポップの手触り。

---

## 2. 性能（常時描画ゆえ最重要）

- **背景は `Render._bgCache`（オフスクリーン）にキャッシュ**され、stage 切替時のみ `paintBackground` が走る。→ **静的 detail は実質無料**（毎フレームは 1 回の `drawImage` のみ）。detail は惜しまず盛ってよい。
- **重要な落とし穴**: `paintBackground` 内で `this.time` を使っても**動かない**（キャッシュ時の値で凍結される）。**動かしたい背景要素は `draw()` に別関数を作り、`st.id` ゲート＋`this.time` で毎フレーム描く**（既存 `drawMonolith8`／`drawBugSweep` が手本）。
- **毎フレーム描画は最小限**。60fps 維持を**毎惑星で実測**（`scratchpad` の puppeteer で 1.5s 計測）。低下したら層数・粒子を減らし、原因を HANDOFF に記録。
- 毎フレームの粒子ループ・大量 `createRadialGradient` は主犯。動的層は「1〜3 要素の微動」に絞る。
- 静的 deco の乱数は `lcg(st.id * 素数)` の決定論 rand を使う（`paintBackground` が受け取る `rand`）。毎回同じ絵＝キャッシュと整合。

## 3. パレット

- ベース土壌トークン（`--ink-*`／`--sand-*`）＋**惑星アクセント**（UISkills §1.5）。Neo-Terrarium（魂はレトロ・額縁はモダン）に収める。奇抜さで浮かせない。
- **ポップの彩り**はアクセント色・空・光源で出す。**意味深さの核**は低彩度・沈んだ色で"気配"に留める（明るく主張させない）。
- 各惑星アクセント（確定・UISkills §1.5）: 砂漠=砂金/草原=若草/密林=翡翠#2FA98A/古代古墳=苔緑/火山=熔岩#E0533B/氷の前線=氷水#7FC7DE/廃原子炉=チェレンコフ#6FB8A0/水中都市=深海光#5FA8C9/遺跡=黄昏金/摩天楼=ネオン#D957B0。

---

## 4. 密度（ポップ×意味深さの配分）

- **一目の親しみ** = シルエット・彩り・可愛い形（多め・散らす）。
- **奥行き** = **中景の遺物 1〜3 個に意味を凝縮**（散らしすぎない）。「1 つの謎の核 ＋ それを補強する 2〜3 の小片」。核を 1 つに絞ると効く。
- 意味の核は**精度・異質さ**で語る（例: 非トカゲ的な完璧な直立/等間隔グリフ/風化との精度差）。周囲の風化・埋没・欠けと対比させると「これは何だ」が立つ。

---

## 5. reduced-motion / fx0

- 動きのある背景要素は `prefers-reduced-motion`（`Motion.reduced`）と dial の `fx0` で**静的化**（機能・見栄えは保つ）。静止時も「作り込みの密度」は残る（動的層は最後の一筆に留め、静止で成立する構図にする）。

---

## 6. CFG / トークン化

- 各惑星の背景パラメータ（遺物の位置・数・強度・周期・密度）は **CFG 化**（帰還後に実機で手触り調整可能に）。マジックナンバーを散らさない。
- 色はトークン／惑星アクセント追従。絵文字禁止（自作 canvas 描画）。

---

## 7. 不可侵の制約

- **魂は不変**: トカゲ・大地の起伏・飼育槽内の描画には触れない。背景層のみ本格化。
- **セーブ非接触**: 背景は描画のみ・additive。Game 状態は読み取り専用。
- 1 画面固定（スクロールなし）・全解像度であふれ 0・当たり判定のズレなし。
- 各コミットで **#spin-proof 全10惑星 PASS・純血回帰 PASS・console エラー 0** を確認。

---

## 8. 制作手順（1 惑星 = 1 小コミット＋push）

1. crank.md §3.4 でその惑星の世界観×機構×素材×失ったものを確認。
2. 「謎の核 1 つ＋補強 2〜3」を決める（何を暗示するか）。
3. 静的 detail を `paintDeco` へ（キャッシュ＝無料）。動かすなら `draw()` に別関数＋stageゲート＋reduced-motion。
4. fps 実測・スクショ保存・#spin-proof/純度/console 確認 → HANDOFF に「何を表現し・どこに意味を潜ませたか」を記録 → commit＋push。
