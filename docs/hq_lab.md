# 本部＝研究施設 設計書 v1.0（新設）

> **Ric構想**：本部を**モーダル・文字ベース**から、**独立したページ**へ移行する。
> 単なる情報画面ではなく、**設備のように強化（発達）していく研究施設**とし、**研究室チックな空間**として描く。
> 最初は**白タイルだけの空の部屋**。育てるほど設備が増え、研究施設になっていく。

---

## 1. コンセプト

- **「数字を見る画面」から「研究する場所」へ。**
- 飼育槽が「生き物を眺める場所」なら、本部は「**その生命を研究する場所**」。二つの場所を持つゲームになる。
- **育つ空間**：Phase 8（設備の成長表現）と同じ思想。レベルで**見た目ごと発達**する。プレイヤーの達成が景色として残る。
- **最初は白タイルのみ**（何もない実験室）→ パソコンデスク群・実験用水槽・ロケット…と埋まっていく。

---

## 2. 【重要】立体的な描写について

Ric要望：**今までの表現に無いような立体的な描写**。

- 飼育槽は**横から見た平面（サイドビュー）**。本部を同じ描き方にすると、既視感が出て「別の場所」に感じられない。
- → **提案：アイソメトリック（斜め見下ろし）で描く。**
  - 床の白タイルが**菱形のグリッド**として奥へ続き、机・水槽・ロケットが**箱として立体的に立つ**。
  - 飼育槽（サイドビュー）と**明確に異なる視覚言語**になり、「別の場所に来た」が成立する。
  - Canvas 2D で実現可能（3Dエンジン不要）。奥行きは**描画順（奥→手前）**で担保。
- ※この方式で進めてよいか、**Ric承認**を得ること。別案（クォータービュー／正面パース）があれば提案可。

## 3. 画面構成

- **独立ページ**（モーダルではない）。飼育槽と同様に**1画面固定・スクロールなし**。
- **行き来の導線**：トップバーの「本部」から入り、明確な戻り導線で飼育槽へ帰る。**どちらの場所にいるか**が一目で分かること。
- 飼育槽と同じく、**画面が主役・UIは控えめ**（UISkills）。設備の説明文で埋め尽くさない。
- 既存モーダルの機能は**1つも失わない**（§6の棚卸しを必須とする）。

## 4. 設備（研究施設のtier成長）

> Phase 8 と同じ方式：`facTier(lv, thresholds)` による**3〜4段階のtier**で、レベルが上がると**姿ごと発達**する。定位置は維持。

| 設備 | 役割 | 成長の方向（案） |
|---|---|---|
| **白タイルの床** | 施設の土台 | 素の白タイル → 継ぎ目の整った床 → 配線ダクト・ライン引き → 磨かれた床＋間接照明 |
| **パソコンデスク群** | **研究＝特性レシピの解読**・合成の成功率/コスト改善 | 机1つ＋端末1台 → 3台の島 → 多面モニタの解析卓 → サーバーラック併設の研究室 |
| **実験用水槽** | **特性の合成（トランスミュート）を行う場所** | 小さなガラス水槽 → 培養槽＋配管 → 錬成槽（深紅の光が差す） → 複数槽の実験区画 |
| **ロケット** | 既存のクリア目標（`rocket.done`） | 部品 → 骨組み → 機体 → 完成（発射可能） |
| **標本棚／記録** | 特性コンプ率・記録の閲覧 | 棚1つ → 標本瓶の列 → 資料棚＋星図 → 記録の間 |

- **設備は「置物」ではない**（Phase 8 §8.5）：**トカゲがそこで何をするか**を織り込む。研究施設にも**研究員として働くトカゲ**がいてよい（水槽を覗く／端末の前にいる／棚を整理する）。※実装は後段。
- **既存のHQ Lv** との関係を整理すること（HQ Lv がそのまま施設全体のtierになるのか、設備ごとに個別Lvを持つのか＝§7判断）。

## 5. 特性システムとの連携

- **実験用水槽 ＝ 合成の場**（`trait_system.md` §4）。素材個体を選び、賢者の石を触媒に上位特性を錬成する。
- **パソコンデスク群 ＝ 研究**。育てるほど**レシピが解読される**／成功率・石コストが改善（CFG）。
- **標本棚 ＝ 特性図鑑**（コンプ率）。既存の図鑑（種）とは別軸。
- → **本部を育てる動機**が「数字が増える」ではなく「**個性の錬成が進む**」になる。

## 6. 【必須】移行前の棚卸し

現在の本部モーダルが持つ**全機能を列挙**し、新ページでの行き先を1つずつ定めること。

- 各項目について：**新ページのどこに置くか／統合するか／撤廃するか**を提案し、承認を得てから移行。
- **機能が黙って消えないこと**（Phase 9 の通知棚卸しと同じ手順）。
- HQ Lv・強化・その他の数値が、移行後も**同じ意味で機能する**こと。

## 7. Ric判断待ちの一覧

1. **描画方式**：アイソメトリック（推奨）でよいか（§2）

5. **既存モーダル機能の行き先**（§6の棚卸し結果を見て判断）

## 8. 制約（厳守）

- **既存機能を失わない**（§6）。**セーブ資産を壊さない**（本部の既存Lv・進捗を保全。セーブに触るなら退避＋冪等＋承認先行）。
- **確率・物理・純血・魂は不変。**
- **1画面固定**・全解像度であふれ0・当たり判定のズレなし・consoleエラー0・fps実測・reduced-motion対応。
- **全CFG/トークン化**（手触りはRicが実機で調整）。
- **1設備ずつ実装＋スクショ実証**（一度に全部作らない）。
- fable群・UISkills・stage_skills.md の作法に準拠。新しいUIトークンが要るなら**先にUISkillsへ追記**してから実装。
