## Phase 0 — 表記バグの掃討【最優先・ライブ不具合】

**現象（添付1）**: 卵スロットの系統名の後ろに `<svg class="icon" aria-hidden="true"><use href="#i-spark"/></svg>` が**文字列としてそのまま表示**されている（「コモドドラゴン系 <svg ...>」）。

- **原因の型**: SVGアイコンを差し込むべき箇所が、`textContent`/エスケープ経路で挿入され、SVGがHTMLとして解釈されず文字列表示になっている（アイコン一括SVG化 §9 の取りこぼし）。
- **1箇所だけ直さない**: 同じ型（SVG文字列がエスケープ表示される／`Icon.svg()` の戻り値が textContent に入っている等）を**全画面・全モジュールで洗い出して**まとめて潰す。grep で `<svg`・`Icon.svg`・`i-spark` 等の挿入経路を確認し、innerHTML経路に統一 or 適切なDOM生成へ。
- **対象例**: 卵スロット（系統名＋孵化アイコン）、その他アイコンを動的に名前へ連結している箇所すべて。
- **テスト**: 卵スロットの系統名にSVGタグ文字列が出ない（アイコンが図として出る）／同型の他箇所も出ない／grepでエスケープされたSVG文字列の残存ゼロ。
- **完了条件**: SVGタグが文字列表示される箇所がゼロ。**これを直してから他Phaseへ。**

## Phase 1 — 給餌クランクの集約（最重要・画面圧迫の解消）

**現状（添付2）**: クランクの脇に「オート」トグル＋「コオロギ自動補給」トグル＋「低/中/高」が横に並び、**幅が広く存在感が強い**。文字表記も多い。

> **設計の芯**: 機能は減らさず、**表記を削り、クランク本体の操作に寄せる**。理想は「**クランクのボタン1個＋横に縦2段のトグル＋目立たない補給ボタン**」で、さらに突き詰めると「**レバーを引く方向でモードを変える**」ことで文字と小中高タブを消し、最大UXにする。

### 1.1 レイアウトの集約

- **クランク本体を主役に、大きくする**（アイコンのみ路線に絞るなら拡大可）。餌やりの主操作なので、押しやすく・目立ってよい。
- **小/中/高（レート）は縦に展開**してタブの横幅を削る（現在の横並びをやめる）。
- **オート／コオロギ自動補給のトグルは、クランク横に縦2段**で配置。
- **コオロギ自動補給（非表示/補給）ボタンは目立たなく**（主張を抑えた小さな副次トグル）。
- 全体として「クランク1個＋横に縦トグル」の**コンパクトな塊**にし、飼育槽への圧迫を減らす。

### 1.2 レバー方向でモード切替（最大UXの本命）

- **小中高の文字タブ・レートの文字表記を極力なくし、「レバーを引く方向／引き具合でモード（レート）を変える」操作に置換**する。
  - 例: クランクのレバーを上下（または左右）に引く位置で 低→中→高 が決まる。位置そのものが現在レートを示すので、文字ラベルが不要になる。
  - 直感的に「どの段か」が**レバーの位置で分かる**ようにする（目盛りは最小限の視覚表現で、文字を減らす）。
- これにより、画面上の文字要素を大幅削減し、クランク1個の操作系に集約する。

### 1.3 給餌の操作（タップ・長押し・オート）

- **タップ（クリック）**: 1掴み給餌（現行どおり）。
- **長押し**: 押している間**連続給餌**できるようにする（＝旧・長押し一括餌やりの操作感を復活）。
- **オート**: レバー位置（低/中/高）に応じて自動給餌。**回転速度をレートに同期**（下記1.4）。
- **オート中にタップ**: レバー（クランク）が**ばねで回転する演出**を返す（触ると反応する気持ちよさ）。

### 1.4 回転速度＝給餌速度の同期（体感の要）

- **オートの回転速度を、給餌頻度（低/中/高）に合わせる**。低はゆっくり、高はかなり速く回り、「高＝勢いよく給餌されている」イメージをユーザーに与える。
- **「高」の給餌速度は、旧・長押し一括餌やりの速度まで引き上げる**。
- **重要な等価関係**: 「オートの高」＝「長押し」＝同スピード（オート解除時の長押しも同等）。
  - 狙い: **長押しの手間を省くためにプレイヤーが"オート高"を選ぶ**、という自然な誘導。長押しとオート高が同速だと分かれば、放置派はオート高でストレスなく回せる。

### 1.5 維持する原則

- 給餌の効果ロジックは不変（既存処理の再利用）。
- コオロギ自動補給ON＝Goldがある限り永続（現行維持）。
- 平常は静か（オートの回転は§1.4のレート同期の範囲で。トースト等は出さない）。
- アクセシビリティ: レバー操作はクリック/キーボードでも段階変更でき、ドラッグ必須にしない。reduced-motionで回転演出は止め機能維持。

### 1.6 テスト／完了条件

- **テスト**: クランク周辺の文字表記・横幅が削減され圧迫が減った／レバー位置でレートが変わり文字タブが消えた/最小化された／タップ=1掴み・長押し=連続・オート=レート同期回転／オート高＝長押し＝同スピード／オート中タップでばね回転演出／コオロギ補給ボタンが目立たず機能する／reduced-motion・キーボード対応。
- **完了条件**: クランク1個の操作系に集約され、画面圧迫が明確に減り、かつ手動/連続/オート/Gold永続の全運用が維持されている。**「クランクボタンのみで全機能を賄える」が成立。**

## Phase 2 — 蛇ボスの粗さ取り・サイズ調整

**現状（添付3）**: T5級の蛇ボスが**巨大すぎる**（画面を専有し、頭がフィールド外へ）。加えて**デザインが稚拙で、拡大により粗さ（ジャギー・単調な塗り）が目立つ**。

- **サイズを下げる**: 現行 T5≒1.75倍は過大。**威圧感は保ちつつ画面に収まる比率へ**（目安: 基本×1.25＋ティア係数を縮小し、T5でも頭・目・上半身が画面内に収まる程度）。「見上げる大きさ」であって「画面を潰す大きさ」にしない。実際の上限は、フィールド内に主要部が収まることを基準に調整。
- **粗さを取る**: 拡大で目立つ粗さ（輪郭のジャギー、単調な塗り、のっぺり感）を改善する。ボスの描画（レンダラ）は手を入れてよい（トカゲ・大地・飼育槽の魂は不変）。
  - 塗りに陰影/グラデーション、輪郭の締まり、鱗や質感のディテール、目の造形の強化など、**拡大に耐える描き込み**にする。「稚拙」の印象を脱する。
- **脅威感は維持**: サイズを下げても、登場テレグラフ・呼吸・威嚇・Enrage・映画的HPバーで脅威は担保されるので、サイズ縮小で怖さが減る心配はない（むしろ全体像が見える方が造形の脅威が伝わる）。
- **テスト**: T5ボスの主要部が各画面幅でフィールド内に収まる／拡大しても粗さが目立たない／脅威感が保たれる／戦闘ロジック（HP・当たり判定・迎撃・Enrage）不変／トカゲ・大地は不変。
- **完了条件**: ボスが「画面を潰さず、見上げる威圧感があり、粗くない」状態になる。

## Phase 3 — 味方（ミーアキャット等）の描画改善

**現状（添付4）**: 味方ミーアキャットの描画が**稚拙**（造形が粗く、生き物としての魅力が薄い）。

- 味方の描画品質を、**トカゲ（魂）と同等の水準**へ引き上げる。味方はフィールドに常駐し観賞要素でもあるので、粗いと全体の質感を下げる。
- ミーアキャットを筆頭に、稚拙さが目立つ味方から順に**造形・塗り・ディテール**を改善（立ち姿・見張りポーズ・質感）。
- **線引き**: 味方はトカゲそのものではないが「フィールドの生き物」であり、品質基準はトカゲに揃える。味方の描画改善は可。トカゲ本体・大地・飼育槽の描画は不変。
- **テスト**: ミーアキャット等の味方が魅力的な生き物として描かれる／各味方の識別性が保たれる／トカゲ・大地は不変。
- **完了条件**: 味方が「稚拙」の印象を脱し、フィールドの生き物として自然に馴染む。

## 安全制約（全Phase共通）

1. **一括置換の前に必ずgrepで件数確認。** 関数エントリポイント（openXxx等）を巻き込む置換は禁止。想定より多ければ分割。
2. **1機能=小コミット（200〜400行目安）**、各コミット後に回帰スクショ＋ロジックテスト。
3. 破壊的変更の前にバックアップ。崩れは即ロールバック。
4. 数値・色・時間・**サイズ/回転速度**はハードコードせず設定定義（トークン/CFG）へ集約（後から即調整できるように）。
5. **確定した値は次の作業に移る前にコミット**（撮影用の一時変更と混在させない・前回のガラス縁教訓）。
6. **視覚要素は実機で目視確認**（機械テストをすり抜ける／前回の教訓）。
7. コンテキストが肥大したら /clear（HANDOFF/CLAUDEに記録あり）。

## 禁止事項

- **トカゲ・大地・飼育槽の描画（魂）には触れない。** ボス・味方の描画は品質改善のため可。
- **クランクの機能を減らさない。** 集約は"表記を削り操作に寄せる"であって機能削減ではない。
- **給餌の効果ロジックを変えない。** 既存処理を再利用。
- **平常画面を賑やかにしすぎない。**
- **Phase 0（表記バグ）完了前に他Phaseへ進まない。**
- UISkillsに無いスタイルを場当たりで足さない（先に追記）。
- 各Phaseの節目でスクショと完了条件チェックをHANDOFFに残す。
