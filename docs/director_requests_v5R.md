## 0. 共通規律(全アークに適用)

- 安全境界: セーブ資産・確率・物理・純血・魂の聖域は従来通り。確率に触るもの(R2/R5-a)は
  `roulette_rules.md §4` 流のMC実測を必須とする。
- 資産は消さず: 撤廃・置換時はバックアップ退避/git記録/払い戻し設計(該当時)。
- 全CFG化: 手触り数値はCCが推測で確定しない。
- QAゲート3層+boot console0+同乗デプロイ禁止規律(HANDOFF記載)を全アークで適用。
- 各アークの節目は「設計/モック → Ric承認 → 本実装 → Ric承認 → デプロイ」。

## 実施順序(推奨)

1. **R4** 本部復元(不合格状態の解消を最優先・復元自体は速い)
2. **R3 → R2** アメジスト新設→ルーレット報酬改定(経済アーク・R2はR3に依存)
3. **R1** 繁殖UI刷新+クイック繁殖
4. **R5** 特性システム見直し(最重量のアート+確率アーク・最後)

## R1. 繁殖UIの刷新 — 左メニュー化・種別ピッカー・クイック繁殖

### R1-1 繁殖ボタンの左メニュー追加
- 左メニューに「繁殖」ボタンを追加する。
- **厳守**: 下部の四重スリット実験の位置・既存レイアウトを一切崩さない。
  追加前後のレイアウト差分スクショで不変を証明すること。

### R1-2 新・繁殖モーダル(種別ピッカー)
- 繁殖ボタン → 展開モーダル。個体リストの全数表示を廃し、**種別のみをタイル表示**する
  (画面を大幅にすっきりさせるのが目的)。
- 選択フロー:
  1. 種タイルをクリック → その個体に「A」マークが付き、左下のAスロット(モーダル)に姿を表示。
  2. 次はB選択の待機状態になる。
  3. **同種2匹以上**なら、A選択後もその種タイルは選択可能のまま(同種掛け合わせを許容)。
     **同種1匹のみ**なら、A選択後にその種タイルはグレーアウト。
- 種タイル選択時にどの個体を使うか: **希少スコア(R1-3)最高の個体を自動選出**し、
  A/Bスロットに個体の姿+特性チップ+固定印(S3③の資産)を表示。
  スロット内の ◀▶ で同種内の個体を切替可能(すっきりさと個体選択の両立)。
- 確定・実行・CD等の繁殖ロジックは完全不変(表示とピッカー構造のみの刷新)。

### R1-3 クイック繁殖
- モーダル内に「クイック繁殖」ボタンを追加。押すと**最も希少性の高い子に到達し得る
  掛け合わせ**をA/Bに自動選出する(選出のみ。実行はRicの確定ボタン)。
- 希少スコアの定義(レア度システムは撤廃済のため、図鑑と特性から逆算):
  優先度順に (1)図鑑未登録エントリへ到達し得る組 (2)合成レシピ成立(2枚持ち)へ寄与する組
  (3)コロニー内保有数が少ない特性を持つ組 (4)固定印持ち。
  **CCは実装前にスコア式の具体(重み・同点処理)を提案し承認を得ること。** 重みは全CFG化。
- スコアは決定論(同じコロニー状態なら同じ選出)。乱数を使わない。

### 承認ゲート
- 静的モック(タイル表示/A・Bスロット/グレーアウト/クイックボタン) → Ric承認 → 本実装。

## R2. 遺伝子ルーレット報酬改定 — 卵の撤廃・鉱物報酬へ

### 背景(Ric裁定)
ルーレットの卵報酬が卵の供給過多を招いているため撤廃する。

### R2-0 【実装前必須】獲得可能性の事前監査
- 卵報酬の撤廃により、図鑑の個体(モーフ/虹含む)の獲得経路が塞がるものが無いか、
  `tools/audit_obtainability.js` を拡張して全数監査する。
- **「コード上存在するのに獲得できない」が1件でも生じる設計は実装禁止**。
  塞がる獲得物が見つかった場合は、その獲得経路の移譲先(例: ボス報酬卵)を設計して
  Ric承認を得てから実装に入る。

### R2-1 報酬の新体系
- 通常ルーレット: 卵の球 → **ダイヤのマークの球体**が転がる。虹ポケットに入ると**アメジスト**。
- **エリートボス(大ボス)撃破時**: **アメジストの球体**が転がり、虹ポケットに入ると**賢者の石**。
- 球体の数はボスの強さに連動して変動(スケール式はCFG・たたき台をCCが提案し承認)。
- **物理・確率は聖域**: 球の挙動・盤面・虹ポケット確率は一切変更しない(景品テーブルの
  差し替えのみ)。変更後にMC実測で (a)新報酬の全種到達 (b)確率分布の不変 を証明する。
- `roulette_prize_regression.js` を新報酬体系へ更新(純血監視は継続)。

### 承認ゲート
- R2-0監査報告+球数スケール式の提案 → Ric承認 → 実装 → MC実測報告 → デプロイ承認。

## R3. アメジスト資源の新設(R2の前提)

- トップバーの**賢者の石の左**にアメジストを追加。**ダイヤの上位アイテム**の位置づけ。
- 序列の視覚言語: ダイヤ < アメジスト < 賢者の石 が並びと意匠で読めること。
  アイコンは既存の形クラス分離(円/四角/ドーム/六角)の規律に従い、シルエットで判別可能に。
- 用途(初期実装): **繁殖CDのアメジストによるリセット(即繁殖可能)**。
  - 消費数はCFG(たたき台をCCが提案し承認)。
  - CDリセットは繁殖ロジック本体に触れず、CD残時間のクリアのみ(可逆・確率非接触)。
- 鉱石6種(ORES)との関係整理: アメジストは既にORES内部名に存在する(Dev.grant対応キー)。
  既存の鉱石アメジストとトップバー資源の統合/分離をコード実測で確認し、
  二重定義にならない設計を提案してから実装(名前衝突は事故の元)。
- Dev.grant対応キーに追加(存在済なら整合確認)。セーブ追加フィールドは単調・可逆設計。

### 承認ゲート
- 統合/分離の設計提案+アイコン2サイズ検証 → Ric承認 → 実装。

## R4. 本部UIの見直し — ロケット構想の撤廃・GBA研究室の復元

### 背景(Ric裁定)
v4ドックはデザインとして合格点に至っていない。ロケット構想を撤廃し、
元の研究室(GBA風)を復元する。

### R4-1 忠実復元(第一段)
- git記録+基準ページ(test-hqlab-pixel.html)から、**GBA規律の俯瞰研究室**
  (案Aカイロソフト系俯瞰・壁のある部屋・プロップ16種+主役機材・RAMP色ランプ・
  tier成長T1〜T3=「散らかる方向に育つ」)を復元する。
- ロケット/ドック(v4)・管制室(v3)の描画は撤廃(git記録は残す)。
  labInvest→rocketStages写像は廃止し、投資→labRoomTiers(部屋の成長)へ戻す。
- **巨大監視スクリーンは復元しない**(俯瞰との相性不良が5点裁定の一因)。
  生中継の技術資産は**小型の壁掛けモニタプロップ**として縮小残置
  (「本部はこちらを見ている」の気配だけ残す・CFGでOFF可)。
- 建造計画パネルの扱い: ロケット要素(みちのりトラッカー/工程表示)は撤去。
  ただし**統一書式(アイコン+素材名+保有/必要+不足深紅)・変換ボタンの保有内蔵・
  研究ロック行のホバー開放条件は維持**する(これらはロケットと独立したUX改善であり、
  「何を投じればよいか分からない」問題の解決を失わないため)。
  パネル名は「研究デスク」へ戻す。
- 機能・当たり判定・パネルロジック・QA実操作の全数維持。

### R4-2 再判定と改善パス(第二段)
- 忠実復元のスクショ+URL → **Ricが再判定**。
- 過去の5点裁定時の指摘(密度不足・「5億年ボタン」感)が再発する場合に備え、
  改善パス(密度・質感の引き上げ案)の提案を復元報告に添付する(実施は判定後)。

### 承認ゲート
- 忠実復元 → Ric判定 → (必要なら)改善パス → デプロイ承認。

## R5. 特性システムの見直し — genesis のランダム化・意匠の全面刷新

### R5-a genesis(創世)のランダム化
- 現状の「賢者の石による特性の選択付与」を廃し、**付与特性はランダム抽選**とする。
- 抽選対象は基本12特性のみ(合成専用6種は従来通りgenesis不可=到達の証を維持)。
- 血統重複時の扱いは trait_system.md の既存仕様に従う(変更する場合は設計承認を先行)。
- 抽選は決定論シード or 正規乱数のどちらで実装するかを含め、**確率構造の変更として
  MC実測**(12種全到達・合成専用6種の混入ゼロ・分布の一様性)を必須とする。
- 選択UIの撤去に伴う演出の調整: 「何が創世されるか分からない」緊張を、既存の
  錬成演出(深紅・静・重)の枠内で表現(演出過多にしない)。

### R5-b 特性意匠の全面刷新(15種)
- **維持: ミミカクシ・ヴォイド・ハクシ**の3種。それ以外の15種(基本9+合成専用6)の
  見た目を全面刷新する。
- 刷新の方針(Ric裁定): 現状は地味。**名前に縛られず、個性的かつ希少感のある意匠**へ。
  必要なら特性名の改名も提案してよい(命名はRic承認)。
- 維持すべき構造原則:
  - 魂(トカゲの基本描画)は不変。特性は上乗せ表現のみ。
  - 意匠の血統原則: 合成の素材2つ→結果の意匠変化が見て取れること。
  - 合成専用6種の共通の格「深紅の芯線」は維持(または同等の格の新definitionを提案し承認)。
  - 完全マッチング制約(基本12が6レシピで各1回)はデータ構造として不変。
  - レジェンダリーは特性対象外のまま。
- 進め方: **1種目を基準として先行制作**(ミミカクシが基準だった時と同じ作法)→Ric承認→
  残り14種へ展開。展開は3〜5種ずつのバッチでスクショ提示。
- test-trait-catalog.html を刷新後の全18種+6レシピ血統列で更新(全容確認の恒久資産)。

### 承認ゲート
- R5-a: 設計+MC計画 → 承認 → 実装+MC報告。
- R5-b: 基準1種 → 承認 → バッチ展開(各バッチ承認) → カタログ更新 → デプロイ承認。
