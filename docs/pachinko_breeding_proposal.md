## 3. 解釈の選択肢

| | 案A: 繁殖の決着を台に | 案B: 台を主画面に | 案C: 最小 |
|---|---|---|---|
| 体験 | ペアを手で選ぶ→繁殖台がせり上がる→遺伝子球を撃つ→**着地が子の遺伝を決める**→卵。平常の主画面は飼育槽のまま | 起動先がパチンコ台。打ち続けて当たりで産卵。飼育槽は「コロニー」ビューへ | ボス報酬の景品に卵を戻す(R2-1以前の経路) |
| 既存裁定との整合 | **全項目と整合**(常設しない/手動ペア/1繁殖=1卵/魂は主画面) | 表の1・3・5を反転(憲章の改定が必要) | 3と衝突(卵の供給過多が再発) |
| 新規に要るもの | 繁殖セッション(既存物理の流用)・座ごとのポケット定義・繁殖台の器 | 新ルール層(常設台の物理とFSM)・持ち玉の経済・新ページ・台のUI一式 | 景品テーブルの差し戻し |
| セーブ | **非接触**(未決着ぶんは保存直前に早送りで確定) | 持ち玉・統計の追加(単調追加だが承認事項) | 非接触 |
| 卵の供給量 | 不変 | 増える方向(上限設計が必須) | 増える |
| 規模 | 中(ルール層は追加のみ) | 大(新規 2,500〜4,000行の見込み) | 小 |

**段階案(A→B)**: 案Aの「繁殖台」は案Bの中核部品そのものなので、先にAを基準台として作り、実機判定のうえでBへ進むかを決める。どちらに転んでも作ったものが無駄にならない。

## 4. 推奨と、正直な見立て

- **推奨: 段階案(まず案A)**。Aは既存の全裁定と整合する唯一の読みで、しかもBの部品になる。
- **正直な見立て**: 指示の字面(「パチンコゲームにして」)は案Bに近い。一方で過去の裁定は一貫して案Aの方向を指している。どちらがRicの意図かはCCには判定できない。**Bは憲章(「飼育し、眺める」)の反転なので、Ricの明示の選択が要る。CCは選ばない。**

## 5. 案A 基準台の仕様(たたき台・数値はすべて★Ric調整)

**流れ**: 繁殖ピッカー(現行のまま)でA/Bを手で選ぶ → 「この組で繁殖」 → コスト・CD・卵スロット判定は現行どおり → **繁殖台がせり上がる**(ボス報酬と同じ器・同じクランク) → 遺伝子球を撃つ → 全球の着地で子の遺伝が確定 → 卵は既存パイプラインへ(`eggs.push`)。

**一球一座(遺伝子座ごとに1球)** — 「遺伝子ルーレット」を名前どおりの装置にする。

| 球 | 左に着地 | 右に着地 | 変異ポケット(景品帯) | 中央の割れ目 |
|---|---|---|---|---|
| 種族球 | 親Aの種族 | 親Bの種族 | 上位種へ(`breedablePool()` 内) | — |
| モーフ球 | 親Aのモーフ | 親Bのモーフ | 別モーフへ | レジェンダリー |
| 模様球 | 親Aの模様 | 親Bの模様 | (左右のみで判定) | (左右のみで判定) |
| 特性球(親の非固定特性1つにつき1球) | — | — | 継承 | — |

- 固定特性は球を撃たず必ず継承(現行と同じ)。体色のゆらぎは連続量なので式のまま(乱数だけ台のシード窓口から引く)。
- **1繁殖=1卵**。球数は「機会の数」ではなく「遺伝子座の数」なので卵は増えない(R2-1と整合)。
- 1球ずつ落とす(座ごとにポケット幅が違うため)。3〜9球×約2.5秒。「全部撃つ」で即決着、reduced-motion は物理を早送りして即時解決(どちらも結果は同一シードゆえ変わらない)。
- **純血**: 上位種の候補は `breedablePool()` のみ。`tests/purity_regression.js` に本経路を追加する。
- **決定論の改善**: 繁殖の乱数が `Math.random` から台の単一シード窓口へ移る=「同一シード+同一ペア=同一の卵」が成立し、繁殖に初めて黄金値テストを置ける(fable2)。
- **見える真実**: 巣Lvが上がると変異ポケットが目に見えて広がる(確率を幾何が語る)。
- **保存**: 新規キーなし。決着前に保存・惑星移動が来たら物理を早送りして卵を確定させる(支払い済みの繁殖が消えない)。
- **可逆性**: `CFG.pachiBreedOn:false` で現行の `inherit` へ完全復帰。

## 6. 案Bで追加で要るもの(骨子・選ばれた場合に別途詳細化)

- **台**: 既存の報酬盤とは別の常設台(新モジュール)。「結果を先に決めない」を守るなら液晶抽選(入賞時にRNGで当否決定)は使えず、**羽根モノ型の物理抽選**(スタート入賞→羽根開放→役物内の回転体→V入賞=産卵)になる。
- **持ち玉**: 新しい通貨(補給源・賞球・使い道の設計)。保存が必要=セーブ影響。
- **卵の供給**: 打ち続ければ卵が出る構造になるため、卵スロット・収容数・ペアのCDで上限を掛ける設計が必須(R2-1の再発防止)。
- **画面**: 新ページ(`UI.place()` 分岐・環境音の場所・排他・戻る導線)。起動先の変更。襲来中の扱い。
- **憲章の改定**: `roulette.md` §1.2 v4 / `UISkills.md` §0・§15 / `CLAUDE.md` 冒頭の書き換えが先。

## 8. 大型機能の開始手順(fable0・案A前提)

- **レイヤー**: ルール=`Roulette`(物理・座の決着)＋`Game`(支払い・CD・卵化) / 表現=繁殖台の器(盤ペインタは既存を共用) / 基盤=CFG。
- **データフロー**: 入力(クランク) → `Roulette` 物理 → イベント(`BallLanded` に座と決着を付加) → `Game` が遺伝を組む → `emit("breed")` → 表現(盤・結果表示・音)。表現層はルール状態を書き換えない。
- **FSM**: `idle → paid(支払い済・未決着) → firing(座iの球が飛行中) → resolved(全座確定) → egg(卵化) → idle`。中断(保存・惑星移動・閉じる)は `paid/firing → 早送り → resolved` の1本だけ。
- **非決定性の窓口**: セッションシード1つ(mulberry32)。`Math.random`/`Date.now` はシード生成の1箇所のみ。
- **命名**: CFGは `pachi*`。座の定義は `CFG.pachiLoci` のテーブル(コンテンツ追加=データ追加)。
