# Crank_Deepening_Sprint — 給餌クランクの作り込み

- 版: 1.0（2026-07-11）
- 役割: ゲームディレクター兼UX/UIディレクターによる、Claude Code 向け実装指示書
- **本書は仕様であり、コードは含まない。** Phase順に実装する。
- **必読**: `docs/crank.md`（クランク設計憲章）と `docs/UISkills.md`。クランクに関わる全実装はこの2つに従う。crank.md §1 の不可侵原則を最優先で守る。
- 位置づけ: クランクは機能的には100点。本スプリントは、**クランクを"物語の入口"へ昇華させる作り込み**。ゲーム開始直後に必ず触れる餌やり機構に「前向きな違和感」を宿し、トカゲ惑星の科学力を後天的に理解させる（crank.md §0）。

## このスプリントの芯

> **操作は全惑星で完全統一。見た目と機構表現だけが、各惑星の科学的発展を語る。** 「同じ操作なのに、惑星ごとに全く違う文明の機械に見える」——この一貫性の上の差異が「意味がありそう」を生む。派手さより密度と統一感。

- **機能・操作骨格は変えない**（crank.md §2）。乗せるのは見た目・質感・機構表現・微演出の層。
- **文字の操作説明を出さない**（ツールチップのみ・crank.md §1-2）。模索UXを残す。
- **魂（トカゲ・大地・飼育槽）不変。** クランクの造形のみ。

---

## Phase 0 — 基盤の分離とテーマ機構

- **目的**: 現行クランクの「操作骨格」と「見た目（スキン）」を分離し、**惑星ごとにスキンを差し替えられる構造**を作る。まだ見た目は現行のまま。
- **変更内容**: クランクの描画を「機構スキン」として抽象化（骨格＝操作/状態、スキン＝SVG/CSSの見た目層）。惑星IDでスキンを選ぶ仕組み（現行スキンを"default"として登録）。CFG/トークンで層数・エフェクト量を後から抑えられる土台。
- **対象**: `screens/feeder.js` ほかクランク描画。
- **テスト**: 現行の全機能（タップ/長押し/オート/補給/レバー/折りたたみ/ばね応答）が分離後も完全一致で動作／スキン切替の器が機能（default1種のみでよい）／ロジック59項目PASS。
- **完了条件**: 操作骨格に一切手を入れず、スキンを差し替えられる構造ができた（見た目は現行のまま）。**ここを固めてから作り込みへ。**

---

## Phase 1 — 第1スキンの作り込み（1惑星で"違和感"の基準を作る）

- **目的**: いきなり全惑星を作らず、**代表1惑星のスキンを高密度で作り込み**、「前向きな違和感」の濃度基準をRicと合わせる。
- **方針**: crank.md §3 の中から**1案を選んで試作**（推奨: 世界観の中心が伝わる「高級時計のムーブメント風」か「原子炉風」。着手時にRic確認）。crank.md §4 の密度要素（多層構造・待機微動・操作への精緻な反応・折りたたみ最小表示の見せ場）を作り込む。
- **重要**: 操作は現行と完全に同一。見た目だけが別文明の機械になる。文字は増やさない。
- **提示**: 通常/オート稼働/レバー操作/折りたたみ/reduced-motion のスクショ（できれば短い動きの説明）を出し、**「二度見する密度か・でも操作は迷わないか」をRicが判定**。濃さOKなら他惑星へ横展開する基準になる。
- **テスト**: 第1スキンで全操作が現行同一に動く／多層・微動が§UISkills「平常は静か」を破らない／reduced-motionで微動停止・機能維持／性能（フレーム負荷）実測で問題なし。
- **完了条件**: 1惑星のクランクが「餌やり機構ごときに二度見する」密度に達し、かつ操作は一切迷わせない。**濃度基準が確定。**

---

## Phase 2 — 惑星割り当ての確定

- **目的**: どの惑星にどの機構（時計/溶鉱炉/原子炉/ターミネーター/ホログラム/他）を割り当てるか確定する。
- **変更内容**: crank.md §3 の割り当て方針（環境・世界観との対応）に沿って、全惑星への割り当て案を作成し、Ricが確認・確定。crank.md へ確定表を追記。
- **対象**: 設計のみ（実装なし）。割り当て表を crank.md に反映。
- **テスト**: —（設計工程）。
- **完了条件**: 全惑星の機構割り当てが確定し crank.md に記録された。

---

## Phase 3 — 全惑星スキンの横展開

- **目的**: Phase 1の密度基準・Phase 2の割り当てに沿って、残り惑星のスキンを実装する。
- **変更内容**: 各惑星スキンを1つずつ実装（1スキン=1コミット単位）。共通の操作骨格を再利用し、見た目層のみ差し替え。惑星移動でスキンが切り替わる（既存のワープ演出に自然に乗せる）。
- **対象**: クランクのスキン層（惑星ごと）。
- **テスト**: 各スキンで全操作が現行同一／惑星移動でスキンが正しく切替／全スキンでreduced-motion・性能OK／どのスキンでも操作方法が同一（統一性の検証）。
- **完了条件**: 全惑星に固有の機構スキンが乗り、操作は完全統一のまま、見た目だけが文明ごとに異なる。

---

## Phase 4 — 微演出・音・折りたたみの見せ場（任意層）

- **目的**: 各スキンの"心臓部"が垣間見える折りたたみ最小表示、操作への機構反応、（任意で）文明ごとの機構音を仕上げる。
- **変更内容**: 折りたたみ状態を各文明の見せ場に（回っているだけの状態に凝縮された機構美）。タップ/長押し/レバー/トグルへの文明別の反応演出。音は実装可否をRic判断（後続でも可）。
- **テスト**: 折りたたみ最小表示が各スキンで魅力的／操作反応がスキンごとに個性を持つ／音を入れる場合はミュート可・うるさくない／全て操作を妨げない。
- **完了条件**: 作り込みが細部まで行き渡り、「意味がありそう」の違和感が完成する。

---

## Phase 5 — 仕上げ・QA

- **目的**: 全惑星スキン×全機能×性能の総点検。
- **テスト**: 全惑星でスキン切替・全操作（タップ/長押し/オート/補給/レバー/折りたたみ/ばね応答）が現行同一に動作／新規・既存セーブで崩れなし／reduced-motion全対応／性能（多スキン・多層でのフレーム負荷）実測で問題なし／絵文字ゼロ（自作SVG）／視覚要素の目視確認（CSS変数の静かな無効化を見逃さない・前スプリント教訓）／ロジックテスト全PASS。
- **完了条件**: クランクが全惑星で"物語の入口"として完成し、機能・操作は一切損なわれていない。

## 実装ロードマップ／依存

```
Phase 0 (骨格/スキン分離) ─► Phase 1 (第1スキン=濃度基準) ─► Phase 2 (惑星割り当て確定)
                                                                      │
                                                                      ▼
                                            Phase 3 (全惑星横展開) ─► Phase 4 (微演出/音) ─► Phase 5 (QA)
```

- **Phase 0 が最初**（骨格を触らずスキンを差せる構造を先に）。
- **Phase 1 で濃度基準を確定してから Phase 3 の量産**（1つ作って基準を握る→横展開、の実績ある進め方）。
- Phase 2（割り当て）は Phase 1と並行検討可だが、確定は Phase 1 の濃度を見てから。

## 安全制約（全Phase共通・実績の規律を継承）

1. **操作骨格に手を入れない。** 本スプリントは見た目層の追加。骨格（タップ/長押し/オート/補給/レバー/折りたたみ/同速関係）は現行のまま再利用する。
2. 一括置換の前に必ず grep で件数確認。エントリポイントを巻き込む置換は禁止。
3. 1スキン=小コミット、各コミット後に回帰スクショ＋ロジックテスト。
4. **確定した値は次の作業前にコミット**（撮影用の一時変更と混在させない・ガラス縁教訓）。
5. **視覚要素は実機で目視確認**（CSS変数の静かな無効化・教訓）。
6. 数値・層数・エフェクト量・回転速度はCFG/トークンへ集約（後から即調整）。
7. コンテキストが肥大したら /clear（crank.md/HANDOFF/CLAUDEに記録あり）。

## 禁止事項

- **crank.md §1 の不可侵原則を破らない**（操作統一／文字の操作説明を出さない／模索UXを残す／一貫性優先／機能削減しない／魂不変）。
- **操作を惑星ごとにバラバラにしない。** 見た目だけが違い、操作は完全統一。
- **派手さで浮かせない。** 密度と統一感で違和感を作る。Neo-Terrarium／惑星アクセントの世界観に収める。
- **平常画面を賑やかにしすぎない**（待機微動はうるさくしない）。
- **Phase 0（骨格/スキン分離）完了前に作り込みへ進まない。**
- 新スキン・新機構を足すときは先に crank.md へ追記してから実装。
- 各Phaseの節目でスクショと完了条件チェックをHANDOFFに残す。
