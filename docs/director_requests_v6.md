## 0. 前提と全体規律

- **β公開が目的**。実装の完成度より、**初見のプレイヤーが迷わず、壊れた印象を持たないこと**が優先。
- 未完成のものは「隠す」判断を優先する(不完全なまま見せない)。
- 既存プレイヤーの資産は保護する(損失感ゼロ)。撤廃には払い戻し・移行・記録を伴わせる。
- 各フェーズは独立して完了・デプロイ可能な単位とする。フェーズを跨いで中途半端な状態を本番に置かない。
- 従来の安全境界(確率・物理・純血・魂・セーブ)と、QA3層+boot console0(カナリア先行)、
  同乗デプロイ禁止、セッション運用規律(§5x-OPS)はすべて継続。

## フェーズ P1 — 撤廃と整理(バランスに影響する変更を先に済ませる)

### P1-1 味方の廃止

- 各ステージの味方を撤廃し、関係コードを削除する。
- **【重要】単純削除では済まない点をCCが先に洗い出すこと**:
  - 味方効果は脅威型(monitor/spider/crow/scorpion/hawk)に紐づく。撤廃で**戦闘難度が上がる**。
    どの程度上がるかを実測し、`bossHpMultByStage` 等での再調整が必要かを提案すること。
  - Phase7の `allyScaleByTier`(味方のボスLv連動)、`allyBoost`、味方関連CFG・テスト・図鑑項目・
    UI表示・描画資産の全数を列挙してから削除に入る。
  - **既存プレイヤーが味方に投じた資産(あれば)は全額払い戻す**。払い戻し方法を設計し承認を得ること。
  - 削除した資産はgit記録＋撤去前スクショ。
- 恒久テスト:「味方は存在しない」を監視。同時に「削除しすぎていない」(戦闘・報酬・図鑑が壊れていない)ことも検査する。

### P1-2 合成システムの撤廃と、特性の拡張

- 特性の**合成システムを撤廃**する。
- **【最重要】既存の合成特性個体の扱い**を先に設計し、承認を得ること:
  - 合成専用6種(ムメイ・ハガネ・コンテンギ・ホウカン・リンカイ・シズミマチ)は「genesis不可＝到達の証」
    として設計された。既に所持している個体がいる可能性がある。
  - 選択肢:(a)既存個体の特性は残す(以後入手不能＝希少化) (b)別の特性へ変換 (c)その他。
    **(a)を推すが、図鑑・カタログ・獲得可能性監査との整合(「存在するのに獲得できない」問題)を
    どう扱うかを含めて設計すること。**「入手経路が閉じた記念個体」として矛盾しない形にする。
  - 完全マッチング制約(基本12が6レシピで各1回)が消えるため、`trait_system.md` の設計思想を改訂する。
- **特性の追加**: 合成撤廃で減る「横の収集軸」を補うため、新規特性を追加する。
  - 種類数・意匠の方向はCCが提案 → Ric承認 → 基準1種先行 → バッチ展開(R5-bで確立した型)。
  - 意匠は刷新済み15種と同水準・同文法(素材の物語的昇華)。genesis対象に含める。
  - 深紅の芯線(合成の格)は合成撤廃に伴い意味を失う。新しい格の定義が要るか提案すること。
- **承認ゲート**: 撤廃と追加は**一度ページで閲覧できる状態にし、Ricの許可が出てからデプロイ**する。

## フェーズ P2 — 巣ネットワークの完成(β版の目玉)

### P2-1 別ページ化

- 現在モーダルで開く「巣」を、**本部と同様の別ページ(セクション切替)**として展開する。
- 本部で確立した構造(独立セクション・右メニュー・戻る導線)を踏襲し、様式を揃える。

### P2-2 ビジュアルの完全再現(画像素材による)

> **【改訂 2026-08-10・Ric裁定=本節を上書き】** コンポーネント単位の切り出し素材を用意できなかったため方針変更。
> - `nest_image2` は**参照画像(正解)**として扱い、CCが**Canvas 2Dのコードで再現**する。
> - **外部アセット禁止の憲法は維持**。`image/` の `.vercelignore` 除外も現状維持(参照画像は本番配信しない)。
> - 参照画像は**比較検証にのみ**使用する。再現度は主観でなく数値で測る(平均輝度・輝度分布・主要色の抽出と
>   占有率・主要要素の位置と大きさの差分px)。恒久テストで「参照画像からの乖離が閾値を超えたら落ちる」形にする。
> - 目視比較用に参照画像と再現結果の並置ビューア(`?tune=1#nest` 等)を用意する。
> - 以下の原文は記録として残す(透過PNG配置・配信対象化の記述は**無効**)。

- **`nest_image2` を素材として使用し、完全再現を厳守する。**
- **この項目に限り、外部画像アセットの使用を許可する**(従来「外部アセット禁止」だったが、
  コードでの再現が困難と判断したためRic裁定で解禁)。
  - 透過PNGとして配置し、Canvas/DOMのいずれで描画するかはCCが提案。
  - `image/` は現在 `.vercelignore` で本番配信されていない。**本素材は配信対象に含める**必要があるため、
    除外設定の変更と、本番での実配信・実表示を必ず実測確認すること。
  - 画像サイズ・読み込み時間・キャッシュ方針(bump-cache との整合)を設計に含める。
- 素材の見た目を**改変しない**。コードで描き足す要素(トカゲ・UI・数値)は、素材の意匠と喧嘩しないこと。
- 3解像度での崩れ確認。素材が欠落した場合のフォールバック(代替表示)も用意する。

## フェーズ P3 — 本部(HQ)の完成

### P3-1 トカゲの分析機能の本番反映

- 「本部でのトカゲの分析」機能が**本番Vercelに反映されていない**(他端末では動作、`?tune=1` にはあった可能性)。
- **調査を先に**: 当該機能が (a)実装済みで本番未配信なのか (b)tuneゲート内に閉じているのか
  (c)そもそも未実装なのかを実測で特定し報告すること。
- 反映漏れがあれば本番へ載せる。他にも同種の「ローカルにはあるが本番にない」漏れがないかを全数点検する。

### P3-2 コンセプトに沿った指令表示

- HQに**ロケット建設率など、ゲームの目的が伝わる表示**を置く。
- 表現は「本部からプレイヤーおよびトカゲへの**指令**」の形式とする(HOLO COMMAND の世界観＝
  プレイヤーは新任のディレクター、という設定に沿う)。
- 内容の候補: ロケット建設の進捗率 / 次に必要な資源 / 現在の目標 / コロニーの状態。
  実データ由来のみ。捏造しない。
- 初見のプレイヤーが「何を目指すゲームか」を3秒で掴めることを目標とする。
  ただし説明過多にしない(「気配だけ見せて説明しない」との両立をCCが設計)。

### P3-3 研究デスクのβ版非公開

- 研究デスクの必要素材表示が分かりにくいため、**β版では内容を非公開**とする。
- 開いても内容が把握できない状態にし、**「今後公開予定」である旨を明示**する。
- 遮蔽の表現はC2で確立した語彙(`REDACTED` / `UNRESOLVED` 等)と揃える。
- 機能自体は削除せず、表示のみ遮蔽する(β後に解禁できる形)。CFGで解禁可能に。

## フェーズ P5 — 音(BGM・効果音)

### P5-1 【要Ric承認】外部アセット禁止の憲法改定

- 本作は「素のHTML/CSS/JS・外部アセット禁止」を憲法としてきた。**音の導入はこれに触れる**。
- CCは実装前に、以下を提案し承認を得ること:
  - (a)音声ファイル(mp3/ogg)を配置する / (b)Web Audio APIでコードから合成する / (c)併用。
  - (b)は憲法を維持できるが表現の幅が限られる。(a)は幅が広いがアセット管理・容量・
    ライセンスの問題が生じる。**ライセンスが明確なものだけを使うこと**(出典を記録)。
  - ファイル容量・読み込み・キャッシュ・本番配信(`.vercelignore`)の設計。

### P5-2 音の設計

- **行き当たりばったりに付けない。各コンセプトに見合う音を設計すること。**
- 場面ごとの方針(たたき台・CCが具体化):
  - 飼育槽 = 温かく静か。生命の場所。環境音主体で主張しない。
  - 本部 HOLO COMMAND = 冷たい機械音・低い駆動音・計器の微音。緊張感。
  - 巣ネットワーク = 籠もった空間の反響。安息。
  - 四重スリット = 張り詰めた無音と、着地の瞬間の一撃。
  - オープニング/Lore = 物語に沿った音楽。無音の間(暗転)を活かす。
  - 効果音 = 給餌・繁殖・孵化・撃破・石の生成・惑星移動。**過剰にしない**。
- **必ず音量調整とミュートを用意**(設定画面)。既定音量は控えめ。初回起動時に大音量が出ないこと。
- reduced-motion と同様に、音を切っても体験が成立すること。

## 実施順序と理由

1. **P1(撤廃)** — バランスに影響する変更を最初に。後続の調整が上に乗るため。
2. **P2(巣ネットワーク)** — β版の目玉。時間がかかるため早めに着手。
3. **P3(HQ完成)** — 初見プレイヤーの導線に直結。反映漏れの調査も含む。
4. **P4(演出)** — 物語の整合。
5. **P5(音)** — 憲法改定を伴うため最後。他が固まってから音を乗せる。

各フェーズ完了時にRic判定 → デプロイ。フェーズを跨いだ中途半端な状態を本番に置かない。
