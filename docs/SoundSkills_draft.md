## 1. 技術方式: WebAudio合成を基盤(将来のファイル併用へ拡張可能な抽象化)

| 評価軸 | (a) 音声ファイル同梱 | (b) WebAudio合成 | (c) 併用 |
|---|---|---|---|
| 憲章整合(外部通信なし/ビルドなし) | ○ 同一オリジン配信なら整合(P2画像解禁の前例) | ◎ 追加ファイルゼロ・コードのみ | ○ |
| 表現の幅 | ◎ 楽曲・録音物・生楽器 | ○ 電子音/計器音/ドローン/ノイズ系SE/ベル・パッド。**生楽器の実在感・歌・録音物の質感は不可** | ◎ |
| 容量・読み込み | × BGM1曲2〜5MB×場面数。モバイル初期ロード増・遅延ロード必須 | ◎ 数KB(コード)・読み込み影響ゼロ | △ |
| ライセンス管理 | × 出所台帳・再配布条件・商用可否の継続管理。gitバイナリ肥大 | ◎ 発生しない(自作コード) | × 発生する |
| 決定論・テスト | △ 再生トリガのみ検査可。波形検証は事実上不能 | ◎ OfflineAudioContextでレンダリング→RMS/ピーク周波数/尺を数値ゲート化。発音イベントはスパイ可能 | △ |
| ビルドなし方針 | ○ | ◎ | ○ |

- **採用案: (b)を基盤**。ただし発音の単一窓口(§3)をソース非依存に設計し、**将来ファイル音源が必要になったら(c)へ拡張できる形**にする(拡張条項=§6)。
- 根拠: ①本作の音はHOLO機械音・環境音・電子SEが中心=合成の得意域と一致 ②ライセンスリスクゼロ ③数値ゲート(B2以来の作法)を音にも適用できる唯一の方式 ④容量ゼロ ⑤P2画像は「参照原画の再現」が目的でアセットが正解だったが、**音には正解素材が存在しない**=作りながらRic実機判定する既存プロセスに乗る。
- 合成の境界: 歌もの・生演奏の質感が要る演出が発生した時点で(c)拡張を裁定にかける。

## 2. 規律の柱

1. **初回は無音スタート**(既定 `soundOn:false`)。設定でON・状態はセーブ(dial系の器)。ONへの導線は一度だけ静かに知らせる(押し売りしない)。
   技術的裏付け: ブラウザのautoplay policyによりユーザー操作前のAudioContextは動かない=「初回から鳴らす」は技術的にも不成立。
2. **音は情報の唯一の担い手にならない**。全ての音イベントは既存の視覚表示(§9「見ればいつでも分かる」)と対で、音を切っても体験が成立する。
3. **発音は単一窓口 `Sound.play(id)`**。AudioContext直叩きの散在禁止。演出層はイベント購読で鳴らす(ルール層に音コードを置かない)。
4. **同時再生の間引き**: 同一SEの最小間隔・同時発音上限(ボイスプール)・連打時は音量減衰。優先度表(石の生成>ボス撃破>孵化>繁殖>給餌)。
5. **CFG外部化**: soundOn / master・系統別音量(BGM/SE/環境) / 各音の波形・周波数・尺・間引き閾値。数値は全て★Ric実機調整。
6. **決定論とテスト**: 発音ログで「給餌1回=feed音1回」「連打10回=≦N回」を装置QA検査。波形はOfflineAudioContextレンダリングのRMS/ピーク/尺を数値ゲート。乱数は決定論バケット。
7. **1操作1音**。UI開閉・ホバーに音を付けない。頻発アクションほど短く小さく、核となる瞬間(石の生成・ボス撃破)に音予算を集中。
8. **新規音は本書の対象表(§4)へ追記してから実装**(UISkillsと同じ作法)。

## 3. 場面別の音設計(たたき台・全て★Ric実機判定)

| 場面 | 方針(Ric提示) | 音設計語 |
|---|---|---|
| 飼育槽 | 温かく静か・環境音主体 | フィルタノイズの風+惑星tint連動の微パッド(データ駆動=slitSkinByStageと同型)。BGMらしいBGMを置かない |
| 本部HOLO | 冷たい機械音・計器の微音 | 低ハム(強フィルタ矩形波)+起動シーケンス同期のtick+パネル開閉ビープ |
| 巣ネットワーク | 籠もった反響・安息 | フィードバックディレイの籠もったパッド+遅い心拍様低音 |
| 四重スリット | 張り詰めた無音と着地の一撃 | 常時無音→クランク稼働中のみ可聴限界近くの微音→全通過の瞬間だけノイズバースト+ベル(最重の一撃) |
| オープニング/Lore | 物語に沿った音楽と無音の間 | 0.4秒グリッドに拍を同期(尺の真実=ノード表に乗る)。暗転=無音の溜め。REDACTED行=一瞬のノイズ |
| 惑星移動 | (頻発=軽く) | ビーム横断のピッチスイープ1音のみ |

## 4. 効果音の対象表(初期・追加はここへ追記してから)

給餌(最軽・超短) / 繁殖成立 / 孵化 / 蛇・ボス撃破(ボスは重) / 賢者の石の生成(最重) / 惑星移動(スイープ) / ランクアップ / Lore解放。

## 5. 不可逆性の判定と将来の制約(改定で固定されるもの)

- 音の**導入自体**は準可逆(soundOn既定false=実質可逆)。
- 本改定で将来固定される制約: ①音必須のゲームプレイを作れない(§2-2) ②発音はSound窓口+CFG経由のみ(§2-3,5) ③音声ファイル追加は§6の拡張条項による再裁定が必要 ④初回無音の既定を覆すには裁定が必要。

## 6. 拡張条項((c)併用への道)

ファイル音源が必要と判断された場合: Sound窓口のソース層(合成/ファイル)差し替えで対応し、ライセンス台帳(`docs/sound_licenses.md`)の新設・容量予算・遅延ロード設計をセットで裁定にかける。本条項があることで、その時の改定は「台帳と予算の追加」だけで済む。

## 7. 実装順(承認後・各段階Ricゲート)

S0 Sound窓口+CFG+テスト器(発音ログ/Offlineレンダ検査) → S1 SE3種(給餌/孵化/撃破)実機判定=**基準音** → S2 飼育槽環境音 → S3 本部/巣/スリット → S4 オープニング/Loreのグリッド同期。
