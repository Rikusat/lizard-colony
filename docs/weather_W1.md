# W1 動的環境演出(天候) — 設計と実測記録

> モーションアークで3度スキップされた⑱「空への反応」は、**動く環境演出が存在しない**ことが前提の欠落だった。
> 本アークでその骨格を新設する。骨格=天候システム1つ / 意匠=惑星別、の型
> (クランク・ルーレット盤・背景・設備・敵味方・四重スリットで確立済み)に乗せる。
> 実装 2026-07-27(自律実行)。**未デプロイ**(Ric実機判定後)。

## A. 骨格(共通機構) — `js/weather.js`

### A-1 サイクル(発生→継続→終息)
`weatherCycleSec`(既定150秒)ごとに **最大1回だけ** 天候が起きる。常時降らせない。

```
bucket = floor(clock / weatherCycleSec)
発生するか = hash(惑星id, bucket) < chance      … 乱数不使用
周期内の開始位置 = hash(惑星id, bucket) * (cycle - total)
強度k = rise(0→1) → hold(1) → fall(1→0)
```
- `clock` = `Game._motClock`(表示クロック・**保存しない**)。
- 稼働率 = (rise+hold+fall)/cycle × chance ≒ **8〜10%**(惑星別のchanceによる)。

### A-2 構成要素(惑星別意匠が乗る器)
| 器 | パラメータ |
|---|---|
| 降下物/浮遊物の粒子 | `n`(数) / `vy`(落下速度・負=上昇) / `rMin,rMax`(サイズ) / `col` / `alpha` / `shape` |
| 風 | `vx`(基本風) + `windAmp`×sin(t/`windSec`) = 向きと強弱の時間変化 |
| 光量と色味 | `tint:[r,g,b,a]` を全面へ上乗せ(**背景アセットは非改変**) |
| 遠景の霞 | `haze` / `hazeCol` を4段の帯で、奥ほど濃く手前へ減衰 |

粒子形状は5種: `dot`(砂/灰/埃) / `line`(雨) / `flake`(雪) / `bubble`(気泡) / `beam`(光条)。

### A-3 D7環境粒子との棲み分け(重要)
- **D7 = 常時の薄い装飾 / 天候 = イベント。二重に降らせない。**
- `Render.drawDriftMotes` が天候強度 `k` を読み、**alphaに `(1-k)` を掛ける**。
  `k ≥ 0.999`(最盛時)は **D7を完全に停止**(early return)。
- 天候が終息すると `k→0` となり、D7は自動的に元の濃さへ戻る。状態を持たない=破綻しない。

### A-4 決定論
`Math.random` 不使用。発生の有無・開始位置・粒子の座標すべてが
「(index または 惑星id) と 時刻」の純関数。同一条件で同一の天候が再現される(恒久テストで検証)。

### A-5 reduced-motion — **粒子と風は完全停止 / 色味と霞は静的に残す**
理由: 天候は「今この惑星で何が起きているか」を伝える**情報**でもある。全部消すと、
reduced-motion利用者だけが世界の状態を知れなくなる。動くもの(粒子・風)は止め、
動かないもの(色味・霞)は残すことで、**眩暈の原因を除きつつ情報は失わない**。

### A-6 負荷
`weatherMaxParticles`(既定90)が天井。惑星別の `n` がこれを超えても切り詰める。
既存の描画方式(背景キャッシュ+差分)は非改変 — 天候は **キャッシュに焼かず毎フレーム上乗せ**するだけ。

## B. 惑星別意匠(全10惑星)

| # | 惑星 | 天候 | 形状 | 粒子数 | 特徴 |
|---|---|---|---|---|---|
| 1 | アリド | 砂嵐 | dot | 70 | 強い横風(260+120)・暖色の霞が濃い |
| 2 | ネオヴェルデ | 酸性雨 | line | 62 | 速い落下・シアンの筋・夜空が沈む |
| 3 | シルヴァ | 霧と木漏れ日 | beam | 7 | 霞0.30が主役・光条がゆっくり動く |
| 4 | パルス | 黄砂 | dot | 66 | 砂嵐より細かく、霞が最も濃い |
| 5 | イグニス | 降灰と火の粉 | dot | 54 | 灰に**火の粉(emberEvery=9)**が混じる |
| 6 | ユンガ | 豪雨(スコール) | line | 82 | 最も激しい(vy=520)・視界が暗く沈む |
| 7 | メアリス | 気泡の上昇流 | bubble | 46 | **vy負=上昇**・横揺れ付き |
| 8 | グラキス | 吹雪 | flake | 78 | 強風(300+150)・空を沈めて白を立てる |
| 9 | ヴォルタ | 冷たい灰と放射霧 | dot | 40 | 霞0.30の緑がかった放射霧 |

**実測で直した設計欠陥**: 当初は各惑星の背景と**同系色**の粒子にしたため、
**①砂嵐(砂地に砂)・⑧吹雪(白地に白)が完全に同化して見えなかった**。
粒子を明度側へ、空の色味を逆方向(暗く/濃く)へ振ってコントラストを作り直した。
→ **「粒子は背景と同系色にしない」を天候意匠の規律とする。**

## C. モーション接続(⑱の本体)

既存語彙を流用し、**新規モーションは追加していない**。

| # | 反応 | 実装 | 優先順位 |
|---|---|---|---|
| C1 | 天候の開始時に空を見上げる | 既存⑯(盤への目線)と同じ「向きだけ・静止中のみ」の機構に分岐を追加。`_skyT` 窓の間は既存 **lookup 姿勢**(頭を上げて浮く)を流用 | 盤 > **天候** > 群れ警戒 > 波紋 |
| C1b | 居場所(spot)に居る個体も反応 | 向きは変えず**姿勢だけ**(spotの向き指定を壊さない)。`weatherSpotLookMult` | — |
| C2 | 降下物を目で追う | C1と同じ機構。継続相では `follow` 確率で発火。上昇流の惑星(⑦)は下から昇るものを追う | 同上 |
| C3 | 強い天候では巣へ避難 | `nestEntryFor`(動線分散)へ寄って**身を寄せる**。`weatherHuddleK` 超で発火、`huddle` 割合の個体のみ | **ボス避難が最優先**(襲来中は発火しない) |
| C4 | くつろぎの解除・再開 | `relaxActive` の ratio に `relaxMult` を掛ける。荒天で下がり、穏やかな天候(③⑦⑩)では上がる。終息で自動復帰 | — |

### C3の設計判断(ボス避難との併発)
既存の避難は `returning=true → resting=true` で**巣に入る**が、`resting` は
**表示枠コントローラ(emerge/retreat)**が管理しており、天候が勝手に入れると
コントローラが即座に出そうとして競合する。
→ **天候避難は巣に入らない**(入口へ寄って留まるだけ)。`resting`/`returning` に触れないので
ライフサイクルと競合しない。**ボス襲来中は天候避難に入らない**(戦闘の避難が最優先)。
天候終息で自動的に通常徘徊へ戻る(状態を持たない)。

## D. 相互作用の実測(J+K事故の再発防止)

**既定CFG値のまま**・**設備建設済み**(spotが実在する状態)・**多個体**で240秒シミュレート。
テストのために機能を無効化していない。ラン間で `_motClock` をリセットし天候の位相を揃えた。

| 個体 | 天候 | くつろぎ | ボス | 水飲み到達 | くつろぎ率 | 避難中 | 見上げ | 天候稼働 | 経済不変 |
|---|---|---|---|---|---|---|---|---|---|
| 3 | OFF | OFF | 無 | 0 | 0% | 0 | 0 | 0% | ✓ |
| 3 | OFF | ON | 無 | 0.16 | 7.9% | 0 | 0 | 0% | ✓ |
| 3 | ON | OFF | 無 | 0 | 0% | 0.51 | 11 | 14.2% | ✓ |
| 3 | ON | ON | 無 | 0.08 | 6.0% | 0.25 | 44 | 14.2% | ✓ |
| 24 | OFF | OFF | 無 | 0.26 | 0% | 0 | 0 | 0% | ✓ |
| 24 | OFF | ON | 無 | 0.54 | 7.4% | 0 | 0 | 0% | ✓ |
| 24 | ON | OFF | 無 | 0.17 | 0% | 2.29 | 99 | 14.2% | ✓ |
| 24 | ON | ON | 無 | **0.72** | 4.7% | 2.29 | 88 | 14.2% | ✓ |
| 24 | ON | ON | **有** | 0.26 | 0% | **0** | **0** | 14.2% | ✓ |

読み取り:
- **水飲みは天候で殺されない**(24個体・くつろぎON: OFF 0.54 → ON 0.72)。J+K事故の再発なし。
- **ボス襲来中は天候避難0・天候の見上げ0** = 戦闘が最優先で正しく抑制されている。
- **経済(コイン/ジェム/賢者の石)は全条件で不変**。
- くつろぎ率は天候ONで微減(4.7% vs 7.4%)。天候は稼働率14%なので希釈される=妥当。

### この実測で発見して直した2件
1. **ボス襲来中も空を見上げていた** → 天候の視線を `!this.raid` で抑制。
2. **少数個体+くつろぎONで見上げが0**(全個体がspotに居ると、視線ブロックの `!lz.spot` 条件で誰も反応しない)
   → **C1b**(spot滞在個体は姿勢だけ反応)を追加。3個体でも 0 → 44 に回復。

## E. 安全境界

- 経済・生産・繁殖・戦闘・確率・純血・魂・セーブに**非接触**(天候は表示層のみ)。
  `weather.js` に `Game.state`/`localStorage`/経済APIの参照は**0件**(恒久テストで監視)。
- **天候が経済に影響する設計は今回入れていない**(例: 雨で生産+X%)。
  将来入れるかは **Ric裁定事項** として記録する。
- 背景アセットは非改変(`paintBackground` のキャッシュには触れず、上乗せのみ)。
- 恒久テスト `tests/weather_regression.js` **69 PASS**。
