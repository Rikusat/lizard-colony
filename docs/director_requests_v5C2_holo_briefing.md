## 0. 方針転換の理由

C1はフラット2Dイラスト表現で5版を重ねたが、造形力が基準に達せず中止した。
一方 **本部 HOLO COMMAND(ホログラムHUD)はディレクター試作が一発で本採用**されており、
この表現領域は本プロジェクトの強みであることが実証されている。
よってシネマティックを **ホログラムHUD調で再出発**する。

## 1. コンセプト —「本部の起動ブリーフィング」

**このムービーは演出ではなく、本部システムがプレイヤー(＝新任のディレクター)に対して行う起動時ブリーフィングである。**

- HUDが画面に出る理由が世界の内側で成立する(装飾でなく機構)。
- 既存の本部 HOLO COMMAND と地続きになり、ムービーが終わった瞬間にゲームが起動する＝**導線が途切れない**。
- 見終わったプレイヤーは「システムを起動した」感覚を持つ。これが本アークの導線設計の核。

## 2. 表現規律

### 2-0 【最重要】C1の禁止事項は本アークに適用しない

C1で禁じた「グラデーション禁止・光彩ぼかし禁止・stroke禁止」は、**フラット2Dイラスト表現に対する規律**だった。
**HUD/ホログラム表現ではこれらは逆に必須の語彙である。**

- 線(stroke)＝HUDの主要素。細線・破線・弧・ブラケット・目盛は積極的に使う。
- 発光(shadowBlur / 加算合成)＝ホログラムの実在感の源。使う。
- グラデーション＝走査線・減衰・スイープの表現に使う。
- ただし **「立体的な陰影で物体をリアルに見せる」用途には使わない**。ホログラムは半透明の光の投影であり、
  質量を持った物体ではない。ここが唯一の禁則。

### 2-1 様式の基準(スタイルバイブル)

`docs/design/hq-holo-command-poc.html`(本採用済みの本部HOLO COMMAND試作)を**様式の正本**とする。
配色・書体・ブラケット・目盛環・走査線・テレメトリの語彙をここから継承すること。

- 配色: 虚空 `#04060a` / 琥珀 `#ffb547`(主) / 深紅 `#d2384a`(警告・錬成) / 白青 `#dfe9ee`(瞬間のハイライトのみ)。
  **色は3色に厳しく制限**。多色を使うのは⑦虹の一瞬だけ。
- 書体: 和文＝太ゴシック(見出し) / 欧文・数値＝等幅(テレメトリ)。数値は必ず実データ風に桁を揃える。
- 質感: 暗部に浮かぶ半透明の光。走査線・微細なノイズ・グリッチ。レターボックス。

### 2-2 疑似3D(科学力の表現)

「3Dの技術力」は3Dエンジンでなく **Canvas 2D上の投影計算**で表現する。数学的に本物の3D回転を2Dへ投影すること。

- 回転するワイヤーフレーム球(惑星)・軌道・分子/遺伝子の螺旋・等角の格子。
- 透視投影(遠近)と陰線処理の簡略(奥の線を減光)で立体感を出す。
- **ホログラムなので不完全でよい**: 走査線で途切れる・輪郭が滲む・時々グリッチする。完璧なCGより説得力が出る。

## 3. 構成 — ミッション・インポッシブルOPのオマージュ

参照: https://www.youtube.com/watch?v=4WOx16_rOwU

MIのOPの構造は「**導火線が走り、その道中でこれから起こる出来事の断片が高速で閃く**」——予告モンタージュである。
これを本作の語彙に翻訳する。

### 3-1 導火線 = 深紅の芯線

合成特性の共通の格である **深紅の芯線** を導火線に見立てる。
1本の深紅の線が画面を走り、**通過するノードごとにホログラムが開いて断片を見せ、すぐ閉じる**。
線は最後に中央へ収束し、タイトルになる。

### 3-2 ノード(閃く断片) — 伏線として機能させる

各ノードは1秒未満。説明しない。**「これは何だ」と思わせて閉じる**のが目的。

| # | 断片 | 伏線・狙い |
|---|---|---|
| 1 | 故郷の球体がワイヤーフレームごと侵食され崩壊 / `CONTAINMENT FAILED` | バガーの正体は語らない |
| 2 | 十の惑星がワイヤーフレーム球で高速に流れる。各球に固有の幾何環(四重スリットの確定意匠を引用) | 行き先の全体像 |
| 3 | 純血のロック表示: 各惑星に2種のみ、3種目が `REDACTED` で伏せられる | 「3種目とは何か」の疑問を残す |
| 4 | 遺伝子ルーレットの球の軌道と確率テレメトリ | 射幸の予告 |
| 5 | 四重スリット: 4基が別速度・逆回転し、球が通過、賢者の石が結晶化 | 到達の困難さ |
| 6 | 特性グリフが滝のように流れ、1つだけ深紅の芯線を持つものが止まる | 合成＝到達の証 |
| 7 | 虹のスペクトル走査(唯一の多色) | 生命の祝祭 |
| 8 | 署名ボスの影が一瞬だけ複数フラッシュ | 脅威の予告 |
| 9 | コロニーのバイタルが多数並び、1個体だけ `記録破損 / UNRESOLVED` | **最大の伏線**(未解明の個体) |

### 3-3 タイムライン(たたき台・尺は12秒前後)

```
0.0-1.2  起動      暗転 → 細い琥珀線 → ブラケットが噛み合う → BOOT テレメトリ
1.2-2.0  点火      深紅の芯線が左端から発火、走り始める
2.0-8.5  モンタージュ ノード1〜9が高速で開閉(1つ0.5〜0.8秒)
8.5-9.5  暗転部    全ホログラムが一斉に消え、深紅の警告だけが残る(ダークの底)
9.5-10.8 収束      芯線とホログラムの断片が中央へ収束し、輪になる
10.8-12.0 題       トカゲコロニー / LIZARD COLONY → システム起動
```

### 3-4 リズム(音がない前提での設計)

音声は付けない。したがって**カットの間合いだけで疾走感を作る**。

- **0.4秒のリズムグリッドを敷き、カットの切替を必ずグリッド上に置く**(0.4/0.8/1.2…)。
  ずらすのは意図的な溜め(暗転部)のみ。
- 3連続で同じ長さのカットを置いたら、4つ目で長さを変える(単調さの回避)。
- 情報量の波: 密→密→密→**空白**。空白があるから密が効く。§3-3の「暗転部」がそれ。

---

## 4. 伏線とダークトーンの規律

- **説明しない**(crank.mdの作法)。ノードは提示するだけで、意味は本編で回収させる。
- ダークの作り方: 深紅の警告 / `REDACTED`・`UNRESOLVED`・`CONTAINMENT FAILED` の遮蔽表示 /
  一瞬のグリッチ / 全ホログラムが落ちる暗転部。**血や暴力に頼らない**。情報が欠落していることが不穏さの源。
- 嘘をつかない: 表示する数値・種名・惑星名は実データまたは実設定に基づくこと(捏造したそれらしい数値を並べない)。
  伏線として意図的に伏せる場合は `REDACTED` 等の遮蔽表示を用い、偽情報を書かない。

---

## 5. 技術制約

- 素の HTML/CSS/JS・ビルドなし・**Canvas 2D のみ**。外部ライブラリ・外部アセット禁止。
- 3Dは投影計算で自前実装(回転行列＋透視投影)。ライブラリ不可。
- 決定論(乱数不使用・ハッシュと時刻バケット)。グリッチも決定論で。
- `prefers-reduced-motion`: 動きを止め、最終画を静止表示。ただし情報(テレメトリ・断片)は残す。
- **スキップ可能**(クリック/タップ/キー・即時・確認なし)。
- 尺12秒前後。全パラメータCFG化。
- 本編のロジック・セーブ・経済・確率・純血・魂に非接触。再生済みフラグは単調追加。
- 再生機構は独立モジュール。将来の差込先(惑星解放/Lore/スリット成功)に再利用できる構造にする。
- 負荷: 再生中のみ描画。本編描画ループに条件分岐を足さない。

## 6. 進め方(承認ゲート)

1. **基準カット**: 「起動＋点火＋ノード1〜2」の**最初の3秒**を制作。
   ここで様式・疾走感・情報密度の基準が決まる。`?tune=1#opening` のビューアで提示。
   - 併せて**導火線の表現を2案**(例: a=深紅の芯線が走る / b=走査ビームが横断する)並べ、Ricが選ぶ。
2. Ric判定 → 承認後に**全編制作** → Ric判定 → デプロイ承認。
3. 本編組み込み(初回起動時の自動再生・既存セーブでは流さない・設定から再視聴)は全編承認後に別途指示。
4. 静止画で伝わらないため、提示は必ず**位相をずらした連番3枚以上**を添えること。

---

## 7. 判定基準

1. **圧倒されるか**(ハリウッド級の要求に対して)。
2. **導線**: 見終わった直後に始めたくなるか。ムービーとゲームが地続きに感じられるか。
3. **伏線**: 「今の何だ」と思う瞬間が最低2つあるか。
4. **科学力の説得力**: HUDとホログラムが本物の機構に見えるか(飾りに見えないか)。
5. **ダーク**: 不穏さがあるか。ただし品位を失っていないか。
6. **読めるか**: 高速でも情報が視認できるか(速すぎて何も残らない、を避ける)。

# C2改訂 (ディレクター発行 2026-07-28) — 単発のOPから「再利用可能なHUDトランジション機構」へ

## R-0. 位置づけの変更

C2は単発のオープニングではなく、**ゲームの節目に挟む再利用可能なHUDトランジション機構**とする。

- 実装対象(2つ): **(1) 惑星移動トランジション**(=フェーズ1) / **(2) オープニング**(バガー暴走 → 惑星からの飛び立ち。=フェーズ2)
- 将来の差込先候補(**今回は実装しない**・候補として記録のみ): 本部への入退場 / 署名ボスの出現 / 四重スリットの着地成功 / 新種の発見。

## R-1. 様式の確定 — 案b(beam) を共通様式として採用

- **採用: 案b = 白青の走査ビームが横断し、通過後にHUDの格子が起動して残る。**(`CFG.holoFuseVariant: "beam"`)
- **是正済みの欠陥**: 基準カットでは横断完了後もビームが画面右端(0.94W)に描かれ続け、後続のノード表示と競合した。
  → `Holo.beam()` として共通化し、先端を画面外(1.08W)まで走らせ、末尾 `CFG.holoBeamTailF`(0.18)で減衰させて必ず消す。
  通過済みの格子だけが残る。基準カットの案bにも同じ関数を通したため、同一の是正が効いている。
- **案a(core / 深紅の芯線)の扱い**: 撤去せず**フェーズ2への転用候補として保持**する(参照は0件ではない=
  `?tune=1#opening` の2案比較ビューアと `drawCut(variant)` から現に呼ばれている)。
  転用案: 芯線の「焼け跡が残る・火花が散る」語彙は、フェーズ2の**バガーによる侵食痕**の表現に一致する。
  フェーズ2で不採用となった時点で、参照0件の証明を添えて撤去する。

## R-2. フェーズ1 — 共通基盤 + 惑星移動トランジション(実装済み)

### 頻度への配慮(最重要)

| 要求 | 実装 |
|---|---|
| 尺 0.8〜1.2秒を上限 | `CFG.holoTravelMaxSec: 1.2` で**クランプ**(CFGに超過値を書いても効かない)。初訪 1.10s / 既訪 0.80s / reduced 0.45s。**実機実測 1.109s / 0.807s(超過はいずれも1フレーム未満)** |
| スキップ即時・確認なし | クリック/タップ(`pointerdown`)・キー(`keydown`)のいずれでも即終了。実測レイテンシ ≒ 1フレーム |
| 初回と2回目以降で差 | 未開拓(=初めて訪れる)=情報表示ありの長い版 / 開拓済=短縮版(ビームの走査+惑星名のみ)。しきい値 `holoTravelFullOnUnpioneered`・尺は全てCFG |
| CFGで完全OFF | `holoTravelOn: false` で**従来の宇宙船トランジション(planetTravelSec)へ完全復帰**(=可逆) |

### 内容

ビームが横断 → 行き先の惑星がワイヤーフレーム球で回転して現れる → 固有幾何環(四重スリットの確定意匠を引用)
→ 着地の一閃 → 惑星名・固有種2種・脅威型・素材を等幅で一瞬表示 → ビームが抜けて惑星画面へ。

- **表示は全て実データ由来**: 惑星名=`PLANET_NAMES` / 固有種=`SPECIES.stage` / 脅威型=`PLANET_BOSS`→`BOSS_TYPES` /
  素材・HQ Lv=`STAGES`。欠落は `REDACTED` / `UNRESOLVED` の遮蔽表示で、偽の数値を書かない。
- **惑星ごとに色調が変わる**: その惑星の `STAGES.sky` を引用し、虚空 `#04060a` の上で線が読めるよう
  ①色相を保った増幅 ②飽和分だけ白へ寄せる、の2段で明度を底上げする(`Holo.tintOf`)。10惑星で10通り。
- HUDの骨格(ビーム=白青 / ブラケット・目盛=琥珀 / 虚空)は3色規律を維持し、**惑星の色は惑星そのものにだけ乗る**。

### 既存 planetTravelSec との関係(判断)

**置換する。**「その中で描く」= 従来の3.0秒の宇宙船演出の**後に**1.1秒のHUDを重ねることになり、
合計4.1秒＝「演出が摩擦になってはならない」に正面から反するため。
ただし従来の実装は `UI.travelToLegacy()` として残し、`CFG.holoTravelOn: false` の復帰先とした(可逆性の担保)。

> **ディレクター指示との競合を1度だけ指摘する**: 過去の承認事項「⑥惑星移動のスキップ撤廃(待ち時間そのものが
> 宇宙の広さの表現)/ `planetTravelSec=3.0`」と、本改訂の「尺≦1.2秒・スキップ即時」は真っ向から競合する。
> 本改訂が後発かつ明示的であるため**本改訂を優先**した。旧方針へ戻す場合は `holoTravelOn: false` で即復帰できる。

### ゲーム進行への影響(実測)

**トランジション中も本編の時間経過・生産は進む。** 実測(惑星1→2): 計測窓で `Render.time` +1.267 / コイン +1.507 = 止まっていない。

- 理由: 本編ループ(`UI.loop`)はDOMオーバーレイと独立した単一の `requestAnimationFrame` で回っており、
  止めるには**本編ループに条件分岐を足す**必要がある(安全境界「本編ロジック非接触」に抵触・§5の負荷規律にも反する)。
- 不自然でない方の判定: 止めた場合、背後のCanvasが1.1秒間フリーズしてから再開するため**復帰時にカクつきが見える**。
  進める場合、失われるものは1.1秒ぶんの生産(≒コイン1.6枚)のみで体感差がない。**進める方が不自然でない**と判断。

### 安全境界の遵守

惑星切替の既存処理の**順序は不変**: 演出の `onEnd` → `UI.confirmSwitch(id)` → (開拓済なら)`Game.selectStage()` →
`reset`・`Roulette.reset` 等。演出側から `selectStage` を直接呼ばない(恒久テストで固定)。
`js/holo.js` は `Game`・`localStorage`・`Roulette/Slit/Weather` を**一切参照しない**(恒久テストで固定)。

## R-5. フェーズ2(次セッション・今回は未着手)

バガー暴走 → 惑星からの飛び立ち。前版の9ノード予告モンタージュは、この物語の中に断片として最小限だけ残す(伏線)。
