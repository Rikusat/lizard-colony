## 1. 解決する5つの問題

| # | 現状の問題 | V3での解決 |
|---|---|---|
| 1 | 過去Stageへ戻る意味がない | 各Stageが**独立コロニー**として時間経過。Stage固有素材が他Stageの最深部要求に必要（§6・§9） |
| 2 | トカゲが大量で画面が圧迫 | **巣収納システム**。平時はアダルトが巣で休み、数匹だけ外出。ボス時に全個体が飛び出す（§4） |
| 3 | Stageが背景変更だけ | Stageごとに**専用種・専用設備・専用探索ツリー・専用ボス**（§3・§6・§7・§8） |
| 4 | Stage毎の特徴が薄い | 環境ルール（気温・湿度）が生態と設備の意味を変える（§3.3） |
| 5 | 終盤のやり込み不足 | **探索ツリー（ハクスラ）** ＋ **本部メタ成長** ＋ 伝説報酬（§5・§9） |

## 2. コア設計思想

> **「引っ越し」ではなく「拠点を増やす」。プレイヤーは失っていない。増えている。**

V3最大のリスクは、Stage独立化がプレイヤーに**リセット感**を与えることだ。この一点の設計で成否が決まる。原則を3つ置く。

1. **ゼロから始まるのはコロニーだけ。プレイヤー（本部）は決してゼロにならない。** 本部レベル・研究・実績・探索成果・図鑑は全Stage共通で永続する（§9）。
2. **新Stageは「難易度の高い挑戦」ではなく「新しい土地の開拓」。** 開始時点で本部ボーナスが乗るため、2つ目以降のコロニーは1つ目より**速く育つ**（体感的な成長カーブは常に右肩上がり）。
3. **旧Stageは死なない。** 放置生産・探索・ボス進行が走り続け、戻る理由が常にある（§3.4）。

## 3. Stage Colony System

### 3.1 定義

Stageは背景ではなく、**独立したコロニー**。各Stageが以下を個別に保持する。

| Stageが保持するもの | 備考 |
|---|---|
| 個体（LizardData[]） | Stage専用種を含む。Stage間の移動は原則不可（例外は§9.4 創始者の卵のみ） |
| 設備（EquipmentData[]） | Stage専用設備。Lvも個別 |
| 巣（NestData） | 巣Lv・探索隊・卵スロット |
| 探索進行（ExplorationData） | Stage専用ツリーの解放状況 |
| ボス進行（BossData） | 撃退数・ティア・Elite周期 |
| 資源（StageResources） | コオロギ在庫・Stage固有素材 |
| 環境（EnvironmentProfile） | 気温・湿度などStage固有ルール |

### 3.2 グローバルに残るもの（＝プレイヤーの資産）

- Gold・ジェム（**全Stage共通のウォレット**。これは分割しない。分割すると新Stageが本当に貧しくなり、リセット感が致命的になる）
- 本部レベル / 研究 / 実績 / 称号 / 図鑑 / 味方 / 統計

> **設計判断**: 通貨を共通にすることで「新Stageに前のStageの富を投入できる」。開拓の初速はこれで担保する。一方、**コオロギ在庫と固有素材はStage別**にすることで、各Stageの経済に自立性と手触りを残す。

### 3.3 環境プロファイル（Stageの個性の正体）

各Stageは環境値を持ち、既存ステータス（満腹・渇き・体力）の減少速度に係数を掛ける。**新ルールではなく、既存の数値への係数**であることが重要。

| Stage | 環境 | 効果（初期値） | 意味 |
|---|---|---|---|
| 砂漠 | 高温・乾燥 | 渇き−50%速い / 体力−20%速い | 水場が生命線 |
| 草原 | 温暖 | 補正なし（基準） | 標準 |
| 密林 | 高温多湿 | 満腹−30%遅い / 渇き−30%速い | 餌は楽・水は要る |
| 湿地 | 低温多湿 | 移動速度−15% / 毒環境 | 泥で鈍る |
| 火山 | 極高温 | 体力−60%速い / 満腹−20%速い | 過酷。設備必須 |
| 雪原 | 極低温 | 体力−80%速い / 満腹−40%速い | 保温が生命線 |
| 洞窟 | 低温・暗 | 繁殖効率−20% / レア発光個体+ | 暗さがレアを映す |
| 古代遺跡 | 変動 | 全補正が周期変動 | 集大成 |

### 3.4 オフライン進行（旧Stageが生き続ける仕組み）

- 非アクティブStageは**簡易シミュレーション**で進行する（全個体のFSMは回さない。CPU負荷を出さないこと）。
  - 生産: アダルト数 × 生産レート × 経過時間（設備バフ適用）
  - 探索: 派遣隊の進行度を経過時間分だけ加算
  - ボス: 撃退確率を「迎撃力 vs ボスHP」で1回だけ判定し、勝敗と報酬を丸めて記録
  - 満腹/渇き/体力: 平均値で丸める（自動給餌器があれば維持、無ければ生産効率が段階低下）
- **上限**: オフライン進行は最大24時間分（本部研究で延長可）。
- **復帰時**: Stage切替UIに「!」バッジ＋「おかえりリザルト」で「留守中: 探索完了2件 / ボス撃退3回 / 素材+○」をまとめて通知。**この通知こそが「戻る理由」の設計そのもの。**

## 4. トカゲ収納システム（Nest Retreat）

**目的**: 描画負荷と視認性の同時解決。かつ「巣で暮らしている」生活感の強化。増やすのではなく**引く**改善。

### 4.1 平時（Idle Mode）

- **アダルト個体は原則、巣の中にいる**（描画されない）。巣に「休息中 ○匹」のバッジと、巣口から尻尾や頭がのぞく小演出を表示。
- **外出枠**: 常時フィールドに出るのは **最大N匹**（初期値: 8匹 ＋ 巣Lvごとに+1、上限15）。
  - 外出メンバーは30〜90秒ごとに入れ替わる（帰る個体・出てくる個体のアニメ付き）。
  - **ベビー/ヤングは常に外**（可愛さと成長の実感は外で見せる。ただし合計は外出枠に含める）。
  - **レア/伝説個体は外出優先度が高い**（見せたい個体が見える設計）。
- **個体の見つけ方**: 巣タップ→巣内一覧（全個体をリスト表示）。「この子を外に出す」ピン留めが可能（お気に入りは常時表示）。

### 4.2 ボス襲来時（Combat Mode）

1. 襲撃予告 → 巣口に緊張演出（全個体がざわめく）
2. 襲撃開始 → **全アダルトが巣から一斉に飛び出す**（0.05秒ずつ時差で噴出。ここが本Sprint最大の見せ場）
3. 迎撃 → 既存の迎撃ロジック（監視塔で上限拡張）
4. 戦闘終了 → 数秒かけて隊列を組んで巣へ帰還。外出枠の平時運用に戻る

> **演出の狙い**: 「普段は静か → ボスで一斉出撃」という**динамик差**が、113匹の物量を"圧迫"から"迫力"に変える。物量は消すのではなく、**見せる瞬間を絞る**。

### 4.3 描画パフォーマンス方針

- 平時のフィールド描画対象を常時15体前後に抑える（現在の113体から約87%削減）。
- 戦闘時のみ全個体を描画。**戦闘時は上限を設ける**（描画上限: 60体。超過分は「後衛」として巣口に集約表示し、戦闘計算には全数参加させる）。
- Phase 0のfps実測値と比較し、**平時fpsが実測で改善していること**を完了条件に含める。

## 5. 探索システム / 探索ツリー（ハクスラ）

### 5.1 基本ループ

```
巣をタップ → 探索画面
  ↓
探索隊を編成（トカゲを派遣）
  ↓
時間経過で探索進行（オフラインでも進む）
  ↓
素材 / 装備 / 突然変異素材 / 超レア素材 を取得
  ↓
素材でツリーのノードを解放 → 探索速度・報酬が伸びる
  ↓
より深い階層へ → 最深部 → 伝説報酬
```

- **派遣中の個体はフィールドと巣から一時的に外れる**（＝収納システムとも噛み合う）。派遣中は生産に寄与しない（トレードオフ）。
- 探索は**放置と相性が良い**（オフラインで進む）。ボス戦の緊張と、探索の待ちが交互に来る設計。

### 5.2 探索速度の決定要素

```
探索速度 = 基礎速度
         × (1 + 派遣数ボーナス)     … 派遣1匹ごとに +8%（上限は隊列枠まで）
         × (1 + レア個体ボーナス)   … レア度に応じ +5〜30%／伝説個体は +50%
         × (1 + 設備ボーナス)       … 研究所・展望岩・Stage固有設備
         × (1 + 研究ボーナス)       … 本部研究（全Stage共通・§9）
         × (1 + ツリーノードボーナス) … 当該Stageツリーで解放した速度ノード
```

- **隊列枠**（同時派遣数）は巣Lvで拡張（初期3 → 最大10）。複数隊の同時派遣は巣Lv5から解禁。
- 個体の**成長段階・幸福度**も係数に入れる（アダルト＞ヤング、幸福度が高いほど速い）。

### 5.3 探索ツリーUI（添付画像に準拠）

**添付画像（格子状パッシブツリー）のフォーマットを採用する。**

- **形状**: アイコンノードを**格子状に配置し、線で接続**する。曲線的な有機ツリーではなく、**行＝カテゴリのレーンが横に伸びる格子**。
- **ノード**: 小さな正方形アイコン（枠色でレアリティ表現: 茶＝通常 / 金＝強力 / **緑枠＝キーノード（画像の緑枠に相当）**）＋直下に短い日本語ラベル。
- **レーン構成（行＝カテゴリ）**: 画像がGold行・EXP行・宝箱行・戦闘行に分かれているのと同様に、本作は以下の4〜5レーンで構成する。
  - **資源レーン**: 素材取得量 / ボス素材 / 希少素材 / Stage固有素材
  - **効率レーン**: 探索速度 / オフライン探索報酬 / オフライン報酬解放 / 隊列枠
  - **収納レーン**: インベントリ枠 / 宝箱保管数 / **一括開封**（画像の「一括開封」に相当。終盤UXの要）
  - **戦闘レーン**: 迎撃攻撃力 / 防御 / 移動速度 / ボス報酬
  - **繁殖/変異レーン**: 突然変異率 / レア孵化率 / 伝説抽選
- **解放**: ノードはStage固有素材で解放。手前のノードを取らないと先へ進めない（**接続線＝前提条件**）。
- **分岐**: 序盤は1本、中盤で複数レーンに分岐し、**最深部で再合流して伝説ノードへ**。
- **視認性**: 解放済み＝彩色、解放可能＝点滅枠、未解放＝暗色。画像同様、**一目でどこまで進んだかが分かる**こと。
- **深度**: 1ツリーあたり **60〜100ノード**（画像相当の物量感）。うち「取り得のあるキーノード（緑枠）」を8〜12個。

### 5.4 探索の報酬階層

| 階層 | 深度 | 主な報酬 |
|---|---|---|
| 浅層 | 1〜3 | Stage基礎素材、コオロギ、Gold |
| 中層 | 4〜7 | 装備素材、設備強化素材、レア素材 |
| 深層 | 8〜12 | **突然変異素材**（既存個体の系統を変異させる）、上位装備、ジェム |
| 最深部 | 13+ | **超レア素材 / 伝説設備 / 伝説個体（の卵） / Stage固有の唯一報酬** |

- **最深部到達は「Stageのクリア」に相当する到達点**。到達時に専用カットイン＋称号＋図鑑登録。
- **宝箱**（画像の宝箱ノード群に対応）: 探索で宝箱を獲得 → 開封で中身抽選。**保管数の上限**があり、ツリーで拡張。「一括開封」ノードで終盤の作業感を消す。

## 6. Stage専用探索ツリー

**各Stageは、名前も見た目も報酬も全く異なるツリーを持つ。** これが「戻る理由」の本体。

| Stage | 巣の名称 | ツリーの世界観 | 固有素材 | 最深部の伝説報酬 |
|---|---|---|---|---|
| 砂漠 | **地下巣穴** | 掘り進むトンネル。砂に埋もれた骨と化石 | 乾いた砂・化石片 | 伝説設備「太古の卵殻」／伝説個体：古代砂竜 |
| 草原 | **草の根の巣** | 根が張り巡る地下。虫と種子 | 草の実・繊維 | 伝説設備「豊穣の祭壇」／突然変異素材の安定供給 |
| 密林 | **巨木（樹上の巣）** | 上へ登るツリー（垂直方向の演出） | 樹液・蔦・希少花 | 伝説個体：翡翠樹上竜／伝説設備「世界樹の苗」 |
| 湿地 | **湿地の巣** | 沈む泥、沼底の遺骸。毒と菌 | 泥炭・菌糸・毒腺 | 伝説設備「解毒の泉」／毒完全無効 |

| 雪原 | **氷穴** | 氷を割って潜る。凍結した何か | 氷晶・凍結琥珀 | 伝説個体：氷竜／伝説設備「永久凍土庫」 |
| 洞窟 | **深淵洞** | 光の無い縦穴。燐光と未知 | 燐光石・深淵結晶 | 伝説個体：発光竜／**突然変異素材の最上位** |
| 古代遺跡 | **遺跡地下墓所** | 石扉・碑文・封印。全ての答え | 遺物片・古代金属 | **始祖竜の卵**（全Stage最終報酬）／伝説設備「創世の碑」 |

### 6.1 クロスStage素材要求（＝過去Stageへ戻る強制力）

**最深部ノードは、他Stageの固有素材を要求する。**

- 例: 火山ツリー最深部「熔炉」 → 火成鉱×500 ＋ **氷晶×50（雪原）** ＋ **黒曜石×200（火山）**
- 例: 遺跡ツリー最深部「創世の碑」 → **全8Stageの固有素材を各100**

> **設計意図**: これにより「旧Stageの探索隊を回し続ける」ことが最適解になる。過去Stageが**素材プラント**として生き続け、戻る意味が構造的に発生する。ただし要求量は「放置で数日回せば貯まる」水準にし、手作業の往復を強要しないこと（＝ストレスにしない）。

## 7. Stage専用個体（生態系）

- 各Stageに**固有系統を5〜8種**追加。既存の系統/遺伝の仕組みにエントリを足すだけで、**新ルールは作らない**。
- Stage固有種は**そのStageでしか繁殖・出現しない**。図鑑もStage別タブに分かれる。

| Stage | 固有種の方向性（例） |
|---|---|
| 砂漠 | 砂トカゲ / 角トカゲ / 砂潜り種。淡色・砂に紛れる |
| 草原 | 草トカゲ / 走行種。既存系統の基準 |
| 密林 | **樹上トカゲ** / 擬態種 / 翡翠系。木登り演出を持つ |
| 湿地 | 湿地トカゲ / 毒持ち種 / 半水棲。毒耐性を先天的に持つ |
| 火山 | **火山トカゲ** / 耐熱種 / 溶岩紋。体が熱で明滅 |
| 雪原 | **雪原トカゲ** / 白化種 / アルビノ系。息が白い |
| 洞窟 | 発光種 / 無眼種 / 燐光紋。暗闇で光る |
| 遺跡 | 古代種 / 石化紋 / **始祖竜系**（唯一） |

- **突然変異**: 深層で得る突然変異素材を使うと、既存個体を**Stage固有種の変異体へ変える**。これが探索と繁殖を接続する終盤の遊び。
- **図鑑**: Stage別タブ ＋ 「全Stage総覧」タブ。コンプ率に応じ本部ボーナス（§9）。

## 8. Stage専用設備

- 設備はStageに紐づく。**そのStageに来ないボス用の設備はUIに表示しない**（例: 火山Bossが出ないStageでは火山設備を非表示）。
- 設備タブは「このStageで意味のある設備のみ」を出す。**選択肢を減らすことがUX改善**。
- V2で設計した20設備は、Stageごとに「使える/使えない」を割り当てる。加えてStage固有設備を各1〜3種。

| Stage | Stage固有設備（例） | 効果 |
|---|---|---|

## 9. リセット感の解消（最重要設計）

新Stage＝0匹スタート。これを「また最初から」ではなく「**新しい土地の開拓**」に感じさせる。以下5層をすべて実装すること。**この章が本アップデート最大の成否を握る。**

### 9.1 本部（Headquarters）— 全Stage共通のプレイヤー本体

- プレイヤーの本体は個々のコロニーではなく**本部**。本部Lvは**全Stageの累計成果**（総生産・総撃退・総孵化・探索深度）で上がり、**決してリセットされない**。
- 本部Lvは全Stageに恒久バフを与える:

| 本部Lv帯 | 恒久バフ（全Stage適用） |
|---|---|
| 1〜10 | 生産+○% / 探索速度+○% |
| 11〜25 | 初期コオロギ支給 / 孵化時間短縮 |
| 26〜50 | オフライン上限延長 / 迎撃力+ |
| 51+ | レア率+ / 伝説抽選+ / 開拓ボーナス強化 |

### 9.2 開拓ボーナス（新Stage初動の加速）

**新Stage開設時、本部Lvに応じたスターターパックが自動支給される。**

- Gold（共通ウォレットから独立の開拓資金）／コオロギ初期在庫／**設備の無償設置（Lv1の水場・シェルター・巣）**
- **重要**: 本部Lvが高いほど支給が厚い。結果として、**2つ目・3つ目のコロニーは1つ目より圧倒的に速く育つ**。プレイヤーは「戻された」ではなく「**前より上手くやれる**」と感じる。これが体感カーブの核。

### 9.3 研究（Research）— 全Stage共通の恒久ツリー

- 探索で得た素材・撃退報酬を投入する**本部研究ツリー**（探索ツリーとは別。こちらは全Stage共通）。
- 内容: 生産・繁殖・迎撃・探索・オフライン・レア率の恒久強化。**一度取ったら永久**。
- 効果: 新Stageでも初日からこのバフが乗る。＝「積み上げは消えない」の可視化。

### 9.4 創始者の卵（Founder's Egg）— 血統の継承

> プレイヤーが最も惜しむのは「育てた個体との別れ」。ここに1本だけ橋を架ける。

- 新Stage開設時、**旧Stageから卵を1つだけ持ち込める**（個体そのものは移動しない＝「0匹スタート」は維持）。
- この卵は旧Stageの親個体の**系統・遺伝・レア度を引き継ぐ**。孵化すると「創始者」の称号が付き、専用マークを持つ。
- 名前も引き継げる。**「あの子の血を、新しい土地へ連れて行く」**という物語がリセット感を情緒的に殺す。
- 制約: 1Stageにつき1個。Stage固有種は持ち出せない（生態系の整合を守る）。

### 9.5 その他の共通要素

- 実績・称号・図鑑・統計・味方（V2の⑩）は**全Stage共通で永続**。
- 味方（ワシ・フクロウ等）は**任意のStageへ配置換え可能**（＝新Stageの護衛として連れて行ける。これも強力な"継承"の実感）。
- Gold/ジェムは共通ウォレット（§3.2）。

## 11. SaveData設計

### 11.1 新構造

```
WorldData (root)
├─ version              … スキーマ版数（Migration判定に必須）
├─ meta                 … プレイ開始日時・総プレイ時間
├─ wallet               … Gold / ジェム（全Stage共通）
├─ headquarters         … 本部Lv / 累計成果 / 研究ツリー解放状況
├─ collection           … 図鑑（全Stage） / 実績 / 称号 / 統計
├─ allies[]             … 味方（Lv・配置先StageId）
├─ currentStageId       … 現在表示中のStage
└─ stages[]  ← StageData の配列（Stageごとに完全独立）
     ├─ stageId / unlocked / lastTickAt   … lastTickAt がオフライン計算の基点
     ├─ environment                       … 環境プロファイル
     ├─ resources                         … コオロギ在庫 / Stage固有素材
     ├─ lizards[]      … LizardData[]（個体）
     ├─ equipments[]   … EquipmentData[]（設備・Lv）
     ├─ nest           … NestData（巣Lv / 卵スロット / 外出枠 / 収納状態）
     ├─ exploration    … ExplorationData（ツリー解放 / 派遣隊 / 進行度 / 宝箱）
     └─ boss           … BossData（撃退数 / ティア / Elite周期 / 次回襲来時刻）
```

### 11.2 設計上の鉄則

1. **Stage間で共有される参照を持たせない。** LizardDataはStageDataの内部にのみ存在する。個体IDはStage内でユニークであればよい。
2. **旧グローバル状態の降格**: Phase 0で洗い出した「Stage単位に降格すべき状態」を漏れなく StageData 内へ移す。**降格漏れ＝Stage間の値の混線バグ**であり、V3最大の事故要因。
3. **時刻ベース進行**: 各Stageは `lastTickAt` を持ち、切替/復帰時に「経過時間 × レート」で一括計算する。フレーム依存にしない。
4. **version必須**: 旧セーブは version=旧 として検出し、Migration（§Phase 9）を通す。
5. **サイズ対策**: 8Stage×100匹超を想定。個体データのフィールドを圧縮（不要な派生値は保存せず再計算）。保存が重い場合は差分保存 or 圧縮を検討。

### 11.3 Migration（旧セーブ → V3）

- 現行の単一コロニーを **`stages[火山]`（＝到達済み最終Stage）として丸ごと移設**する。個体・設備・撃退数は全て保持。
- 過去Stage（砂漠〜草原など）は**「解放済み・0匹・設備なし」のコロニーとして生成**し、プレイヤーが後から開拓できる状態にする。
- 通貨・図鑑・実績はWorldData直下へ移設。
- **本部Lvは、既存の進行（ランク77相当）から換算して初期付与する。** ここを0にすると既存プレイヤーが激怒する。**必ず換算して報いること。**
- Migrationは**不可逆**。実行前に旧セーブのバックアップを保存し、失敗時にロールバックできること。

## 12. バランス方針（中盤＝歯応え寄り・確定）

- **中盤（ランク30〜59）は対策を怠れば負ける。** ボスの弱点（V2 §②）を突かないと撃退が間に合わない水準に置く。放置だけでは勝てない。
- ただし**詰みは作らない**: 敗北ペナルティは資産（卵・素材・生産停止）に限定し、**個体は死なない**。負けても翌ウェーブで対策を打てば取り返せる。
- **難しさの正体は「数値」ではなく「準備」**にする。設備・味方・探索ツリーで準備した者が勝つ。プレイヤーが暗記するルールは増やさない。
- 新Stageの初動は**本部ボーナスで速い**（§9.2）。難しいのは中盤のボスであって、開拓の立ち上がりではない。
- 探索ツリーのノード要求量は「放置で数日」を基準。手作業の反復を要求しない。
- **KPI**: 中盤で「負けた → 対策した → 勝った」のサイクルが、暗記なしで成立すること。

- 数値のハードコード禁止。全て設定定義へ。
- **既存プレイヤーのセーブを壊す変更を、Migration実装前に入れない。**
- 各Phaseの節目でスクリーンショットと完了条件チェックをHANDOFFに残す。
