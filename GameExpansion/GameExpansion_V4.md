## ② ゲームデザイン変更理由（3つの問題）

### 2.1 問題① — 新惑星0匹の詰み【致命的・最優先】

**現象**: V3で新Stageへ移る際「卵を持っていかない」を選ぶと0匹で始まり、繁殖できず続行不能になる。

**根本原因**: 「開始個体の供給」が任意選択に依存している。プレイヤーの選択で詰みが発生する設計は、いかなる理由でも不可。

**設計解（複数案・体験最優先で選定）**:

| 案 | 内容 | 評価 |
|---|---|---|
| A. 現地生物（採用・主軸） | 各惑星には**固有種のトカゲが既に生息**している。到達＝無人ではなく、その惑星の野生個体と出会う。数匹が最初から居るか、短時間で寄ってくる | ★★★★★ 物語（「現地生物とも共存」）と完全一致。0匹が原理的に起きない。V3のPlanet Speciesとも噛み合う |
| B. HQ開拓ペア（採用・保険） | 惑星開設時、HQが**開拓ペア（アダルト2匹）**を必ず派遣する。本部Lvが高いほど質が上がる | ★★★★☆ Aの上に重ね、確実に繁殖可能な床を保証 |
| C. 創始者の卵を任意ボーナス化（採用） | V3の「卵1個持ち込み」は**必須ではなく任意の追加**に降格。持ち込まなくても詰まない | ★★★★☆ 「血統を連れて行く」情緒は残しつつ、詰みの原因から外す |
| D. 「持っていかない」選択の廃止 | 選択肢自体をなくす | ★★★☆☆ シンプルだが情緒を削る。A+B+Cで十分なため不採用 |

> **結論: A（現地生物）を主軸に、B（開拓ペア）で床を保証し、C（創始者の卵は任意ボーナス）。** 惑星到達時は「無人の荒野」ではなく「野生のトカゲが暮らす星に降り立つ」体験になる。詰みが構造的に消え、かつ没入が増す。

### 2.2 問題② — 旧惑星のほうが効率的な逆転【進行設計の破綻】

**現象**: 旧惑星で大量繁殖→一括餌やり→ランク上昇を回すと、最新惑星より効率が良くなる。プレイヤーが前へ進まない。

**根本原因**: 報酬・経験値が**惑星ローカルのランクに単純比例**し、かつ旧惑星が制限なく育つため。「楽で安全な旧惑星」が最適解になる。

**設計解（ループは変えず、係数と指標を見直す）**:

1. **フロンティア・ボーナス**: 最新開放惑星に生産・報酬の倍率を付与。**常に最新惑星が最も稼げる**。旧惑星は快適だが実入りは細る。
2. **惑星ティア報酬**: 惑星ごとに難易度ティアがあり、報酬（Gold・資源・EXP）はティアに比例。低ティア旧惑星の単位報酬は逓減する。
3. **旧惑星の逓減（ソフトキャップ）**: 各惑星のローカルランクに**その惑星のティアで決まる上限**を設ける。旧惑星をいくら回しても、そのティアの天井で頭打ちになる（詰ませはしないが「稼ぎ場」にはならない）。
4. **進行指標をHQ Levelへ一本化**: プレイヤーの真の進行度は惑星ランクではなく**HQ Level**（§3.4）。HQ Levelは全惑星の成果を集約するが、**高ティア惑星ほど寄与が大きい**。＝前へ進むほどHQが伸びる。
5. **侵略圧（Invasion Pressure）**: バガーの侵略は**フロンティアで最も激しい**（§3.5.3）。放置すると侵略ゲージが進むため、プレイヤーは自然に最前線へ向かう。物語が進行動機になる。

> **狙い**: 「旧惑星は生活の拠点（快適・放置向き）／最新惑星は成長の最前線（稼ぎ・挑戦）」という**役割分担**を作る。旧惑星を弱体化して罰するのではなく、最新惑星を魅力的にして**引く**。

### 2.3 問題③ — Goldインフレ【支出不足】

**現象**: Gold供給は適切だが支出先が足りず、Goldが余る。

**制約**: **設備を増やして支出先を作るのは禁止。逆に設備は減らす**（§3.1）。

**設計解（設備を増やさずにGoldの出口を作る）**:

1. **資源への変換（主軸）**: GoldをHQで**資源（食料供給・エネルギー等）へ変換**できる（§3.3）。Goldは「余る貯蓄」から「惑星運営を回す燃料」になる。これが最大の恒常的支出。
2. **設備の深いLvカーブ**: 設備は**数を減らす代わりにLv上限を上げ、強化コストを指数的に**する。同じ設備を育て続けることでGoldが吸われる（新設備追加ではない）。
3. **惑星開発（Planet Development）**: Goldを投じて惑星全体の開発度を上げる（生産・快適度の底上げ）。惑星ごとに独立した大きなGoldシンク。
4. **HQ永続強化**: HQ研究・通信のアップグレードにGoldを要求（資源と併用）。
5. **QoL自動化の運用コスト**: 自動餌やり等はGoldを消費して稼働（§3.1.3）。手間をGoldで買う構造。

> **狙い**: Goldの出口を「モノを増やす」ではなく「**運営を回す・積み上げを深める**」に置く。画面の要素は増えず、支出だけが増える。

### 3.1 設備整理（2タブ化・総数削減）

**設備画面を「通常設備」「防衛設備」の2タブに分離する。**

- **通常設備タブ**: 育成・繁殖・QoL のみ。防衛用は一切出さない。
- **防衛設備タブ**: ボス（バガー含む）対策専用のみ。**その惑星に来ないボス用の設備は非表示**（V3 §8を継承）。

#### 3.1.1 設備の統廃合（V2の20＋V3追加 → 約12へ削減）

冗長・重複する設備を統合する。方針: 「同じ目的の設備が複数ある」ものは1つに畳み、Lvで差を出す。

| 通常設備（育成/繁殖/QoL） | 統合前の該当 |
|---|---|
| 巣（収納・外出枠・卵スロット） | 巣＋巣箱＋孵化室を統合、Lvで機能拡張 |
| 水場 | 水場＋給水塔＋高級水槽を統合 |
| 保温設備 | 保温ライト＋大型保温器＋温室を統合 |
| 餌場（自動給餌・餌効率） | 自動給餌器＋昆虫養殖場＋温室(餌)を統合 |
| 繁殖施設（繁殖予約・クイック繁殖強化） | 人工巣＋フェロモン装置＋遺伝解析室を統合 |
| 展望台（QoL: 情報表示・巣管理） | 展望岩＋標本棚を統合 |

| 防衛設備（ボス専用のみ） | 用途 |
|---|---|
| フェンス | 侵入遅延・先制（既存） |
| 監視塔 | 迎撃枠拡張 |
| 罠設備 | 侵入時ダメージ（罠フェンス＋薬草園＋日光反射板を用途別に整理し数を絞る） |

> **原則**: 設備は「増やして解決」ではなく「**育てて解決**」。総数を減らし、各設備のLvカーブを深くする（§2.3-2）。

#### 3.1.2 削除する設備

- 装飾専用・効果が薄い設備、V3で素材依存だった設備（熔炉・遺物台座など素材前提のもの）は削除 or QoL/資源系へ役割変更。
- 伝説設備は「資源の大量産出施設」へ役割を付け替え（素材ではなく資源を生む）。

#### 3.1.3 追加してよいQoL設備（手間削減限定）

**効果が「プレイヤーの操作回数を減らす」ものだけ**追加可。ゲーム性に新ルールを足さないこと。

| QoL設備 | 効果 |
|---|---|
| 自動餌やり装置 | 空腹個体へ自動給餌（Goldまたは食料供給を消費・§3.3） |
| 自動給水 | 渇きを自動維持 |
| 繁殖予約 | 条件を満たしたら自動で繁殖を実行（卵スロット空き時） |
| 餌効率アップ | 給餌1回の満腹回復量UP＝給餌頻度を下げる |
| 休憩効率アップ | 体力回復速度UP＝休憩回転を上げる |
| 巣管理コンソール | 外出枠・お気に入り・派遣隊をまとめて管理する省操作UI |

### 3.2 惑星システム（Stage→Planet）

- V3の StageData は概念そのまま、**名称を「惑星（Planet）」へ**変更。各惑星は独立コロニー（V3 §3を継承）。
- Stage → 惑星の呼称変更: 湿地惑星 / 火山惑星 / 雪惑星 / 砂漠惑星 / 密林惑星 …（V3の8Stageを惑星として読み替え）。
- **各惑星に固有種が生息**（§2.1-A）。到達時に野生個体が居るため0匹にならない。
- 惑星間移動＝宇宙移動として演出（§4）。

### 3.3 資源システム（素材の全廃と置換）【V3巻き戻し】

**V3で追加した素材・アイテム・鉱石・氷晶・突然変異素材などのアイテム収集要素を全削除する。** 代わりに、惑星運営のための抽象リソース「資源（Resource）」を導入する。

#### 3.3.1 資源の種類（初期案）

| 資源 | 生産源（既存ループから自然発生） | 用途 |
|---|---|---|
| 生態データ | トカゲの育成・繁殖・図鑑埋め | HQ研究・惑星開発 |
| 食料供給 | 餌場・餌自動化 | 自動給餌の稼働・頭数維持 |
| エネルギー | 惑星開発・各種施設 | 自動化の駆動・HQ稼働 |
| 研究力 | HQ研究施設・生態データ変換 | 研究ツリーの解放 |
| 通信力 | HQ通信施設 | 新惑星の解放・惑星間支援 |
| 防衛力 | 防衛設備・味方 | 侵略圧の抑制・オフライン自動防衛の判定 |

- **重要**: 資源は**アイテムとして拾い集めるのではなく、コロニー運営から自然に生まれ・自然に消費される**フロー型リソース。インベントリ管理・素材集めの手作業をプレイヤーに強いない。
- **Gold→資源変換**（§2.3-1）: HQでGoldを食料供給・エネルギーへ変換できる。Goldの主要な出口。
- 資源は**惑星で生産され、HQへ集約して使う**（生態データ・防衛力は惑星ローカルの意味も持つ）。
- V3の探索ツリー（§5）は残すが、**報酬を素材から資源・QoL・図鑑・資源産出ノードへ全面置換**する。「掘って集める」から「開拓して惑星の生産力を上げる」へ。

### 3.4 HQ（本部）システム

**全惑星共通の中枢。プレイヤーの真の本体。** V3の本部を正式実装し、進行の一本化（§2.2-4）を担う。

| HQ機能 | 内容 |
|---|---|
| 研究 | 全惑星共通の恒久強化ツリー（研究力を消費）。生産・繁殖・迎撃・自動化・侵略抑制 |
| 惑星通信 | 通信力を消費して新惑星を解放。惑星間の支援（味方・開拓ペアの派遣） |
| 永続強化 | HQ Level による全惑星恒久バフ（§2.2）。決してリセットされない |
| 資源管理 | 全資源の集約・変換・配分のハブ（Gold→資源変換もここ） |
| 探索支援 | 各惑星の探索隊へHQからブースト（研究/通信で強化） |
| 侵略戦況 | バガー侵略ゲージの俯瞰と、押し返しの進捗（§3.5.3） |

- **HQ Level** = 全惑星の累計成果（高ティア惑星ほど寄与大）。これがプレイヤーの到達度指標。
- HQ画面は「惑星に属さない全要素（研究・実績・図鑑総覧・味方・統計）」の集約先（V3 §10.2を継承）。

### 3.5 世界観「Planet Reptile」

**没入を足すが、前面に出さない。** 物語はプレイの邪魔をせず、UIの端・図鑑・HQ演出に静かに宿る。

#### 3.5.1 設定（要約してゲーム内テキストへ）

惑星Reptile——高度な文明を築いたトカゲたちの星。近隣惑星の虫養殖実験が暴走し、圧倒的繁殖力を持つ実験生命体「**バガー**」が誕生、惑星を侵食した。文明は複数惑星へ移住したが、バガーは宇宙を越えて卵を飛ばし侵略を続ける。生き残った文明は各惑星を**本部（HQ）でネットワーク接続**し、**現地生物とも共存**しながら惑星防衛を開始する——。

#### 3.5.2 組み込み方（軽く・自然に）

- **導入**: 初回起動 or HQ初訪問時に短いイントロ（スキップ可・数枚のテキスト＋画像）。既存プレイヤーには「HQ起動」の演出として提示。
- **図鑑にLoreタブ**: バガー・各惑星・現地生物の設定を、遊ぶうちに解放されるコレクションとして配置。
- **既存要素の意味づけ**: コオロギ＝食料であり、暴走した虫がバガー、という対比で世界が繋がる。**新ルールは足さず、既存要素に物語の意味を与えるだけ**。
- **惑星説明**: 各惑星の環境・固有種に1〜2行のフレーバー。

#### 3.5.3 長期目標「侵略を止める」（薄く敷く）

- **既存のボス襲撃システムに、バガー侵略の意味づけを重ねる**（新ループではない）。バガー系のボスを既存ティア構造で登場させ、通常の捕食者ボス（蛇・鷹等）と混在させる。
- **侵略圧ゲージ**: 各惑星に侵略度があり、放置で上昇・防衛成功で減少。フロンティアほど高い（§2.2-5）。全惑星の侵略度を押し返すのが**ゲーム全体の長期目標**。
- **主役はあくまで育成**: 侵略ゲージは「進行の背景」であり、プレイヤーの主活動はトカゲを育て繁殖させ眺めること。世界観がループを乗っ取らないよう、UIでの露出は控えめにする。

- 素材・アイテム・鉱石インベントリ関連の全フィールド（V3 ExplorationData 内の素材保管を含む）。
- 「卵を持っていかない＝0匹」を許す移行ロジック。

**追加**:
- `resources`（各惑星の資源フロー: 生態データ/食料供給/エネルギー/防衛力）＋ HQ集約の `hqResources`（研究力/通信力）。
- `headquarters` の正式フィールド: HQ Level / 研究ツリー解放 / 通信解放惑星 / Gold変換設定。
- 各惑星に `nativeSpecies`（固有種の初期生息）と `invasionPressure`（侵略度）。
- `lore`（解放済みLoreエントリ）。

**改名**:
- `stages[]` → `planets[]`（内部IDの互換は Migration で吸収）。StageData → PlanetData。

**Migration（V3→V4）**:
- 素材保有を破棄する代わりに、**保有量に応じた資源 or Goldへ一度だけ払い戻し**（プレイヤーの損失感をゼロにする。重要）。
- 全惑星に固有種の初期個体を付与し、**現存する0匹の惑星があれば開拓ペアを補填**（詰み救済）。
- 設備統廃合: 旧設備を新統合設備のLvへ換算移設（効果を落とさない）。
- version を V4 へ。**不可逆前にバックアップ必須・ロールバック可能**に。

## 禁止事項（Claude Codeへ）

- **ゲームシステム・ゲームループを変更しない。** V4は整理・QoL・世界観のみ。新しい遊びのルールを足さない。
- **設備を増やして問題③を解決しない**（QoL設備のみ例外）。設備は減らす方向。
- **素材収集を残さない/復活させない。** 資源はフロー型であり、拾い集めるアイテムにしない。
- **Phase 1 完了前に他Phaseへ進まない。** データ構造が土台。
- **Migration実装（Phase 8検証）前に、既存セーブを壊す変更を確定しない。** 素材の払い戻しと0匹救済は必須。
- 数値のハードコード禁止。全て設定定義へ。
- 本書にない機能を思いついても実装せず、HANDOFFへ提案として記録する。
- 各Phaseの節目でスクリーンショットと完了条件チェックをHANDOFFに残す。

## 未決定事項（Ric確認待ち）

1. **資源の種類数**: 6種（生態データ/食料供給/エネルギー/研究力/通信力/防衛力）は多い可能性。**最初は3〜4種に絞り、後から足す**ことを推奨。全部同時に導入するとUIと理解負荷が増す。
2. **侵略圧の強さ**: 長期目標として薄く敷く方針。侵略ゲージが「圧」になりすぎると放置ゲームの気楽さを損なう。**初期はほぼ無害な演出寄り**から始め、様子を見て強めるのが安全。
3. **イントロの扱い**: 既存プレイヤー（ランク77）にストーリーを後付けで見せる形。強制フル再生か、HQで任意閲覧か。**任意閲覧＋初回の短い1枚**を推奨。
4. **V3探索ツリーの残し方**: 報酬を資源へ置換して残す前提。もし探索自体を縮小したいなら、Phase 3 の設計が変わる。
