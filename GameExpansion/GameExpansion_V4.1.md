## 本書の位置づけ（V4本体との関係）

V4本体（Planet Reptile）はデプロイ済み。本 v4.1 は、その中の**巣・探索まわりを差し替える**追加仕様である。以下を明示する。

| 対象 | V4本体 | v4.1での扱い |
|---|---|---|
| 探索隊・探索ツリー・宝箱・巣内一覧 | 実装済み | **全廃・撤去**（§2） |
| 巣 | 惑星ごとに保持 | **全惑星共通の統合放置システムへ刷新**（§3） |

| 運営フロー資源（生態データ/食料/エネルギー/研究力） | 実装済み | **維持**。今回の希少資源とは別レイヤー（§5） |

> **設計思想の一貫性**: これはV3探索の再々修正にあたる。「トカゲを集める素材ゲー」化を避け、**プレイヤーの主活動を繁殖に一本化し、巣はその裏で勝手に育つ"報酬装置"に徹する**。操作を足すのではなく、操作を消す方向の刷新である。

## v4.1のコア体験（全Phaseの判断基準）

> **「繁殖に夢中になっている間に、気づいたら新しいノードが開いていた」**

この一文が本アップデートの成否を決める。設計判断に迷ったら「これはプレイヤーに巣の操作を要求していないか？」「繁殖から目を離させていないか？」を問い、YESなら却下。巣は**眺めるもの・気づくもの**であって、**操作するもの・管理するものではない**。

同時に、放置ゲームでありながら**完全放置を最適解にしない**。その唯一の仕掛けが「バガー侵食率」（§6）——1日1回程度のログインが最適になる、ごく緩い圧である。

## ③ 巣システムの刷新（完全放置・全惑星共通）

### 3.1 定義

- **巣は全惑星共通の単一インターフェース**。惑星ごとに持たない。どの惑星から巣を開いても同じ1つの巣ネットワークが表示される。データ上も**WorldData直下（HQと同格）**に置く（§Phase 1）。
- **プレイヤー操作は一切不要**。派遣も、素材投入も、ノードの手動解放もない。巣は繁殖という主活動の"副産物"として自動で育つ。
- **見た目**: 蜘蛛の巣状のノードネットワークUI（放射状に広がる巣の糸。中心＝起点、外周＝深部）。§4で詳述。

### 3.2 ノードの自動解放エンジン

各ノードは**複数条件のいずれか/組み合わせ**で自動解放される。プレイヤーは繁殖を続けるだけで、条件が満たされ次第ノードが開く。

**解放条件の種類（例）**

| 条件カテゴリ | 例 |
|---|---|
| 繁殖数 | 累計繁殖回数が閾値到達 |
| 種族数 | 保有系統の種類数が閾値到達 |
| 突然変異 | 変異個体を◯体誕生させた |
| 遺伝子傾向 | 特定の色/模様/性格の遺伝が◯世代継続 |
| 図鑑率 | 惑星別 or 総覧の図鑑コンプ率が◯% |
| 複合 | 上記の2つ以上を同時に満たす（深部ノード） |

### 3.3 可変解放（非直線・先行解放）

**直線的な前提ツリーにしない。** 蜘蛛の巣状である理由がこれ。

- 通常は近傍ノードから解放されるが、条件を満たせば**未接続の遠方ノードが先行解放**され得る。
- 2つの経路: ①**条件先行解放**（遠方ノードの解放条件を満たしていれば、隣接未解放でも開く）／②**確率先行解放**（繁殖などの節目イベント時に低確率で遠方ノードが1つ開く「サプライズ」）。
- 先行解放時は糸が新たに走る演出＋通知（§4.3）。「予想外の場所が光った」という驚きを作る。

> **設計注意**: 確率先行解放は"嬉しい驚き"専用。**外れて損をする感覚を絶対に出さない**（ハズレ演出・確率明示のガチャ的UIにしない）。条件解放が主、確率解放は上乗せのボーナス。

### 3.4 放置成長のリズム

- ノード解放は**繁殖の裏で静かに進む**。プレイヤーが繁殖UIを触っている最中/直後に「新ノード解放」のさりげない通知を出すのが理想のタイミング。
- オフライン中も、繁殖予約（V4のQoL設備）などで満たした条件は復帰時にまとめて解放し、「留守中に3ノード開いた」と通知（§4.3）。

### 4.1 レイアウト

- **放射状の巣**: 中心に起点ノード、そこから糸（エッジ）が同心円状・放射状に広がる。外周ほど深部＝高価値。
- **ノード**: 円形アイコン。状態で見た目が変わる——**解放済み（彩色・発光）／解放間近（条件◯%達成でパルス）／未解放（暗い糸だけ見える）／先行解放（特別な輝き）**。
- **糸**: 解放済み同士は光る糸で接続。未接続の遠方ノードへは、先行解放時に糸が新たに走る。
- **操作は閲覧のみ**: パン/ズームで巣全体を眺められる。タップは「そのノードの報酬内容とツールチップ表示」だけ。**解放ボタンは存在しない。**

### 4.2 情報表示（操作ではなく理解のため）

- ノードをタップ → 「解放条件（あと◯回の繁殖 等）」「報酬内容」を表示。プレイヤーが"次に何をすれば開くか"を把握できるが、**やることは結局いつもの繁殖**。
- 巣全体のヘッダーに「解放済み ◯/総数」「次に開きそうなノード」を控えめに表示。

### 4.3 解放演出（体験の核）

- **解放の瞬間**: 対象ノードが光り、糸が走り、報酬が中心へ流れ込む短い演出（1〜2秒・派手すぎない）。
- **通知タイミング**: 繁殖直後・惑星移動時・オフライン復帰時にまとめて。「気づいたら開いていた」を演出で作る。
- **先行解放**: 通常と差別化した特別演出（遠くの糸が一気に走る）＋「予想外のノードが解放された！」。

## ⑤ ノード報酬・希少資源（コオロギ/Gold/ダイヤ禁止）

**巣ノードの報酬は希少価値の高い鉱石系に限定する。** 日常資源（コオロギ・Gold・ダイヤ）は**報酬に含めない**。巣は「日々の運営」ではなく「長期の夢」を配る装置。

> **テーマ統一（v4.1確定）**: 希少資源は**すべて鉱石／鉱物系**に統一する。機能は一切変えず、名称のみ鉱石へ寄せる。これにより「HQ研究データ」を鉱石名へ改めることで、**フロー資源「研究力」との紛らわしさも同時に解消**される（未決定事項#1を解決）。

### 5.1 希少資源一覧（鉱石系に統一）

| 鉱石 | 位置づけ | 主な用途（機能は不変） |
|---|---|---|
| 🔮 **アメジスト** | **ダイヤの上位鉱石**。最上位の貴重通貨 | 高位アンロック・将来の課金通貨との共存枠（§5.2） |
| ⚙️ **イリジウム** | 惑星規模の重要金属 | **ロケット建造・惑星移住計画**（§7・長期目標の燃料） |
| 🟠 **琥珀（こはく）** | 太古の遺伝情報を封じた化石樹脂 | 突然変異・レア/伝説系統の解放・遺伝子解析（旧「古代DNA」＝琥珀に閉じ込められた太古の遺伝子） |
| ☄️ **隕石（いんせき）** | 宇宙から飛来した"中身が未確定"の鉱塊 | 割る/解析すると希少・伝説個体が出現（旧「未知卵」のロマン枠。物語の"宇宙から来た生命"と親和） |
| 🔩 **オリハルコン** | 伝説の希少金属。HQ大型マイルストーン専用 | HQ研究の上位段階・宇宙港/遺伝子解析の解禁（旧「HQ研究データ」を改名＝研究力との衝突解消） |
| ⛏️ **チタン鉱** | 設備を化けさせる特殊鉱石 | 既存設備の上位Lv/特殊化を解禁（設備を"増やす"のではなく"化ける"。旧「設備設計図」） |

- これらは**フロー資源（生態データ等）とは別のウォレット**（希少鉱石ウォレット）で管理。全惑星共通。
- **琥珀/隕石は繁殖と直結**——巣（繁殖の副産物）が繁殖をさらに豊かにする正のループ。ただし新ルールは足さない（既存の繁殖/変異/図鑑に流し込むだけ）。
- **旧名との対応**: 古代DNA→琥珀 ／ 未知卵→隕石 ／ HQ研究データ→オリハルコン ／ 設備設計図→チタン鉱。**各資源の用途・接続先・実装挙動は旧設計から一切変えない**（見た目とアイコンと名称のみ鉱石化）。

### 5.2 アメジストと課金通貨の共存（設計上の配慮）

- アメジストは**ゲーム内でのみ入手できる最上位資源**として設計しつつ、**将来の課金通貨と役割が衝突しない**よう用途を分離しておく。
  - アメジスト＝「やり込みの証・時間で得る最上位」。
  - （将来の）課金通貨＝「時間短縮・利便」。
- **Pay-to-Winにしない前提**: アメジストで買えるものは、課金通貨では"買えない/時短だけ"に留める設計余地を残す。**本Phaseでは課金は実装しない**が、データ設計で両者を別ウォレットに分けておく（後付けで揉めないため）。

## ⑥ バガー侵食率（完全放置を最適解にしない唯一の仕掛け）

### 6.1 目的

- 完全放置を最適解から外し、**1日1回程度のログインが最適**になるバランスを作る。
- ただし**プレイヤーを急かさない**。侵食は"締切"ではなく"緩やかな庭の手入れ"の感覚に留める。

### 6.2 仕様

- **全惑星共通の単一パラメータ**（V4の惑星別侵略圧を、共通の侵食率へ統合・格上げ）。0〜100%。
- **上昇**: 非常にゆっくり自然上昇（例: 完全放置で数日かけて閾値に近づく速度）。フロンティア惑星の存在で微増。
- **影響（閾値超過で発動）**: 段階的に **繁殖効率↓／設備効率↓／ボス強度↑**。低いうちは無害、高くなって初めて体感。
- **低下手段（容易であること）**:
  - **定期ログイン**: ログイン時に自動で一定量低下（＝毎日触れば低く保てる）。
  - **HQ防衛技術**: HQ研究で「侵食の自然上昇を鈍化／ログイン時低下量を増加」を恒久強化。
  - **バガー撃退**: バガー系ボス撃破で侵食率が下がる（V4本体で実装済みの-10を継承・調整）。

### 6.3 バランス目標（最重要）

- **「1日1回ログインすれば侵食は常に低空飛行、放置しすぎると緩やかに効率が落ちる」** が理想。
- **罰を強くしない**: 侵食が高くても"詰み"や"大損"は作らない。触れば即回復できる可逆な圧に留める。数日空けても、戻ってログインすれば数分で立て直せること。
- 侵食率の数値・影響曲線・低下量はすべて設定定義へ。**初期は弱め**から始め、様子を見て調整（V4本体の"演出寄り"方針の延長）。

## ⑦ HQ拡張（永続成長拠点・ロケット建造）

V4本体のHQ（研究・通信・資源管理・侵略戦況）に、以下を追加する。**HQは全惑星共通・永続・リセットされない**。

| HQ機能 | 内容 |
|---|---|
| 研究 | 既存の恒久研究に加え、**侵食抑制技術**（§6.2）を追加 |
| 通信 | 既存（通信力で惑星解放） |
| **ロケット開発** | **イリジウム**を投入して段階建造。完成で**新惑星開拓 or ストーリー進行を解禁**（§7.1） |
| **宇宙港** | ロケットの発着・惑星移住計画のハブ。ロケット建造の進捗表示 |
| **遺伝子解析** | **琥珀**を用いて系統/変異/伝説を解析・解禁（繁殖と接続） |
| 図鑑管理 | 惑星別＋総覧＋Lore（既存）＋希少個体の殿堂 |
| 希少鉱石管理 | アメジスト/イリジウム/琥珀/隕石/オリハルコン/チタン鉱の集約ウォレット |

### 7.1 ロケット建造＝長期目標

- **イリジウムを長期間かけて蓄積 → ロケット段階建造 → 完成で新惑星/物語の解禁**、という終盤の大目標。
- 巣ノード（イリジウム供給源の一つ）→ ロケット → 新惑星 → さらに巣が育つ、という**長期の正ループ**を形成。
- 建造は「日々少しずつ進む」放置向き設計。完成時に大きなカットイン＋称号＋新惑星解放。
- **主役は育成のまま**: ロケットは背景の長期目標。UI露出は控えめに、宇宙港に閉じる。

- **テスト項目**: 各条件カテゴリで正しく解放される／条件先行解放が働く／確率先行解放が"損失感なく"稀に起きる／オフライン中に満たした条件が復帰時にまとめて解放される／**プレイヤー操作ゼロで解放が進む**。
- **完了条件**: 繁殖を続けるだけでノードが自動解放され、遠方先行解放も含めて破綻しない。

### Phase 4 — 巣UI（蜘蛛の巣状ネットワーク・放置演出）

- **目的**: 「気づいたら開いていた」を成立させる閲覧専用UIと解放演出。
- **変更内容**: §4の放射状ノードUI（パン/ズーム・状態別見た目・糸）／解放演出／通知タイミング（繁殖直後・移動時・復帰時）。
- **データ構造**: 表示用の座標/接続（Phase 3のグラフを流用）。
- **スクリプト**: 追加 `NestWebUI`（描画・閲覧）・`NestRevealFX`（解放演出）・`NestNotifier`（通知）。
- **Prefab**: 巣ノード（解放済/間近/未解放/先行解放）／糸／解放エフェクト／通知トースト。
- **UI**: 巣画面（閲覧専用・**解放ボタンなし**）。ノードタップで条件/報酬ツールチップ。
- **テスト項目**: 操作は閲覧のみで解放操作が存在しない／解放が演出付きで可視化される／通知が繁殖直後/復帰時に出る／モバイルでパン/ズームが快適。
- **完了条件**: 巣が"眺めて気づく"体験として成立し、操作要求がゼロ。

### Phase 5 — 希少報酬・資源

- **目的**: 巣報酬を希少資源に限定し（コオロギ/Gold/ダイヤ禁止）、各資源の用途を接続。

- **データ構造**: `rareWallet`（Phase 1で新設）を稼働。チタン鉱の設備適用先定義。
- **スクリプト**: 追加 `RareOreSystem`・`MeteoriteCrack`（隕石を割る/解析して希少個体を抽選）・`OreForge`（チタン鉱で設備特殊化）／変更 `BreedingSystem`/`MutationSystem`（琥珀接続）・`EquipmentSystem`（チタン鉱で特殊化）。
- **Prefab**: 希少鉱石アイコン6種／隕石を割る演出／チタン鉱の設備適用UI。

- **完了条件**: 巣が「長期の夢」を配る装置として成立し、繁殖と正のループを作る。

### Phase 6 — バガー侵食率

- **目的**: 完全放置を最適解から外し、1日1ログインが最適なバランスを作る。

- **完了条件**: 「毎日触れば低空飛行、放置しすぎると緩く効率低下」が成立し、急かしすぎない。
